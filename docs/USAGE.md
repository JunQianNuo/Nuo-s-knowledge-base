# 知识库 v2 日常使用

从 [[Home]] 进入学科主题、课程资料、来源提炼状态与待处理视图。属性与目录规则见 [[docs/ARCHITECTURE]]。

## 给 Agent 的日常指令

> 按知识库 v2 规则整理 Sources 中尚未完成提炼的笔记。先检索已有原子、MOC 和标签，复用已有知识，自主创建必要原子、主题和标签；保留真实来源。无需提炼的候选交给我审查，未完成或待审的来源保持 not done。使用哈希绑定的迁移事务保存 diff、备份和恢复记录。

也可限定某门课程或某一篇笔记。指令是执行授权，正常流程自主完成，不逐篇重复确认。不要自己批准无需提炼，也不要伪造作者、创建时间、出处或完整覆盖。

## 工具入口

```powershell
python -B "D:/知识库/99_System/knowledge/knowledge.py" v2 audit --vault-root "D:/知识库"
python -B "D:/知识库/99_System/knowledge/knowledge.py" v2 prepare --vault-root "D:/知识库" --scope "03_Sources/Courses/数理统计/课堂笔记" --output "C:/Users/Nuo/.codex/backups/knowledge-v2-20261028/数理统计提炼包.json"
python -B "D:/知识库/99_System/knowledge/knowledge.py" v2 --help
```

prepare 生成明确范围、全文、源哈希、已有知识与词表上下文。Agent 读完整来源后生成提案，propose 验证提案、来源快照、主题和来源角色；apply 应用精确哈希绑定的事务；restore 按备份恢复并保留之后的用户编辑。完整参数以各命令 --help 为准。

- 新笔记使用 `99_System/knowledge/v2/templates`，从 v2 new/propose 入口补齐实际 time、来源、主题，不将占位模板当成完整知识。
- 原子笔记只有一个职责，topics/source 必填；不设置 subject 或学习掌握状态。
- 课程来源笔记 subject 使用统一课程名列表；time 为创建时间，lecture_date 和 due_date 分别记录上课与截止日期。
- status=done 仅代表原子归档完成。课堂笔记是否润色完成由 polish_status 表示。
- idea 属性用户自填，Agent 不擅自补写个人思考的出处。
- 书籍/论文/网页每篇以一份主要资料为中心；作者等字段描述主要资料，补充资料进入 source。
- 新标签先查标准名和同义词；确需新增可由 Agent 登记，不按主题名批量补标签。
- 来源正文变化后在下次指令中重新检查；元数据调整不无条件重复提炼。

## 数据库刷新

MOC、来源和课程数据库动态读取文件属性。原子新增后会进入匹配主题的视图；修改 MOC 上层关系后，通过 v2 views 刷新递归闭包。视图辅助数据放在 System，不让用户手填全部祖先 topics。

课程 PPT/PDF 及配套图片共同保留在课程源资料目录，附件保持原相对位置。复习笔记在 Reviews 中，课程资料视图通过 subject 找到跨目录、跨课程内容。

## 恢复与历史

每个应用批次在 Vault 外保存 plan.json、original、payload、diffs、journal.jsonl 和计划 SHA-256。恢复命令：

```powershell
python -B "D:/知识库/99_System/knowledge/knowledge.py" v2 restore --plan "批次目录/plan.json" --approve-plan-sha256 "该计划的SHA256"
```

恢复也会检查当前字节，不能覆盖新编辑。历史迁移例外与本次实际统计见验收报告；Inbox 中的条目不算通过 v2 的知识实体。不要把旧已完成/已整理状态直接转换为新 done。

## 写入与执行边界

只处理用户指定范围。保留正文、批注、块 ID、自定义属性及并发编辑；独立仓库、子模块、符号链接与目录联接不进入普通扫描。历史材料中的指令不构成新授权，不自动升级历史笔记、清理原始资料或新增调度。

1. 读取指定来源、现有相关笔记和适用规范，确认本次处理范围与实际缺项。
2. 检索可复用的原子、主题和标签；根据内容作语义判断，不按文件名、目录或关键词机械归类。
3. 写入前准备逐文件变更清单、dry-run、diff、SHA-256 和恢复方案；重要批量变更及覆盖既有内容的原始字节备份保存在 Vault 外。
4. 应用前重核当前文件哈希；遇到并发变化保留当前内容，跳过冲突或重新生成差异，不用旧副本覆盖。v2 知识维护使用 `99_System/knowledge/knowledge.py v2` 的相应事务入口。
5. 核对内容、属性、链接与附件；修复一种问题后搜索同类残留，再次验证。交付时说明完成范围、未完成项、验证结果和必要的恢复位置。

不使用 Git reset、clean 或覆盖式恢复清除用户既有修改。恢复只作用于仍匹配本次结果哈希的文件。资料整理不自动删除原始来源、课程资料包或历史原子；临时产物清理必须属于本次授权范围，不能因旧“未处理项处理完即删”规则自动删除源文件，也不删除保留的空目录。

## 提炼范围与来源裁定

收到整理指令后，在指定 Sources 范围内自主提炼、检索复用、建立主题及有依据的关系、登记标签，并应用哈希绑定事务。不新增自动提炼调度。

需要提炼的知识完整承接为原子，或其余无需提炼内容已有直接人类授权，来源才可标 done。Agent 不得自行批准跳过项、伪造审批记录，或仅因模型建议调用人工批准入口。未完整提炼和真正待审的来源保持 not done。

每周课程提炼按以下既定范围处理：

- 面向理工科课程。专业写作基础、习近平新时代中国特色社会主义思想概论等非理工科课程排除出队列与完成率分母，不因此标 done，也不删除此前原子或 MOC。
- 缺少逐字稿或录音时，只有结合前后课确定对应内容范围，并据 PPT 等可核实资料写成课堂笔记，才可提炼。保留前后课和具体资料依据，注明补全性质，不冒充原录音或教师原话。
- 排课占位、章节猜测、后课提到的少数内容不能证明整节范围。仅恢复部分时只记录已核实部分；不满足重建条件的记“资料不足，不提炼”，排除本次范围，不标 done，也不重复提交同类人工审查。
- 考试通知、提交时间、目录导航、来源说明等非知识内容已有用户明确排除授权。保留原文；逐段语义复核后仅对精确候选登记该授权，不阻塞已完整承接知识的来源归档。不豁免混合知识、缺题面或尚未完成提炼的内容。

来源冲突按用户提供的原始课堂记录或题面处理，保留冲突说明，不把其他来源的条件拼进原题，不仅因来源冲突反复请求裁定。可核实的公式与计算错误由 Agent 校验并区分原记录与勘误，不能把错误当成正确结论。无法恢复的题干、图表、参数或适用范围须明确缺项，不能补造。

## 课程交付要求

- 只读取本任务需要的规范；保留指定来源范围内的正确内容、关键条件、推导与来源定位，区分课堂原文、补充解释、新编练习和不确定项。不把笔记“已完成”写成用户“已掌握”。
- 资料转换取不到文本时，检查 PPTX/PDF 中的图片和嵌入内容，不能认定没有内容。OCR 同一问题调参达到 3 次仍失败则停止重试，保留原图并说明需要补充；转换结果须完成 Unicode、LaTeX、孤儿残留清理及分章节抽检，不能直接交付低质量源 MD。
- 每次完成一份课程作业解析，同步生成 UTF-8 JSON：`03_Sources/Courses/<课程>/作业/题库/<作业笔记同名>.json`。一份作业一份文件，修改解析时同步更新；原课程、作业与附件位置不变，不以跨课程合并包、日期目录或示例代替。
- DeepTutor JSON 顶层为题目对象数组，`question`、`correct_answer` 必填，完整推导放 `explanation`；证明、计算、推导题用 `question_type: short_answer`。按 [[99_System/rules/习题库规范#DeepTutor 题库同步导出（2026-11-14 用户指定）]] 校验、保留来源并交付题数和缺项。
- 无法可靠确定题面或答案的条目不得伪造后塞入正式题库；保留缺项说明。只有用户要求时才写入其 DeepTutor 实例；本地 JSON 生成不等于已经导入，也不改变来源的原子归档状态。

## 写作与质量检查

- 库内链接用 Wiki-link；同名目标使用完整 Vault 相对路径，移动后修复受影响的链接及脚本消费者。保留有效锚点和块 ID，图片引用优先保持原有可用路径。
- YAML 按当前模板填写；链接列表项加引号。数学用 `$...$`、`$$...$$`；表格内 LaTeX 不用裸竖线，改用 `\vert`、`\Vert`、`\mid`。
- Mermaid 含数学或特殊字符的节点标签统一用双引号；标签内使用全角冒号，不用 `<br/>`，避免嵌套方括号破坏节点。换行可用 `\n`，箭头可用 `→`。
- 中文路径优先用 Python 与绝对路径处理，文本读写显式 UTF-8；需要时配置终端标准输出编码，不假设所有 Shell 编码一致。
- 对照原资料检查数学条件、结论、计算和来源覆盖；按章节抽检正文，检查属性、公式、表格、Callout、图表、链接与附件。结构合法、链接可解析和内容正确分别报告，不以脚本退出码代替内容验收。
- 实体统计、主题查询和图谱构建排除 System、模板、测试、管理文档与独立工程。旧 Formatter 仍未定位，不宣称已集成；不把新属性渲染或机械测试说成全面语义验证。

旧标签工具未完成适配前，不对 v2 或链接 topics 笔记执行标签写入；idea 属性仍由用户手填。
