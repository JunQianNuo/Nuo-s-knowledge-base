# 知识库架构重构与属性模板设计

日期：2026-10-28（Asia/Shanghai）

状态：需求已逐项讨论，完整设计待用户确认；本文件不表示已实施迁移。

## 1. 意图与范围

将课程型知识库改为“来源记录 → 可复用原子知识 → 学科主题导航”的组织方式。知识实体以属性和语义链接形成网络，文件夹承担存储职责。来源记录完整保留，提炼不等于删除原记录。

本轮范围为：现有 `概念/`、`知识点/`、`方法/`，课程资料及其复习内容，相关学科 MOC，以及支撑它们的模板、Schema、维护工具、数据库视图、Home 和规范。

AI 工具资料、独立的语言/考研/每日疑惑内容、闪卡及数学建模内容不做归类、移动或正文重写。独立 Git 仓库、子模块、联接和符号链接不进入迁移扫描。`课程/英语/` 属于当前课程资料范围；根目录 `语言/` 不在本轮范围。

为使本轮移动不破坏已有引用，范围外普通笔记只允许定点更新能够确定目标的受影响路径链接，不调整其分类、结构或其他内容；这些变更必须在 dry-run 中单独列出。独立仓库与插件运行时文件不因此进入写入范围。

当前工作区已有大量未提交和未跟踪内容。以执行前的实际字节为基线，不以 HEAD 覆盖它们，不清理或回滚既有改动。

## 3. 内容类型与原子边界

内容笔记统一使用单值 `type`，不再以 `role: moc` 作为新 MOC 的身份标记。

| type | 职责 |
|---|---|
| `concept` | 是什么：定义对象、术语、含义、结构与边界 |
| `proposition` | 什么成立、为什么：条件、事实或关系、结论与依据 |
| `method` | 如何完成：可执行的过程、算法或求解策略 |
| `moc` | 学科与主题导航 |
| `lecture` | 课堂笔记 |
| `review` | 复习笔记 |
| `homework` | 作业与习题，包括不单独另设类型的练习 |
| `book` | 围绕一本主要书籍的阅读笔记 |
| `paper` | 围绕一篇主要论文的笔记 |
| `web` | 围绕一个主要网页的摘录与整理 |
| `idea` | 用户自行记录的想法与独立推导 |

一篇原子笔记只承担一种核心职责。综合展开定义、性质和求解步骤的内容属于非原子笔记，不以“主要内容占比”硬归入三类原子类型。必要符号、条件、依据和例子服务于该单一职责，不为凑齐三类重复建卡。

不再保留“知识梳理”“答疑”独立类型。重构时根据实际内容确定其归类，不将历史“知识点”无条件映射为 proposition。课件及其转换产物是资料，不新增“课件笔记”类型；原始逐字稿、转换 MD、目录索引等也不一概套用笔记模板。

系统记录不是学习内容实体，允许保留其专用管理字段与识别方式，不把标签条目、属性条目、报告、模板或数据库记录硬套上述内容类型。

## 4. 三类原子笔记的共同属性

| 属性 | 格式 | 约束 |
|---|---|---|
| `type` | 文本 | 必填，concept/proposition/method 之一 |
| `time` | 带时区的时间字符串 | 必填，创建时间，之后编辑不改写 |
| `topics` | 整篇笔记 Wiki-link 列表 | 必填、非空，目标必须是实际存在且合法的主题 MOC |
| `source` | 整篇笔记 Wiki-link 列表 | 必填、非空，至少指向一份真实的 Sources 来源笔记 |
| `aliases` | 字符串列表 | 可选，其他名称与缩写 |
| `tags` | 字符串列表 | 可选，采用标签数据库标准名 |
| `prerequisites` | 笔记链接列表 | 可选，理解或学习该知识所需的先修 |
| `uses` | 笔记链接列表 | 可选，定义、推导或执行中直接使用的知识 |

三类共用这些属性，仅 type 和正文职责不同。省略 YAML `title`，标题使用文件名。同一知识共用一篇原子笔记，多个实际来源记录在同一个 source 列表中。原子笔记不设置课程 subject。

除 uses/prerequisites 外不新增固定的原子间关系字段。其他关联可在正文中解释和链接。历史自定义字段及 about/related 等旧数据不因未列入新模板而直接删除，也不机械转换成新关系。

模板示意（占位链接必须在创建实际笔记时替换）：

```yaml
type: concept
time: "2026-10-28T10:00:00+08:00"
topics:
  - "[[02_Maps/MOC-数理统计]]"
source:
  - "[[03_Sources/Courses/数理统计/课堂笔记/充分统计量]]"
aliases: []
tags: []
prerequisites: []
uses: []
```

## 5. MOC 属性与主题数据库

MOC 使用 `type: moc`，另有必填创建时间 `time`，以及 `topics`、`aliases`、`tags` 列表。topics 表示更上层 MOC，可以有多个；顶层允许为空。MOC 不要求原子笔记那样的 source。

MOC 组织的是学科和主题，不是课程来源目录。允许交叉和多个上层主题。实施决定：拒绝自链接和主题层级环，保证递归聚合有确定边界。

主题数据库以 MOC 笔记及属性为数据源，自动识别，不另维护一份注册名单。AI 关联主题前先查该数据库；必要时创建并登记对应学科主题 MOC，确保实际笔记已存在并通过校验后再引用。

上层 MOC 展示自身和所有下层主题所属的原子知识，按实际笔记身份去重。原子不必重复填写所有祖先。MOC 可保留人工路线、主题说明与动态视图，不聚合课堂/复习等非原子笔记。

原生 Bases 能力若不能单独完成递归，实施者应选择可验收的辅助索引或生成视图，维护数据放在 System，不让用户手工填写冗余祖先 topics。不因建立一个基础查询就声称递归聚合已实现。

## 6. 非原子笔记共同属性

lecture/review/homework/book/paper/web 共用以下属性：

| 属性 | 约束 |
|---|---|
| `type` | 对应的单值类型 |
| `time` | 必填，创建时间 |
| `status` | 必填，只使用 `not done` 或 `done` |
| `source` | 必填、非空的真实来源列表，可含课件/PDF 等库内资料链接、网页 URL、书目信息及定位 |
| `aliases` | 可选 |
| `tags` | 可选，复用标准标签名 |
| `subject` | 课程相关时填写课程名称列表，支持多门课程 |

不以 topics 将这些笔记纳入主题 MOC。课程资料视图通过课程目录和 subject 汇集课件、笔记、作业与复习内容。

idea 的属性由用户自行填写，本轮不替用户规定自主思考的来源文本。实施决定：idea 使用宽松的人工维护模式；仅当用户填写了可识别 type 和待处理状态时，才纳入指令提炼。提炼流程可以更新 status，不擅自补造其余人工属性。该决定会在交付时单独提示。

### 课程专属字段

subject 为课程名称列表；课堂和课程作业须有可核实的课程归属。复习允许跨课程。无课程关联的阅读/论文/网页笔记不强填 subject。

lecture 提供可选 `lecture_date`，homework 提供可选 `due_date`，均为真实的 YYYY-MM-DD 日期，不替代 time。

录音生成的 lecture 可额外使用 `polish_status: not done/done`，区分逐字稿整理进度。普通手写课堂笔记无需此字段。只有已整理出完整内容的课堂笔记才能进入原子提炼，空占位不算已完成。

### 阅读、论文、网页的资料元信息

每篇只围绕一份主要资料，以下属性描述主要资料；实际使用的其他资料仍可记入 source。

| 适用类型 | 字段 |
|---|---|
| book/paper/web | `source_title` 原始资料标题，必填；`authors` 作者/机构作者列表、`year` 整数年份、`url` 主资料页面链接，按真实信息选填 |
| book | `publisher` 出版社、`edition` 版次、`isbn`，选填 |
| paper | `venue` 期刊/会议名称、`doi`，选填 |
| web | `site` 网站名称，选填 |

不以笔记文件名代替原始资料标题，不猜作者、日期或 DOI。source_title 与已省略的笔记 title 不是同一职责。

## 7. 标签数据库

沿用已有“一个标准标签一条管理记录”的模式，核心字段为 canonical_tag 和 tag_aliases。数据库从记录自动构成；未来标准名与历史名称都能找到对应记录。

tags 可以灵活使用，不要求完备层级。AI 先查同义名称、复用标准名，确需新标签可自主登记；未知是否同义时不凭字面强行合并。标签不替代 type/status/topics，也不自动将主题 MOC 名批量转成标签。

现有 promote/source_kind/status 等管理数据按依赖核对后保留或迁移，不能因新模板精简而清空原词表证据。旧标签脚本先适配新规则并通过隔离验证，再对新格式数据执行写入。

## 8. 指令触发的 AI 提炼

触发方式是用户指令，不创建提炼定时任务，不设置文件新增自动触发。既有录音采集定时机制独立保留，不能将它误认为知识提炼调度。

流程为：扫描指定 Sources 范围 → 确认内容可处理 → 查已有原子与同义名称 → 语义提炼 → 复用/补充已有知识或创建单职责原子 → 写入真实 source → 查找或建立主题 MOC → 建立有依据的 uses/prerequisites 和正文关联 → 维护标签 → 校验并应用 → 更新来源 status。

AI 的执行主体是当前 Codex/Agent 会话。维护 CLI 负责上下文准备、检索、校验、计划、应用、恢复和报告，不用规则分类器冒充语义提炼，也不要求新增外部模型服务或 API 凭据。

正常提炼在一次指令授权范围内自主完成，不逐篇向用户请求写入许可。操作范围、来源哈希与实际补丁绑定，所有写入经过同一变更控制入口，保留并发编辑。

完成定义：需要提炼的内容均已由原子承接，或用户已人工审查确认无需提炼，才能将来源标为 done。AI 可提出“无需提炼”候选，但不能自行批准。待审/待处理内容存在时保持 not done。来源笔记不用维护额外的归档清单，原子 source 记录来源关系；内部运行报告可记录执行与人工审查证据。

实施决定：指令运行时发现已标 done 的来源内容改变，应重新检查并进入待处理状态；只改元数据时不无条件重复提炼正文。内部内容指纹不作为用户必须手填的笔记属性。

## 9. 现状与迁移策略

只读初步盘点：概念 72、知识点 72、方法 90，共 234 个 Markdown，其中包括历史导航；核心内容中 50 份没有非空 source。课程目录有 1,251 个 Markdown，包含 95 份课堂笔记、302 份旧“习题”、104 份旧“答疑”、70 份“知识梳理”，还有转换资料、原始记录和索引，不能统一当作新内容实体。

实施者须先做完整 dry-run，补充目标位置、实际类型、来源解析、主题解析、附件、引用和脚本消费者的逐文件计划。以上数字是初步盘点，不冒充已完成迁移的实体统计。

初步查找到 AI、考研、每日疑惑中共 6 份笔记含旧核心/课程路径引用；它们只是定点链接核对候选，不构成对这些内容重新分类的授权。当前 Obsidian 已启用 Bases，未在社区插件清单中发现 Dataview；实现优先利用已确认存在的能力，不预设其他插件已经安装。

### 迁移原则

1. 逐文件检查内容角色；原始资料、原子、综合笔记、主题导航、课程资料索引、系统记录分别处理。
2. 有真实来源可核实则补齐 source。仅内容相关不构成历史取材证据；找不到可靠来源时不伪造，保留原内容并进入 Inbox 待核实，报告具体路径。不能将这种条目计作通过新原子规则。
3. 旧“已完成/已整理/已校对”等不证明原子归档已完成。来源默认 not done，只有实际归档及审查证据充分时才设 done；采集/润色/OCR 历史状态按职责保留。
4. 旧“知识梳理”“答疑”按内容归类，不能靠改 type 把综合内容伪装成原子。类型不明时先进入待核实范围。
5. 课程资料索引不自动变为学科 MOC，原始转换 MD 不自动变为 lecture。必要管理索引可保留为系统/资料索引，不参与新知识实体统计。
6. 缺少 time 的历史笔记，优先核实既有创建时间字段，其次文件历史记录及文件创建时间；采用的依据写入迁移报告。不能用迁移执行时间冒充历史创建时间。若只能得到近似记录，应在报告中明确其局限。
7. 去掉笔记 YAML title 前检查与文件名的差异；有意义的别称经核实进入 aliases，原始字节与字段变化仍可恢复。
8. 保留用户正文、批注、公式、块 ID、来源定位及自定义字段。正文只做移动必需的定点链接修复；合并或拆分需有单独语义依据与可审计差异。
9. 内链、Markdown 相对路径、图片引用、PDF 定位、HTML/Canvas 等已发现的路径消费者要一并盘点。无法确定的链接报告为待核实，不猜测改写。

本轮是架构与已有内容迁移，不默认对全部 1,251 份历史 Markdown 执行一次全量知识提炼。新提炼流程需要可演示、可用；未处理来源按 not done 留待后续指令。

## 10. 系统实现约束

尽量复用现有 Validator、Link Validator、维护审计与 change_control，将新要求作为明确版本演进。实施决定：新规则形成 v2（MOC 身份、必填 source/topics/time 与来源类型扩展都属于实质变化）；由系统管理版本标记，历史 v1 继续可识别，不把新规则静默套给未迁移内容。

模板复制时的动态 time 与占位链接需通过创建入口填充。模板是系统样本，不作为真实知识计数；模板有效与新笔记必填值完整分开检查，不能因为模板放了空列表就放松实际笔记校验。

学习内容、系统文件、原始资料、历史兼容条目、独立工程的统计必须分开。主题数据库、标签数据库、课程资料视图和图谱消费者均落实相同的范围规则。未修改的插件过滤不能声称已统一。

同步相关入口：录音拉取与课程归档、逐字稿润色、模板创建、标签维护、现有 Bases 和规范中的有效命令。现有 exe 如需继续作为课程入口，须重打包并验证对应路径/状态协议；不能只改 Python 就声称旧 exe 已同步。未涉及本轮功能的脚本不批量搬迁。

Formatter 当前仍未定位、未集成。如果本轮提供格式化能力，应明确它是新建或复用的哪一实现、实际作用范围及测试，不借用旧名字声称已经接入。数学正文不做无关自动格式化。

## 11. 变更控制、验收与交付

执行前必须生成 dry-run、逐文件 diff、旧/新 SHA-256、路径映射、备份清单与恢复命令，再按确认的设计范围执行。备份在 Vault 外保存，防止被实体扫描收录。恢复以字节与原路径为依据，不覆盖之后的用户编辑。

每次应用前重核来源与目标哈希，拒绝并发改动和目标碰撞；文件移动不覆盖同名文件。中断保留事务日志和恢复能力，不用递归删除清空旧目录。

验收至少覆盖：

- 新旧版本识别、所有约定类型的字段、必填与可选规则；MOC type 识别及系统隔离。
- 非空且有效的原子 source/topics，来源对象类型，重复/歧义链接的区分。
- MOC 多上层、递归汇集、去重、循环拒绝；真实界面或可核对生成结果的展示。
- 标签标准名与同义名称复用、新标签登记、旧脚本隔离适配。
- 课程跨目录资料汇集、多 subject、lecture_date/due_date、polish_status 与提炼 status 的独立性。
- 一次指令从真实、限定的 Sources 样本提炼或复用原子；可查出处、可更新状态；待人工审查的无需提炼候选不自动完成。
- 中文路径、重名文件、图片与 PDF 链接、用户已有改动、独立工程排除，以及中断/恢复的隔离测试。
- 迁移后审计及逐章抽检：内容保存、链接、原文件映射、附件哈希、旧路径残留与异常清单。

交付提供 Home、模板入口、日常提炼指令、审计/恢复命令和本次实际迁移结果。报告区分架构交付、历史来源待处理量、待核实例外和未改动的范围，不把脚本退出码 0 当作全库知识内容已经通过。

## 12. 待完整设计确认时突出说明的实施决定

以下为实施者依据已确认需求提出的具体落地方式，而非用户逐项原话：

- v2 版本演进、MOC 层级拒绝环、递归能力可使用 System 辅助索引。
- idea 由用户维护属性，参与提炼时 AI 仅按流程更新 status。
- 原来源内容变化在下一次指令运行时重新检查，不新增自动调度。
- 无法核实来源的旧条目进入 Inbox，不伪造 source；历史 time 的采用依据进入报告。
- 不改非课程内容的结构；仅对受本轮移动影响且可确定的跨范围链接做定点修复，并单列 diff。
