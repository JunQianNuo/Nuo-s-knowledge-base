# AGENTS 更新建议稿（Phase 1）

本文件是待将来单独审核的根级指令建议稿，不是生效的 AGENTS.md，不覆盖根 AGENTS.md、CLAUDE.md 或旧规范。当前实施依据是用户在本次会话中对 20 个新增文件的明确批准。不能因本稿存在而扩大权限或自动更新其他规则。

## 建议补充的项目模型

- concept 回答对象是什么，保留定义、符号、直观理解、边界及必要例子。
- proposition 回答在什么条件下结论成立，保留假设、量词、结论、证明或依据及适用范围。
- method 回答怎样执行，交代输入、适用条件、步骤、输出、检查和失败边界。
- 三类并列，仅在有独立理解、复用与链接价值时拆分。不为凑齐三类而建卡。
- MOC 是导航视图，使用 role: moc；历史 type: MOC 暂兼容。它不属于三类原子实体。

## 建议补充的元数据规则

原子笔记必须有合法 type；YAML title 可省略，展示标题默认取文件名。schema_version 是可选字段，新模板默认填整数 1。没有版本标记且通过兼容检查，不证明笔记历史上按 v1 创建。

topics、prerequisites、about、uses、related 按需填写，v1 使用带引号的整篇笔记 Wiki-link 列表，允许短名称或路径；不允许嵌入、别名、标题和块锚点。来源信息与语义关系分开，保留引用、页码及时间戳，不维护冗余逆向属性。tags 只辅助检索，不从链接文字机械补标。

历史“知识点”仅标记为待语义审查，不无条件映射为 proposition。未知属性先报告，不能自动删除或丢失值。

## 建议补充的维护边界

读取注册表、模板和 Schema 后再生成新内容。结构验证通过不等于链接存在、关系正确、数学论证正确或用户已经掌握。

未来统计、MOC 查询和知识图谱构建必须先排除系统目录、模板、测试、治理文档与标签/属性管理记录。不得仅凭 type: concept 就把模板计入实体。排除策略见 [[docs/KNOWLEDGE_ARCHITECTURE]]。

重要批量操作必须有范围、规则版本、原文件哈希、逐文件 diff 和恢复方案，审批绑定具体计划；遇到并发修改时停止，不能覆盖用户后续编辑。保留原笔记、附件、Git 历史、未提交修改和独立仓库边界。
