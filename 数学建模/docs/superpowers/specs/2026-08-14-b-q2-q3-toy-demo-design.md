# B题Q2与Q3真实数据toy demo设计规范

> [!success] 实施状态
> 2026-08-14已按本规范完成实现。Q1/Q2/Q3合计44项测试通过；Q2与Q3的MILP、独立穷举和输出CSV重算一致，要求的17项代码输出与报告产物均存在。

## 1. 目的与边界

本任务为[[联赛题目/B题/模型选型/M1正式模型/03-Q2正式数学模型.md|Q2 APDP-GSP模型]]和[[联赛题目/B题/模型选型/M1正式模型/04-Q3正式数学模型.md|Q3 TS-CGS模型]]建立两个可重复的真实数据toy demo。它们用于验证：

1. 真实附件能够被正确读取并映射到模型接口；
2. 候选架次通过统一的容量、燃油、停靠、取送和时间可行性检查；
3. 有限列池主问题的MILP结果与独立穷举结果一致；
4. 输出CSV经过独立重算后仍满足约束并复现全部指标。

本任务明确不包含：

- Q2成对ALNS完整实现；
- Q3大规模时刻嵌入或全量冲突图搜索；
- Q2/Q3各4,000人的正式求解；
- 对有限列池之外全局最优性的证明；
- 对已经通过测试的Q1代码进行重构。

因此，报告只能称为“真实切片模型接口验证”，不得将toy指标写成正式比赛结果。

## 2. 数据来源与只读约束

输入只读使用以下附件：

- `peopleQ2.csv`
- `peopleQ3.csv`
- `distances.csv`

运行前后计算三个输入文件的SHA-256。只要任一哈希发生变化，运行立即失败。程序不得写入附件目录，也不得覆盖题给的`q2-routes.csv`、`q2-assignments.csv`、`q3-routes.csv`或`q3-assignments.csv`模板。

所有toy输出分别使用`q2_toy_`和`q3_toy_`前缀。

## 3. 总体架构

数据流固定为：

```text
真实CSV切片
  -> 构造有限候选列
  -> 独立可行性核
  -> SciPy MILP词典序求解
  -> 穷举oracle
  -> 从输出CSV独立重算
  -> 三方一致后输出PASS
```

代码边界如下：

```text
联赛题目/B题/代码/
├─ common/toy_core.py
├─ 问题二/
│  ├─ q2_toy_demo.py
│  ├─ tests/test_q2_toy_demo.py
│  ├─ results/
│  └─ figures/
└─ 问题三/
   ├─ q3_toy_demo.py
   ├─ tests/test_q3_toy_demo.py
   ├─ results/
   └─ figures/
```

`toy_core.py`只服务Q2/Q3，提供：

- 三种机型参数和可加油设施常量；
- 距离矩阵读取和输入模式检查；
- 整数分钟航段时间；
- 航段燃油、最低安全余油、停靠时长和最多5次海上着陆检查；
- 动态载客量、人员时间、客座公里和可用座公里重算；
- 统一的`ToyValidationError`异常。

Q2负责无时间窗的成对取送和广义集合划分；Q3负责带时刻列、时间窗、具体飞机兼容、冲突图及三阶段目标。Q1保持不变，以避免无关回归。

## 4. Q2真实切片

### 4.1 人员

从`peopleQ2.csv`固定选择三个OD组，每组12人：

| 组 | OD | 人员编号 |
|---|---|---|
| `G_OUT` | `LAND -> F003` | P0030、P0033、P0035、P0257、P0715、P0735、P0925、P1108、P2695、P2719、P3063、P3268 |
| `G_SHUTTLE` | `F003 -> F008` | P0705、P0806、P1116、P1348、P1951、P2461、P2941、P3045、P3148、P3389、P3430、P3458 |
| `G_RETURN` | `F008 -> LAND` | P0779、P0949、P1176、P1546、P1693、P1727、P1833、P2035、P2542、P2629、P2745、P3534 |

`LAND`在本实例中映射为A01。构造时必须逐个核对人员编号、起点和终点；缺失、重复或OD不一致均立即失败。

### 4.2 候选列

有限列池由四列组成：

| 列 | 机型与路线 | 服务内容 | 使用时间 |
|---|---|---|---:|
| `R_RELAY` | T3，`A01-F003-F008-A01` | 三组各12人 | 163 min |
| `R_OUT` | T2，`A01-F003-A01` | `G_OUT` 12人 | 116 min |
| `R_SHUTTLE` | T3，`A01-F003-F008-A01` | `G_SHUTTLE` 12人 | 163 min |
| `R_RETURN` | T3，`A01-F008-A01` | `G_RETURN` 12人 | 150 min |

联合列的逐站过程为：

| 位置 | 地点 | 到达分钟 | 离开分钟 | 操作后载客量 |
|---:|---|---:|---:|---:|
| 0 | A01 | — | 0 | 12 |
| 1 | F003 | 61 | 71 | 12 |
| 2 | F008 | 83 | 93 | 12 |
| 3 | A01 | 163 | — | 0 |

在F003先放下`G_OUT`的12人，再接上`G_SHUTTLE`的12人；在F008先放下`G_SHUTTLE`，再接上`G_RETURN`。因此共运输36名不同人员，但任一航段只有12人在机，低于T3的19座。若错误地按“先上后下”处理，中间瞬时人数会成为24，测试必须能暴露该错误。

联合列总距离为451 km，燃油消耗为`451 x 2.9 = 1307.9 kg`，返场余油为292.1 kg，不低于T3的200 kg安全余油；全程无需加油。

### 4.3 Q2主问题与判定值

变量为四个候选列的非负整数执行次数。三个组均须精确覆盖12人。求解顺序严格为：

1. 总飞机使用时间；
2. 人员总在途时间；
3. 总燃油；
4. 总架次数；
5. 负座位利用率。

MILP和穷举都必须选中`R_RELAY=1`、其余为0。三条分离列合计429分钟，联合列为163分钟；即使分离方案的人员时间更小，也不得越过首要目标选择分离方案。

预期最终指标为：

| 指标 | 预期值 |
|---|---:|
| 服务人数 | 36 |
| 飞机使用时间 | 163 min |
| 人员总在途时间 | 1716 person-min |
| 总燃油 | 1307.9 kg |
| 总架次数 | 1 |
| 座位利用率 | 0.631578947368421 |

### 4.4 Q2负例

自动测试至少包含：

- 把穿梭人员下机位置设为第二次到达F008，违反首次到达规则；
- 把接人事件放在送人事件之前；
- 按先上后下计算导致容量超限；
- 使用续航不足的机型；
- 删除一个人员或重复覆盖一个人员；
- 破坏路线外键或停靠序号连续性。

## 5. Q3真实切片

### 5.1 人员与业务性质

固定选择六名真实人员：

| 人员 | OD | 时间窗 | 性质 | 最终状态 |
|---|---|---|---|---|
| P1100 | `LAND -> F001` | 2026-08-03 06:14 至 08:07 | emergency | 必须服务 |
| P1664 | `LAND -> F019` | 2026-08-03 08:20 至 10:55 | production | 必须服务 |
| P1414 | `F001 -> LAND` | 2026-08-03 00:00 至 2026-08-05 09:10 | temporary | 接纳 |
| P1982 | `LAND -> F019` | 2026-08-03 00:00 至 2026-08-06 10:06 | temporary | 接纳 |
| P2332 | `F019 -> LAND` | 2026-08-03 00:00 至 2026-08-06 11:45 | temporary | 接纳 |
| P2278 | `LAND -> F006` | 2026-08-03 00:00 至 2026-08-05 10:37 | temporary | 预算下取消 |

P1100与P1664代表非临时硬覆盖；四名临时人员用于验证选择性服务。

### 5.2 具体飞机集合

程序按题面表3生成全部24个飞机编号。与本实例两条T3/A01列兼容的飞机只有：

- `A01-T3-H01`
- `A01-T3-H02`

`A01-T2-H01`因机型不符而不兼容，`A02-T3-H01`因所属机场不符而不兼容。若多个具体飞机在全部正式目标上完全等价，最终仅使用按飞机编号升序的稳定规则消除输出随机性；该规则是计算性tie-break，不属于题目目标。

### 5.3 阶段A候选列与基准

两条非临时候选列为：

| 列 | 路线与时刻 | 非临时人员 | 时间 | 燃油 |
|---|---|---|---:|---:|
| `M_F001` | T3，A01 06:14—F001 07:24/07:34—A01 08:44 | P1100 | 150 min | 1270.2 kg |
| `M_F019` | T3，A01 09:14—F019 10:19/10:29—A01 11:34 | P1664 | 140 min | 1183.2 kg |

F001和F019都不是加油设施，两条路线均不加油。两条往返距离分别为438 km和408 km，均满足T3续航，但超过T2在安全余油约束下的400 km可用航程，因此机型T3具有实质必要性。

P1100在最早时刻06:14登机，07:24到达，不晚于08:07；P1664于09:14登机，10:19到达，不晚于10:55。由于两人的时间窗不允许合并为同一架次，阶段A有限列池基准固定为：

```text
B0 = 150 + 140 = 290 min
```

第一架次返场加30分钟周转后的占用区间为`[06:14, 09:14)`；第二架次从09:14起飞，因此两者不冲突，可以由同一架`A01-T3-H01`连续执行。把第二架次改为09:13起飞时，测试必须判定冲突。

### 5.4 阶段B与阶段C候选列

阶段B增加：

- `MT_F001`：与`M_F001`同路线、同时间，增加P1414；
- `MT_F019`：与`M_F019`同路线、同时间，增加P1982和P2332；
- `T_F006`：T2的`A01 06:00-F006 07:05/07:25(加油)-A01 08:30`临时专用列，服务P2278，使用时间150分钟，只与A01的T2飞机兼容。

`MT_F001`和`MT_F019`不增加飞机使用时间，可以在290分钟预算内接纳三名临时人员。选择`T_F006`会使总使用时间至少增加150分钟，因此在预算约束下不可选。

阶段B最大化临时人数，预期最优值为3；阶段C固定接纳3人后，依次最小化：

1. 飞机使用时间；
2. 人员总在途时间；
3. 总燃油；
4. 总架次数；
5. 负座位利用率。

最终应由`A01-T3-H01`执行两个架次。预期指标为：

| 指标 | 预期值 |
|---|---:|
| 非临时服务 | 2/2 |
| 临时服务 | 3/4，即75% |
| 飞机使用时间 | 290 min |
| 人员总在途时间 | 335 person-min |
| 总燃油 | 2453.4 kg |
| 总架次数 | 2 |
| 座位利用率 | 0.06532288167226577 |

P2278必须保留在toy人员输出中，且`aircraft_id`、`flight_no`、`pickup_stop_order`和`delivery_stop_order`四列全部为空。

### 5.5 Q3负例

自动测试至少包含：

- 起飞早于06:00、晚于18:00或返场晚于20:00；
- 人员早于最早登机时间离开起点；
- 人员晚于最晚到达时间送达；
- 返场后仅29分钟再次起飞；
- 机场正确但机型错误，以及机型正确但机场错误；
- 临时专用架次导致总使用时间超过290分钟；
- 非临时人员未覆盖或重复覆盖；
- 未服务临时人员没有保留空白行；
- 时间字段不满足整数分钟逐站传播。

## 6. 求解与独立校验

### 6.1 MILP

使用`scipy.optimize.milp`。每一级词典序目标单独求解；取得该级最优值后，将其固定，再求解下一级。禁止用未经证明的加权和替代词典序。

Q3依次执行：

1. 阶段A最小化非临时基准；
2. 阶段B在基准预算内最大化临时接纳人数；
3. 阶段C固定接纳人数后执行次级词典序。

### 6.2 穷举oracle

由于候选池很小，独立枚举所有列组合及Q3兼容飞机指派。oracle不调用MILP内部函数，也不复用其约束矩阵。以下内容必须完全一致：

- 可行/不可行判断；
- 选中列与执行次数；
- Q3临时接纳人数；
- 各级目标值；
- 最终人员覆盖集合。

### 6.3 输出后重算

第三条校验路径只读取生成的routes和assignments CSV，从零重建：

- 路线连续性和首末机场；
- 飞行时间、停靠时间与燃油轨迹；
- 每人的上下机位置、首次到达和动态载客量；
- Q3时间窗、飞机兼容和周转冲突；
- 使用时间、人员时间、燃油、架次数和座位利用率。

只有“MILP = 穷举oracle = 输出后重算”时才写入`PASS`。任一不一致均抛出异常，并且不得生成宣称成功的报告。

## 9. 失败处理

以下任一情况均为硬失败：

- 输入字段、固定人员或距离数据不符；
- 候选列违反任何硬约束；
- MILP无解或未报告最优；
- MILP与oracle不一致；
- 输出后重算与内存指标不一致；
- 写出路径指向附件或正式模板；
- 图表、报告或指标文件在验证完成前宣称PASS。

失败时保留清晰的异常原因，但不得静默放松约束、替换人员、扩大时间窗或提高预算。
