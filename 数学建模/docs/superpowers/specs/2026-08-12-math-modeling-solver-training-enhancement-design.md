# math-modeling-solver-copy 培训内容流程增强设计

## 1. 目标

在不重构现有目录、不移动 Cookbook、Playbook 和代码模板的前提下，将三次培训中可迁移的方法落实为 `math-modeling-solver-copy` 的强制工作流。

改造后的 Skill 应做到：

1. 推荐模型前先识别问题机制和数据结构；
2. 以可解释基准模型为起点，用证据决定是否升级；
3. 数据处理、模型假设和参数均可追溯；
4. 优化问题能够报告求解状态并诊断不可行；
5. 代码、结果和图表可复现；
6. 模型、代码与论文形成可核查的证据链；
7. 全流程任务支持团队滚动协作，AI 产物必须人工核验；
8. 局部咨询不过度启动完整竞赛工程。

## 2. 范围

### 2.1 本轮包含

- 保留现有阶段 0—8，增强各阶段的进入条件、输出物和质量门禁；
- 新增全流程、局部协助、方案审查三种工作模式；
- 新增数据审计、基准模型阶梯、条件化算法检查、求解器专项工程、复现、团队协同和 AI 核验规则；
- 扩展模型检验、图表规划、结果分析与论文交接；
- 为新增规则建立静态检查和行为场景测试；
- 只修改副本，不影响原版 `math-modeling-solver`。

### 2.2 本轮不包含

- 不移动或重命名现有参考文件；
- 不重写 12 个 Playbook；
- 不批量重构 29 个代码模板；
- 不新增求解器厂商专属教程；
- 不把 `math-modeling-paper` 的论文写作职责并入 solver；
- 不创建完整竞赛项目审计程序；该类自动化留给后续系统重构。

## 3. 设计原则

### 3.1 基准优先

复杂模型必须回答：为什么需要、参数来自哪里、相对基准改善了什么。若收益不足，应保留更简单、稳健、可解释的方案。

### 3.2 数据结构先于模型名称

必须先识别观测单位、独立性、分组、重复测量、时间顺序、截尾、类别不平衡及采样机制，再选择统计假设和模型。

### 3.3 证据触发升级

仅当残差、验证结果、数据结构、现实机制或决策要求暴露基准模型不足时，才升级模型。

### 3.4 检验前置

写代码前定义“什么结果算通过”；检验失败时回退模型或算法，禁止用事后叙事掩盖问题。

### 3.5 结果可追溯

核心结论必须连接题意、公式、代码输出、检验和图表，保证结果能够进入论文并被复核。

### 3.6 按任务规模执行

完整赛题执行全部门禁；局部公式、模型或代码咨询只执行相关检查，避免不必要的文件创建和逐阶段停留。

## 4. 总体架构

现有 0—8 阶段保持不变，在其外增加工作模式路由，并在阶段间增加六类横向约束。

```text
用户请求
  ├─ 全流程模式：完整赛题、从零求解
  ├─ 局部协助模式：指定模型、公式、代码或单一问题
  └─ 方案审查模式：已有模型、代码或结果需要检查
            ↓
阶段0—8既有流程
            ↓
横向约束：
数据审计｜基准模型｜证据溯源｜求解诊断｜复现｜团队与AI治理
```

## 5. 工作模式

### 5.1 全流程模式

**触发：** 用户给出完整赛题，要求分析、求解或产出完整方案。

**行为：**

- 执行阶段 0—8；
- 创建标准项目结构；
- 创建术语与变量字典、假设证据表、团队里程碑和复现清单；
- 各阶段按原规则等待确认；
- 未通过强制门禁不得进入后续阶段。

### 5.2 局部协助模式

**触发：** 用户只询问某个模型、公式、算法、代码、图表或检验方法。

**行为：**

- 直接进入相应阶段；
- 不强制创建完整目录；
- 执行与当前任务直接相关的最小检查；
- 明确缺失上下文和结论适用边界；
- 不把局部答案包装成完整赛题结论。

### 5.3 方案审查模式

**触发：** 用户已有模型、代码、论文片段或结果，希望检查、改进或判断可靠性。

**行为：**

- 先建立审查范围；
- 按数据结构、假设、模型必要性、实现一致性、检验和复现六项审查；
- 输出“通过、警告、失败”及修复优先级；
- 不无理由替换用户已有方案。

## 6. 阶段增强设计

### 6.1 阶段0：项目初始化

全流程模式在原有目录基础上新增：

| 文件 | 作用 |
|---|---|
| `问题分析/术语与变量字典.md` | 统一概念、符号、单位、索引和来源 |
| `问题分析/假设与证据登记表.md` | 记录假设、依据、适用边界及验证方式 |
| `问题分析/团队分工与里程碑.md` | 记录滚动分工、时间节点和交付关系 |
| `代码/运行与复现清单.md` | 记录环境、依赖、入口、随机种子、参数和输出 |

初始化阶段只确认会影响后续执行的必要信息：比赛类型、语言偏好、题目文件、时间限制及是否有队伍分工信息。

### 6.2 阶段1：问题与数据审计

保留逐题拆解，新增独立的 `数据审计报告.md`。最低审计项如下：

| 维度 | 必须回答的问题 |
|---|---|
| 观测单位 | 每一行、每个样本或每个节点代表什么？ |
| 观测关系 | 是否独立，是否存在分组、嵌套、重复测量或个体差异？ |
| 顺序结构 | 是否存在时间顺序、空间关系或网络依赖？ |
| 采样机制 | 是否存在截尾、选择偏差、信息缺失或测量误差？ |
| 数据质量 | 缺失、异常、噪声、重复及无效记录如何定义？ |
| 类别分布 | 是否不平衡，关键少数类的错误代价是什么？ |
| 单位数量级 | 单位、量纲、符号方向和极端范围是否合理？ |
| 数据泄漏 | 预处理、特征和验证是否使用了不应提前知道的信息？ |

处理规则必须记录依据，并规划至少一张处理前后对比图。无法取得数据时，输出待检查项而不是虚构审计结论。

### 6.3 阶段2：基准模型与升级论证

候选模型表前增加“模型阶梯”：

| 层级 | 内容 |
|---|---|
| 常识基线 | 均值、简单规则、数量级估算或领域下界 |
| 数学基准模型 | 可解释、快速、参数较少的首个可运行模型 |
| 升级模型 | 针对已识别缺陷增加机制、变量或算法 |
| 替代路线 | 原理不同、可用于互证或失败回退的方案 |

升级模型必须填写：

- 基准模型暴露的具体不足；
- 不足的证据；
- 升级增加的假设和参数；
- 预期改善指标；
- 计算与解释代价；
- 若改善不显著时的回退方案。

模型评分不能只比较精度，还应比较适用条件、稳定性、可解释性、复现成本和现实可执行性。

### 6.4 阶段3：算法设计与条件化求解工程

本阶段采用“**通用算法契约 → 算法专项检查 → 求解器专项检查**”三级结构。并非所有算法都使用数学规划求解器；仅当实现实际调用求解器时，才执行求解器专项检查。不适用项必须标明“不适用”及理由，不得虚构求解状态或最优间隙。

#### 6.4.1 通用算法契约

所有算法均需说明：

- 输入、输出、参数及其数据类型和单位；
- 初值或初始化方式；若算法无初值，则标明不适用；
- 参数范围、停止条件和随机性；
- 时间、内存和问题规模预算；
- 正常完成、未收敛、超时、数值异常等状态及处理路径；
- 预期保存的中间结果、日志和复现信息。

#### 6.4.2 算法专项检查

根据实际采用的算法选择对应检查，不要求无关算法执行求解器指标。

| 算法类型 | 专项检查 |
|---|---|
| 闭式公式与直接计算 | 量纲、数量级、极端情形、题给基准值和数值精度 |
| 回归与统计模型 | 统计假设、残差、参数区间、独立验证和多重检验 |
| 机器学习 | 数据划分、数据泄漏、过拟合、评价指标、随机种子和校准 |
| GA、PSO、模拟退火等随机优化 | 初始化、超参数、收敛曲线、多次独立运行分布和基准对比 |
| 蒙特卡洛模拟 | 抽样机制、样本量、随机种子、收敛误差和方差控制 |
| ODE/PDE 与其他数值计算 | 步长、容差、稳定性、网格或步长收敛及守恒检查 |
| 聚类与分组 | 类别数依据、内部指标、扰动稳定性和现实解释 |
| 自编精确或组合算法 | 正确性基准、复杂度、边界样例、最优性证明或可验证下界 |

随机优化算法通常无法提供数学规划求解器意义上的最优间隙，因此应报告多次运行的最优值、均值、方差或区间、收敛曲线，以及与基准方案或可验证下界的差异。

#### 6.4.3 求解器专项检查

仅在使用数学规划求解器时执行：

| 项目 | 要求 |
|---|---|
| 数学含义 | 逐项解释决策变量、目标项和约束对应的现实动作 |
| 方法选择 | 说明精确求解器、启发式算法或混合策略的选择依据 |
| 求解状态 | 区分最优、可行、不可行、无界、超时和数值异常 |
| 最优间隙 | 超时或大规模问题保留 incumbent、bound 与 gap |
| 不可行诊断 | 使用冲突约束、最小松弛或逐组关闭约束定位原因 |
| 灵敏度信息 | 适用时读取松弛量、影子价格或通过参数扫描替代 |
| 预测—决策 | 明确预测误差如何进入目标、约束及稳健性分析 |

### 6.5 阶段4：模型检验矩阵

每个核心结论至少规划两类互补检验；风险高或结论关键时至少三类。

| 模型类型 | 最低检验集合 |
|---|---|
| 回归与预测 | 留出/时序验证、残差检查、基准模型对比 |
| 分类 | 分层验证、混淆矩阵、关键类别精确率/召回率/F1 |
| 聚类与分组 | 内部指标、扰动稳定性、现实解释 |
| 优化 | 可行性、基准方案对比、参数/情景敏感性 |
| 机理模型 | 量纲、题给基准值、极端退化、参数敏感性 |
| 评价与排序 | 权重敏感性、排序稳定性、替代方法互证 |

涉及估计和预测时，优先给出置信区间、预测区间、重复实验分布或其他不确定性表达。检验方案继续保留“不合格处理”，并明确回退到阶段2还是阶段3。

### 6.6 阶段5：图表与证据规划

扩展 Figure Contract 的来源类型：

- 原始数据结构与质量；
- 数据处理前后对比；
- 基准模型与升级模型对比；
- 拟合、预测、残差和不确定性；
- 参数敏感性、情景变化和方法互证；
- 求解收敛、最优间隙或不可行诊断；
- 决策变量到现实方案的翻译。

每张图必须说明它支持哪一条 Claim；装饰性图表不进入“必须生成”清单。

### 6.7 阶段6：实现与复现

在现有模板优先规则上增加复现契约：

- 唯一运行入口；
- 环境和依赖版本；
- 随机种子；
- 输入、输出和编码说明；
- 参数配置及来源；
- 求解状态与日志；
- 中间数据和图表数据；
- 结果文件命名；
- 失败时的明确错误信息。

AI 可辅助生成代码骨架、调试和重复性工作，但必须逐项核对数据变换、公式、索引、参数范围和输出解释。未经运行与核验的 AI 代码不得标记为完成。

### 6.8 阶段7：结果分析与诊断

结果报告增加以下字段：

| 类型 | 必须报告 |
|---|---|
| 所有模型 | 实际结果、基准结果、检验结果、误差或不确定性 |
| 随机算法 | 随机种子、多次运行分布、稳定性 |
| 优化模型 | 求解状态、目标值、bound、gap、运行时间、主要参数 |
| 不可行模型 | 冲突约束、最小松弛和修改依据 |
| 决策模型 | 变量取值对应的现实方案、瓶颈与实施条件 |
| 预测—决策模型 | 预测质量与决策质量分别报告 |

若升级模型没有明显优于基准，应保留基准模型，或明确说明复杂模型的非精度收益。

### 6.9 阶段8：论文交接

交接 `math-modeling-paper` 前执行证据链检查：

| Claim | 题意依据 | 公式/模型 | 代码入口 | 数值结果 | 检验 | 图表 | 论文位置 |
|---|---|---|---|---|---|---|---|
| C1 | | | | | | | |

同时检查：

- 变量、单位和索引在字典、公式、代码及表格中一致；
- 参数明确区分题给、文献、数据估计和主观设定；
- 数据处理、假设简化和模型修正有依据；
- 论文不把求解器调用当成数学模型；
- 优化结果说明最优、近似还是仅可行；
- 图前提出问题，图后解释其支持的结论。

## 7. 横向治理规则

### 7.1 团队协同

仅在全流程模式强制：

1. 第一轮题意和基础问题由全队共同理解；
2. 分工采用滚动推进，而非完全割裂；
3. 建模、代码和论文使用同一份变量、参数与约束字典；
4. 模型迭代后同步更新数学表达、代码实现、结果和论文说明；
5. 至少设置选题、基准模型、完整结果、论文初稿和最终检查五类里程碑；
6. 分工建议不虚构队员能力，用户未提供团队信息时只输出可选角色模板。

### 7.2 AI 使用边界

- AI 适合检索词生成、代码骨架、调试、格式转换和解释辅助；
- AI 不代替问题机制判断、模型选择和结果验收；
- 公式、参数和文献必须回到题面、权威资料或可验证数据；
- 无法核验的内容标记为“待验证”，不得作为最终依据；
- 不接受只有截图或一句话上下文就生成完整答案；应先补齐变量含义、数据结构和目标。

### 7.3 范围控制

- 局部问题不创建完整项目目录；
- 用户明确跳过文献检索时，保留参数与假设的来源风险说明；
- 时间紧迫时可压缩候选模型数量，但不能跳过数据结构检查、基准方案和核心验证；
- 不为了执行流程而制造不存在的数据、团队信息或验证结果。

## 9. 错误处理与回退

| 情况 | 行为 |
|---|---|
| 数据不存在或字段含义不清 | 输出待确认项，停止作确定性模型结论 |
| 模型假设不满足 | 标记失败并回到数据处理或模型设计 |
| 升级模型无改善 | 回退基准模型，记录复杂度不值得 |
| 非求解器算法未收敛或结果不稳定 | 按算法类型检查初值、步长、超参数和停止条件，执行重复运行或收敛性分析 |
| 优化不可行 | 执行冲突与最小松弛诊断，不随意删除约束 |
| 求解超时 | 报告当前可行解、bound 与 gap，再讨论替代算法 |
| 检验失败 | 回退阶段2或3，禁止直接进入论文 |
| AI 内容无法核验 | 标记待验证，不纳入最终结论 |
| 论文与代码不一致 | 阻止 `[PAPER_READY]`，先修正字典或结果映射 |

## 10. 验收方案

### 10.1 静态检查

- `quick_validate.py` 验证 Skill frontmatter；
- 检查所有相对引用目标存在；
- 检查主 `skill.md` 包含三种模式和新增资源入口；
- 确认原版所有文件哈希保持不变；
- 检查没有未完成占位符或无定义模板字段。

### 10.2 行为测试场景

| 编号 | 输入场景 | 预期行为 |
|---|---|---|
| B1 | 完整赛题与附件 | 进入全流程模式并先做问题、数据审计 |
| B2 | 只问某个公式 | 进入局部协助，不创建完整目录 |
| B3 | 已有模型求审查 | 使用方案审查模式，不直接推翻方案 |
| B4 | 重复测量数据 | 识别非独立性并限制普通回归的直接使用 |
| B5 | 时间序列随机划分 | 识别数据泄漏并改为按时间验证 |
| B6 | 严重类别不平衡 | 不以总体准确率作为唯一指标 |
| B7 | 复杂模型无基准 | 要求先建立可解释基准模型 |
| B8 | 整数规划不可行 | 先诊断冲突约束和最小松弛 |
| B9 | 求解超时 | 报告当前解、界与最优间隙 |
| B10 | 遗传算法未使用数学规划求解器 | 报告多次运行分布、收敛曲线和基准差异，不要求虚构最优间隙 |
| B11 | ODE 数值求解 | 检查步长、容差和数值稳定性，不触发求解器专项检查 |
| B12 | AI 提供未知文献 | 要求回源核验，不直接采用 |
| B13 | 模型与代码符号不一致 | 阻止论文交接并要求修正 |
| B14 | 用户时间紧迫 | 压缩候选数量但保留数据审计、基准和核心检验 |

1. 所有计划文件已修改或新增；
2. Skill 结构和相对链接检查通过；
3. 14 个行为场景均有可核查的预期规则；
4. 数据审计、基准模型、条件化算法检查、求解器专项诊断、复现、协同和 AI 核验均能从主流程被触发；

6. 原版目录文件哈希无变化；
7. 没有未解决的占位符、路径错误或规则冲突。
