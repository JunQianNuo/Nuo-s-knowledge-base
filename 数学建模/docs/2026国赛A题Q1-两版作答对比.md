## 4. 缺陷溯源：上一轮那个 $\rho_d$ 问题，修了一半

### 4.1 旧探针（round1 内核）——已确认

`methods/shared/probes/real_task_probe.py`：质量方程用 $j_w=h_m(C_s-C_{air})$，
能量侧潜热却用 `water_flux = dry_density * moisture_flux[-1]`（$\rho_d=230.99$）。
同一时刻两侧水通量差 **230.986 倍**（$t=0$ 时能量侧潜热汇 ≈ 1118 W/m²，对流只供 9.6 W/m²）。

上一轮我用**国赛版自己的算子**只改这一个因子复算，得到：

| 潜热密度因子 | T(0) | T(0.5) | T(1) | T(1.5) | T(2 cm) |
|---|---|---|---|---|---|
| $\times\rho_d$（round1 代码） | 10.65 | 10.69 | 10.86 | 11.25 | 11.98 |
| $\times1$ | 33.48 | 33.67 | 34.26 | 35.26 | 36.64 |
| **AutoMM 交付** | **33.43** | **33.63** | **34.21** | **35.21** | **36.62** |

⇒ 那 23–25 K 的温度差 **100% 由这一个因子解释**。现在 round3 的温度落在 33.58–36.79，
再次从交付数据反证了这一点。

### 4.2 新内核 `q1_model.py`——质量侧修对了，热侧把机制删了

```python
# 第 272-292 行（problem_literal 闭包）
surface_c   = (g_c * c[-1] + h_m * air_humidity_ratio) / (g_c + h_m)
water_flux  = DRY_DENSITY * h_m * (surface_c - air_humidity_ratio)   # ✅ 干基口径，带 rho_d
surface_temp = (g_h * temp_K[-1] + heat_transfer * air_temp_K) / (g_h + heat_transfer)  # ❌ 无潜热
c_flux[-1]  = water_flux / DRY_DENSITY                                # ✅ 除回 rho_d
...
net_heat_in = heat_transfer * (air_temp_K - surface_temp)
if closure == "gas_side":
    net_heat_in -= latent_heat(surface_temp) * water_flux             # 潜热只在 gas_side 里
```

**评价**：

- 质量侧的"通量 → $\mathrm{d}C/\mathrm{d}t$"换算**已经自洽**（$\times\rho_d$ 再 $\div\rho_d$），
  这恰好是我上一轮指出的正确写法，也是 AutoMM `formulation_v002` (D3′) 的写法。
  **所以那个机械缺陷确实被修掉了。**
- 但能量侧**把潜热项整个拿掉了**。这不是修正，是删机制：水分仍以
  $j_w=\rho_d h_m(C_s-C_b)\approx 9.5\times10^{-4}$ kg/(m²·s) 蒸发（$t=100$ s），
  而表面能量平衡里没有对应的 $\pm L_v j_w$。
  在 28–37 °C 区间 $L_v\approx2.44\times10^6$ J/kg ⇒ 潜热通量 ≈ **2.3 kW/m²**，
  远大于对流供水；直接后果就是水分场失控塌陷（2.55 → 2.2453 in 100 s）。
- 换句话说：**质量侧修对了，热侧没有同样的处理，两者又回到互不一致**，只是这次不一致
  表现为"水在蒸但不需要能量"。

### 4.3 `gas_side` 闭包——引入题面没有的物理

按 `q1_model.py` 注释与 `run_q1.py` 的 `CLOSURE_CONTRACT`，该闭包：

- **丢弃题给 $h_m=8\times10^{-7}$ m/s**，改用由 $h_T$ 经 Lewis 关系推的 $h_{mg}$；
- 引入水饱和蒸气压、气相常数、水活度 $a_w$、空气密度等**题面未给的新参数**；
- 用湿球温度作为界面温度下界（`psychrometric_wetbulb_range_degC`）。

它的水分场（1800 s 表面 2.4388）比 round3 合理得多，温度也表现出真实的"先降后升"
（100 s 时 26.67 °C，低于初温 28 °C——这正是表面蒸发冷却的正确特征，AutoMM 也复现了这一现象
并在鲁棒性里登记为"已量化物理例外"）。**但**：审查明确指出，
这些新参数与"放弃题给 $h_m$"都没有建模侧决策授权，属未批准改动。

## 6. 建议（按优先级）

### 必须做（否则 Q1 无法提交）

1. **先跑通正式入口**：`run_q1.py` 的 `TEMPLATE_PATH` 指向 `problem/A题/附件/附件3/result1.xlsx`，
   仓库实际在 `2026国赛题目/A题/附件/附件3/`。这一条修掉，`python-code-reviewer` 的第二个 BLOCKER 即解除。
2. **把闭包拉回"质量侧与热侧同一通量"**：以现在已修对的 `water_flux = DRY_DENSITY * h_m * (surface_c - air_humidity_ratio)`
   为基础，把热边界写成
   $-k\,\partial T/\partial n = h_T(T_{air}-T_s) - L_v(T_s)\,j_w$，
   即 **保留潜热 + 用同一个 $j_w$**。这一步同时解决：
   - round1 的 231× 假象（已修）；
   - round3 的"蒸发不耗能"（未修）；
   - 水分塌陷的**部分**成因（见第 3 条）。
   预期结果会落在 AutoMM 的 33–37 °C 附近而非 10 °C 或 26 °C。
3. **处理剩余的水分驱动偏差**：即使通量口径统一，round3 与 AutoMM 在 $t=100$ s 的表面浓度
   仍有 760 倍差距（2.2453 vs 2.5496）。这不是数值问题，而是**驱动力定义**问题——
   把烘箱空气的 `kg/kg` 直接当作材料干基平衡含水率（$C_b$）。AutoMM 在 ASM-13/CONFLICT-01 里
   把同一做法登记为"等效外部水分势、不是真实平衡含水率"，并因此把结论限定在"给定口径下"。
   国赛版需要在 A13 里做同样的限定，或补一条吸附等温关系。**两者当前都缺这一环，但国赛版的数值后果更极端。**
4. **把 `methods/Q1/q1_decisions.jsonl` 补上闭包决策**：目前 round2/round3/`gas_side` 三套改动
   在这本账里**没有任何记录**（账本最后一条仍是 09:08 的 M1/B1 选择）。
   要么人工追认一套并冻结为 canonical，要么回退到批准的 A12+A13 重跑。
5. **给四套结果定唯一权威**：现在 `results/Q1/experiments/` 下有 round1/2/3 三个目录并列，
   没有任何标记说明哪个进论文。按合同 §6，正式结果应只有一套 + `run_summary.json` 的 `fallback` 状态。

### 建议做

   要么给收敛表并在论文里标注取值网格等级。AutoMM 的对应值是 9.4e-8，差 6 个数量级。
