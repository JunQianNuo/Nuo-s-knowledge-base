# 图表规划：Figure Contract 方法与覆盖检查

## 概述

**时机**：本阶段（阶段5）在模型设计（阶段2）、算法设计（阶段3）、检验方案（阶段4）全部确定后执行。

**为什么放在检验方案之后**：
- 图表是模型结论和检验结果的可视化表达，不是先画图再决定建什么模
- 此时已确定：用什么模型（阶段2）、怎么算（阶段3）、怎么检验（阶段4）
- 因此可以精确规划三类图表素材：
  1. **模型示意**（来自阶段2）：几何关系、系统架构、建模流程图
  2. **结果展示**（来自阶段3）：关键变量的曲线/热力图/散点图
  3. **检验可视化**（来自阶段4）：灵敏度曲线、退化验证图、对比验证图、自洽性示意

本文档定义：
1. Figure Contract 方法（每张图的"合同"）
2. 图原型分类（4 种）
3. Claim-Figure 覆盖检查清单（覆盖模型Claim + 检验Claim）

## Figure Contract 方法

### 概念

每张论文图表在绘制之前，必须先明确它的"合同"——即它要传达什么核心结论、用什么数据生成、属于什么类型、优先级如何。

### Contract 模板

| 字段 | 说明 | 示例 |
|------|------|------|
| 图编号 | 论文中的编号（Fig.1, Fig.2, …） | Fig.1 |
| 核心结论（一句话） | 读者看图后应该带走的关键信息 | "天线张角越大，单星覆盖半角θ单调递增，且增长率逐渐减小" |
| 图类型 | 从4种原型中选 | 定量网格 / 示意主导 / 数据图例混合 / 非对称混合 |
| 数据来源函数 | 生成此图需要调用哪个（些）Python函数 | `coverage_half_angle(alpha, h)` |
| 数据来源公式 | 背后的数学关系（如有） | `θ = arcsin(R·sin(α)/(R+h)) − α` |
| 自变量 | X轴变量及其范围和单位 | `α ∈ [0°, 60°]` |
| 因变量 | Y轴变量及其范围和单位 | `θ ∈ [0°, 90°]` |
| 子图/多线 | 如有：多条曲线分别代表什么 | `h = 500, 800, 1200 km 三条曲线` |
| 优先级 | 必须 / 推荐 / 可选 | 必须 |
| 预期位置 | 论文中放在哪里 | "问题一模型建立部分，紧接公式(3)" |
| 与其他图的关联 | 该图的结论支撑或依赖哪张图 | 为 Fig.2 的覆盖判断提供输入 |

### 填写规则

1. **核心结论必须可验证**：不是"展示覆盖效果"，而是"N=40颗星时覆盖率达到99.3%，N=30时降至87.1%"——后者可以被读者用眼睛验证
2. **数据来源函数必须具体到函数名**：不是`ground_track()`，而是`ground_track_latitude(t, i, T, h)`——确保后续编码阶段不遗漏
3. **优先级决定实现顺序**：先实现"必须"级图表，再实现"推荐"级；"可选"级在时间充裕时实现

## 图原型分类（4 种）

### 1. 定量网格（Quantitative Grid）

**特征**：
- 多子图排列（2×2、3×2 等）
- 每个子图传达一个定量结论
- 风格统一，子图之间可对比
- 适合：多参数灵敏度分析、多场景结果对比、多方法benchmark

**示例场景**：
- N=20/30/40/50 四种部署密度下的覆盖率热力图（2×2网格）
- 四种优化算法（GA/PSO/SA/Grid Search）的收敛曲线对比（4×1网格）

**实现指导**：
- 使用 matplotlib `plt.subplots()` + 统一 `rcParams`
- 子图之间共享坐标轴范围以确保可比性
- 每子图标注核心数值（如最终收敛值）

### 2. 示意主导（Illustration-Dominant）

**特征**：
- 一张大幅示意图/流程图 + 少量文字标注
- 目的是传达"关系"或"逻辑"而非精确数据
- 适合：几何关系、系统架构、算法流程图、问题分解图

**示例场景**：
- 星地覆盖几何示意图（卫星位置、天线波束、地面覆盖区的关系）
- 多级物流网络结构图

**实现指导**：
- 可以用 PPT/Inkscape/excalidraw 手绘
- 如需代码生成：matplotlib 的 `Circle`/`Arc`/`annotate`
- 标注关键尺寸和角度（直接标在图上）

### 3. 数据图例混合（Data-Legend Hybrid）

**特征**：
- 主图为 XY 曲线/散点图（定量数据）
- 嵌入小的示意图/图例解释变量含义
- 适合：机制解释——"为什么曲线长这样"

**示例场景**：
- 覆盖半角 vs 高度曲线，旁边嵌入卫星几何示意图标注 θ、α、h 的含义
- 种群数量时间序列，旁边嵌入捕食者-猎物关系简图

**实现指导**：
- matplotlib 的 `inset_axes()` 或 `fig.add_axes()`
- 嵌入的小图可以是简化的几何示意图
- 小图与大图的数据流要有标注关联

### 4. 非对称混合（Asymmetric Mixed）

**特征**：
- 主图大、辅图小，大小不一
- 每个子图传达不同维度的信息
- 适合：多维度综合展示（如一张图展示模型结构的3个方面）

**示例场景**：
- 论文的 "Our Work" 或建模总览图：大图展示建模流程，小图展示关键中间结果
- 问题一的模型框架 + 验证结果放在同一面板

**实现指导**：
- matplotlib 的 `GridSpec` 或 `subplot2grid`
- 确保主图（最大面积）传达最重要的结论

## Claim-Figure 覆盖检查清单

### 检查步骤

1. **提取 Claim 列表**：从阶段2（模型设计）和阶段4（检验方案）提取论文需要论证的所有结论。分为两类：

   - **模型 Claim**（来自阶段2）：每个模型的核心结论——"为什么选这个模型""这个模型的数学关系是什么""结果是多少"
   - **检验 Claim**（来自阶段4）：每项关键检验的结论——"灵敏度如何""退化是否合理""两种方法是否一致""自洽性是否满足"

   格式：
   ```markdown
   ## 模型 Claim（阶段2）
   ### 问题一
   - MC1.1: 单星覆盖半角 θ 随轨道高度 h 单调递增，增速递减
   - MC1.2: 满足题给覆盖要求的最小轨道高度约为 506 km
   - MC1.3: 406-506km 范围内满足约束，最佳高度为 X km
   
   ### 问题二
   - MC2.1: 12面Walker星座可实现无缝覆盖
   - MC2.2: 每面需要至少 30 颗卫星 → 总卫星数 360
   
   ## 检验 Claim（阶段4）
   - VC1: h灵敏度：h±20%→N_min变化<15%
   - VC2: 极端退化：α→0时θ→0，符合几何常识
   - VC3: GA与Grid Search结果一致（偏差<5%）
   - VC4: Q2_N ≥ Q1_Nmin（自洽性）
   ```

2. **Claim→Figure 映射**：每个 Claim 是否有一张或多张图支撑？

   ```markdown
   ### 模型Claim覆盖
   | Claim | 支撑图表 | 覆盖状态 |
   |-------|---------|:------:|
   | MC1.1: θ vs h 单调递增 | Fig.2: θ-h曲线 | ✅ |
   | MC1.2: 最小轨道高度506km | Fig.2 + Fig.3: 覆盖判断阈值 | ✅ |
   | MC1.3: 最佳高度 | Fig.4: 多目标权衡曲线 | ✅ |
   | MC2.1: 无缝覆盖 | Fig.5: 覆盖热力图 | ✅ |
   | MC2.2: 每面30颗 | Fig.6: N vs 覆盖率曲线 | ✅ |

   ### 检验Claim覆盖
   | Claim | 支撑图表 | 覆盖状态 |
   |-------|---------|:------:|
   | VC1: h灵敏度<15% | Fig.7: 灵敏度曲线 | ✅ |
   | VC2: 极端退化合理 | Fig.8: 退化验证 | ✅ |
   | VC3: GA≈Grid | Fig.9: 方法对比 | ✅ |
   | VC4: 自洽性 | — | ⚠️ 用文字+表格 |
   ```

3. **反向检查**：是否有图表不支撑任何 Claim？

   ```markdown
   | 图表 | 支撑的Claim | 是否冗余 |
   |------|-----------|:------:|
   | Fig.1: 覆盖几何示意 | MC1.1, MC1.2（辅助理解） | ✅ 有用 |
   | Fig.10: 某中间变量分布 | — | ⚠️ 可删除或合并 |
   ```

   > 检验相关的图表尤其要检查：灵敏度分析通常需要多子图的定量网格，对比验证需要并排图——这些图天然占用大量篇幅。只保留能支撑检验结论的图。

4. **处理未覆盖的 Claim**：
   - 可以为它新增一张图 → 补充 Figure Contract
   - 可以用文字论证替代（标注"无需图"）→ 必须说明理由
   - 可以合并到已有图表中 → 修改已有图的 Contract

### 检查结果格式

```markdown
## Claim-Figure 覆盖检查结果

- 总 Claim 数：X
- 有图支撑：Y
- 无图但可用文字：Z
- 未覆盖（需补充）：W

### 需补充的图表
[列出所有未覆盖的Claim及建议的图表]
```

## 图表生成优先级与执行顺序

在阶段6编码时，按以下顺序实现图表：

1. **必须+模型结论类**：直接支撑阶段2模型核心结论的图表（如关键公式的曲线、结果热力图）
2. **必须+检验结论类**：支撑阶段4关键检验的图表（灵敏度曲线、退化验证、自洽性示意）
3. **必须+辅助理解类**：帮助读者理解模型的示意图（几何关系、系统架构）
4. **推荐级**：增强论文说服力但不是必须的图表
5. **可选级**：锦上添花，时间充裕时添加

每个阶段5规划的图表，都应在阶段6的代码中有对应的生成函数。阶段7执行时，用代码生成全部已规划的图表到 `图表/` 文件夹。
