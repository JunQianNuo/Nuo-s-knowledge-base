# 模型检验方案设计

## 概述

模型检验（阶段5）在算法设计（阶段4）之后、代码实现（阶段6）之前进行。

**核心原则**：检验不是跑完代码后的附加题，而是建模的一部分——它定义了"什么结果算通过"。先定义通过标准，再写代码去实现。

本文档定义：
1. 检验类型速查表
2. 逐子问题检验设计模板
3. 跨问题自洽性检查
4. 检验执行计划与通过标准

---

## 一、检验类型速查表

| 类型 | 目的 | 适用场景 | 典型方法 |
|------|------|---------|---------|
| **灵敏度分析** | 参数变化→输出变化幅度 | 所有模型 | 参数±10%/±20%，观察输出变化率；绘制龙卷风图 |
| **极端退化** | 参数极限→是否退化合理 | 机理/几何模型 | 参数→0或→∞，检查退化行为是否符合物理直觉 |
| **误差分析** | 数值解 vs 解析解/真实值 | 近似模型、数值方法 | 与解析解对比（如有）、网格细化收敛测试 |
| **对比验证** | 不同方法→结果是否一致 | 有替代方法可对比时 | 用另一个算法解同一问题，比较结果 |
| **假设验证** | 关键假设放松→结论是否成立 | 每个关键假设 | 逐个放松假设，观察结论是否稳健 |
| **自洽性** | 前序约束在后序中是否满足 | 多问题递进 | 检查问题二取值是否≥问题一下界等 |
| **Monte Carlo** | 随机扰动→结果分布 | 含随机性的模型 | 多次运行，统计结果分布（均值/方差/置信区间） |
| **交叉验证** | 训练集/测试集→泛化能力 | ML/统计模型 | k-fold CV、留一法、时间序列前向验证 |

### 每种检验类型的详细说明

#### 灵敏度分析

**目的**：识别哪些参数对结果影响最大。

**标准做法**：
1. 选定 3-5 个关键参数
2. 每个参数在基准值附近取 ±10%、±20%（或更宽范围）
3. 每次只变一个参数（OAT, One-At-a-Time）
4. 记录输出变化，绘制灵敏度图（龙卷风图或蜘蛛图）

**判定标准**：
- 输出变化 < 5% → 模型对该参数不敏感 ✅
- 输出变化 5-20% → 有一定敏感性 ⚠️，论文中应讨论
- 输出变化 > 20% → 高度敏感 ❌，可能需要更精确的参数取值或稳健优化

#### 极端退化

**目的**：验证模型在极限情况下是否退化到合理的特例。

**标准做法**：
1. 识别 2-3 个可推至极限的参数
2. 代入极限值，观察模型输出
3. 检查退化结果是否符合已知的特殊情况（如同类问题的解析解、物理常识）

**判定标准**：
- 退化结果合理 → ✅
- 退化结果不合理 → ❌ 模型公式可能有误，需回到阶段3修正
- 无法判断退化结果是否合理 → ⚠️ 标注"缺乏可验证的极限情形"

**至少 2 种极端情形。**

#### 自洽性检查

**目的**：多问题递进时，前序问题的约束在后序中不能违反。

**标准做法**：
1. 提取阶段1中子问题数据流中的约束关系
2. 将前序输出与后序输入进行数值对比
3. 检查是否出现"N_min=40 但最终方案 N=14"这类矛盾

**判定标准**：
- 数值一致 → ✅
- 数值矛盾但可解释（如后序引入新信息放宽了约束）→ ⚠️ 必须提供解释
- 数值矛盾且无法解释 → ❌ **必须回退修正**

## 二、逐子问题检验设计模板

### 完整模板

```markdown
# 模型检验方案

## 一、逐子问题检验设计

### 问题{X}检验

**建模概述**：[一句话：用什么模型解什么问题]

**关键参数**：[列出该模型中的关键参数及其基准值]

| 编号 | 检验类型 | 检验什么 | 方法/参数 | 预期结果 | 不合格处理 |
|------|---------|---------|----------|---------|-----------|
| V{X}.1 | 灵敏度 | 参数A→输出O | A基准A₀，测试A₀×0.8, 0.9, 1.1, 1.2 | 输出O变化 < 15% | 标注A为敏感参数，论文讨论；若变化>50%则考虑稳健优化 |
| V{X}.2 | 灵敏度 | 参数B→输出O | [同上格式] | [预期] | [处理] |
| V{X}.3 | 极端退化 | [极限场景1] | 代入极限参数P→0 | O→[退化值]（[退化含义]） | 公式有误→回到阶段3重推公式 |
| V{X}.4 | 极端退化 | [极限场景2] | 代入极限参数Q→∞ | O→[退化值]（[退化含义]） | 同上 |
| V{X}.5 | 误差分析 | 数值解 vs 解析解 | [什么情况下有解析解] | 相对误差 < 1% | 加密网格/减小步长 |
| V{X}.6 | 对比验证 | 方法A vs 方法B | [方法B的具体实现方式] | 结果差异 < 5% | 分析差异来源：方法假设不同？或代码bug？ |
| V{X}.7 | 假设验证 | [假设H1]放松 | [如何放松假设] | 结论是否仍成立 | 论文中讨论假设的可靠性 |
| V{X}.8 | Monte Carlo | 输入扰动→输出分布 | [参数] 加 ±5% 随机噪声，重复1000次 | 输出均值≈基准值，CV<10% | 若CV过大，检查是否对输入过于敏感 |

### 问题{Y}检验
[同上格式]
```

### 编写规则

1. **每项检验必须有"不合格处理"**——否则检验就只是走形式
2. **灵敏度分析必须指明具体参数和具体范围**——"灵敏度分析"不够，"对轨道高度 h 做灵敏度分析：h ±10%, ±20%，观察 N_min 变化"才够
3. **"不合格处理"必须可执行**——"回退修改"不是处理方案，"回到阶段3检查公式(3)中的 θ 推导"才是
4. **至少包含**：2项灵敏度 + 2项极端退化 + 1项对比验证（如有替代方法）
5. **Monte Carlo** 适用于含随机性或数值积分的模型

## 三、跨问题自洽性检查

```markdown
## 二、跨问题自洽性检查

| 编号 | 检查什么 | 前序约束 | 后序取值 | 判定 | 不满足时的处理 |
|------|---------|---------|---------|:--:|--------------|
| C1 | 问题二的N是否≥问题一的N_min | Q1每面: N_min ≈ X | Q2每面: N = Y | Y≥X? | 若N<X：多面协同是否降低了单面要求？如是，解释机制；如否，Q1结果可能偏大 |
| C2 | 问题三的总星数S是否=问题二的M×N | Q2: M面×N颗 = S₂ | Q3: S₃ | S₃≈S₂? | 若不等：Q3对星座做了优化调整？说明优化了什么 |
| C3 | [其他跨问题约束] | | | | |
```

### 自洽性判定的层级

```
数值完全一致 → ✅
数值不一致但可合理解释 → ⚠️（需提供解释，在论文中讨论）
数值不一致且无法解释 → ❌（必须回退修正模型或数据流）
```

## 四、检验执行计划

```markdown
## 三、检验执行计划

| 检验编号 | 代码函数 | 输入 | 预计耗时 | 可自动化 |
|----------|---------|------|:------:|:------:|
| V1.1 | `sensitivity_h()` | `h_vals = [0.8, 0.9, 1.0, 1.1, 1.2] × h₀` | <1 min | ✅ |
| V1.2 | `sensitivity_alpha()` | `alpha_vals = [0.8, 0.9, 1.0, 1.1, 1.2] × α₀` | <1 min | ✅ |
| V1.3 | `extreme_degen_h0()` | `h → 0` | <1 min | ✅ |
| V2.1 | `compare_ga_vs_grid()` | GA参数=[...], Grid范围=[...] | ~30 min | ⚠️ 需等待 |
| C1 | `check_q1_q2_consistency()` | Q1结果, Q2结果 | <1 min | ✅ |
```

### 计划规则

- **预计耗时必须诚实**：网格搜索可能需要数小时，标注清楚
- **可自动化 = ⚠️ 需等待**：说明代码跑得慢但不需要人工干预
- **可自动化 = ❌**：需要人工判断的检验，说明判断标准

## 检验方案编写规则

1. **先写"不合格处理"再写"预期结果"**——思考路径："如果检验失败，我能做什么？"如果回答不了这个问题，说明检验方案不够具体
2. **灵敏度分析不要只测 ±10%**——有些参数的关键区间可能在 ±50% 范围外
3. **避免冗余检验**：两个灵敏度的组合（如同时变两个参数）通常不如分别做 OAT 灵敏度的信息量大
4. **自洽性是跨阶段的**——这是最容易遗漏的检验类型，也是审稿人最容易发现的漏洞
5. **检验方案的粒度**：一个检验编号 = 一个具体可执行的操作，不是一个研究方向

## 与阶段6（代码实现）的关系

阶段5的检验方案直接决定阶段6的代码结构：
- 每个 `V{X}.N` 对应阶段6代码中的一个函数
- 检验执行计划中的"代码函数"列就是阶段6要实现的函数名
- 函数名使用具体描述（如 `sensitivity_h()`）而非泛称（如 `check1()`）

## 与阶段7（结果分析）的关系

阶段7严格按照阶段5的检验方案执行：
- 逐项运行检验函数
- 对比实际结果与预期结果
- 按"不合格处理"方案处理异常
- 生成检验执行记录

## 六、分类型最低检验集合

每个核心结论至少选择两类互补检验；风险高或结论关键时至少三类。下表是最低要求，不替代题目特有检验。

| 模型类型 | 最低检验集合 |
|---|---|
| 回归与预测 | 留出或时序验证、残差与假设检查、基准模型对比 |
| 分类 | 分层/按组验证、混淆矩阵、关键类别精确率/召回率/F1；不得只看总体准确率 |
| 聚类与分组 | 内部指标、扰动稳定性、类别数敏感性和现实解释 |
| 优化 | 可行性、基准方案对比、参数或情景敏感性；使用求解器时补充状态与 gap |
| 机理与数值模型 | 量纲、题给基准值、极端退化、步长/网格收敛和参数敏感性 |
| 评价与排序 | 权重敏感性、排序稳定性、替代赋权或评价方法互证 |

### 不确定性表达

涉及估计、预测或随机算法时，优先报告置信区间、预测区间、重复运行分布、误差带或情景范围，而不是只给点值。若无法量化，应说明数据与假设限制。
