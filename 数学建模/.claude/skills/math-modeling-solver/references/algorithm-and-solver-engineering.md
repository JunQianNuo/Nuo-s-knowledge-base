# 算法设计与条件化求解工程

## 目的

让每种算法采用与自身机制相匹配的实现和验收标准。流程为：

> **通用算法契约 → 算法专项检查 → 求解器专项检查（仅适用时）**

没有使用数学规划求解器时，不执行求解器专项检查；对应字段写明“不适用”及理由，不得虚构求解状态或最优间隙。

## 一、通用算法契约

所有算法在实现前填写：

| 项目 | 内容 |
|---|---|
| 输入 | 名称、类型、维度、单位、有效范围 |
| 输出 | 数值、状态、误差/区间及现实含义 |
| 初始化 | 初值、初始解、随机初始化；不需要时标明不适用 |
| 参数 | 范围、来源、默认值及调节依据 |
| 停止条件 | 容差、迭代、时间或确定性终止条件 |
| 计算预算 | 数据规模、时间、内存和可用算力 |
| 随机性 | 随机种子、重复次数和汇总方式 |
| 状态 | 成功、未收敛、超时、数值异常等 |
| 产物 | 中间结果、日志、参数配置、图表数据和最终输出 |
| 失败路径 | 失败时调参数、换算法还是回退模型 |

## 二、算法专项检查

| 算法类型 | 必做检查 | 不应误用的指标 |
|---|---|---|
| 闭式公式与直接计算 | 量纲、数量级、极端情形、题给基准值、数值精度 | 求解器状态、gap |
| 回归与统计模型 | 独立性/分布/方差假设、残差、参数区间、独立验证、多重检验 | 只给拟合优度 |
| 机器学习 | 数据划分、数据泄漏、过拟合、关键指标、随机种子、校准 | 只报训练集表现 |
| GA、PSO、模拟退火等随机优化 | 初始化、超参数、收敛曲线、多次独立运行、基准对比 | 虚构全局最优或最优间隙 |
| 蒙特卡洛 | 抽样机制、样本量、随机种子、收敛误差、方差控制 | 单次随机结果 |
| ODE/PDE 与数值计算 | 步长、容差、稳定性、网格/步长收敛、守恒检查 | 只因程序完成就判定正确 |
| 聚类 | 类别数依据、内部指标、扰动稳定性、现实解释 | 只展示漂亮分组 |
| 自编精确/组合算法 | 小规模正确性基准、复杂度、边界样例、证明或可验证下界 | 未证明的“最优” |

### 随机优化报告

报告多次独立运行的最优值、均值、标准差或区间、成功率与收敛曲线，并与常识基线、数学基准模型或可验证下界比较。

### 数值计算报告

至少做两档步长或网格比较；若结果未随精度提高而稳定，不能进入论文结论。

## 三、求解器专项检查

仅在实际调用线性、整数、混合整数、二次或非线性数学规划求解器时执行。

### 建模对应

- 决策变量必须对应现实动作；
- 目标函数必须对应真实价值；
- 约束必须记录题面、领域规则或建模假设来源；
- 精确求解、启发式算法或混合策略的选择必须说明依据。

### 求解状态

必须区分：最优、可行但未证明最优、不可行、无界、超时和数值异常。程序未报错不等于求解成功。

### 最优间隙

超时或大规模问题保存：

- `incumbent`：当前最佳可行解目标值；
- `bound`：可证明的最优界；
- `gap`：当前解距离理论最优的相对或绝对差距；
- 运行时间、节点数及主要求解参数。

### 不可行诊断

按顺序执行：

1. 检查变量上下界、单位和索引；
2. 提取冲突约束或不可约冲突集；
3. 求最小松弛，量化恢复可行所需调整；
4. 按业务模块逐组关闭约束定位矛盾；
5. 与领域成员确认修改依据，不得只为得到结果随意删除约束。

### 无界与数值异常

- 无界：检查是否遗漏容量、守恒、逻辑或边界约束；
- 数值异常：检查系数量级、过大的 Big-M、病态矩阵和容差；
- 适用时读取松弛量、影子价格；不适用时用参数扫描做灵敏度分析。

### 预测—决策

预测模型与优化模型分别报告质量；通过情景、区间或稳健优化分析预测误差如何改变最终决策。

## 四、完成门禁

- 通用算法契约完整；
- 已选择且执行正确的算法专项检查；
- 只有实际使用求解器时才报告状态、bound 和 gap；
- 失败路径、日志和中间结果可用于复现；
- 结果能够翻译为现实方案，而非停留在变量取值。
