# 数据审计与基准模型

## 目的

在推荐模型前完成数据结构识别，在升级模型前建立可解释基准。结论不足时输出待确认项，不得把猜测写成已验证事实。

## 一、数据结构指纹

逐项填写：

| 维度 | 检查问题 | 证据 | 对模型的影响 |
|---|---|---|---|
| 观测单位 | 每行、每个样本、节点或时间点代表什么？ | 题面/数据字典 | 决定独立性与索引 |
| 观测关系 | 是否存在分组、嵌套、重复测量或个体差异？ | ID与采样说明 | 可能需要层次/混合模型 |
| 顺序依赖 | 是否具有时间、空间或网络关系？ | 时间戳/坐标/边表 | 禁止随意打乱验证 |
| 采样机制 | 是否随机采样，是否存在截尾、选择偏差或测量误差？ | 采样说明 | 决定可推广范围 |
| 数据质量 | 缺失值、异常值、重复和无效记录如何定义？ | 规则与统计图 | 决定清洗策略 |
| 类别分布 | 是否类别不平衡，关键少数类的错误代价是什么？ | 频数与背景 | 决定指标和抽样方式 |
| 单位量纲 | 单位、量纲、正负方向和数量级是否一致？ | 变量说明 | 防止公式与结果错误 |
| 数据泄漏 | 特征、预处理或划分是否使用未来信息、标签或测试数据？ | 数据管线 | 决定验证是否有效 |

### 时间数据硬规则

- 按时间验证或滚动验证，不能用普通随机划分破坏时间顺序。
- 归一化、缺失填补和特征构造只在训练数据上拟合，再应用到验证数据。

### 数据处理证据

每项清洗记录：处理对象、判定规则、领域或统计依据、影响样本数、处理前后图、对结论的影响。不能因为点“不好看”就删除。

## 三、模型阶梯

每个子问题按下列顺序比较：

1. **常识基线**：均值、简单规则、数量级估算、领域上下界或现行方案。
2. **数学基准模型**：参数少、可解释、可快速运行的第一个完整方案。
3. **升级模型**：只针对基准模型已经暴露的不足增加机制或复杂度。
4. **替代路线**：采用不同原理，用于互证或失败回退。

### 升级证据表

| 项目 | 必须说明 |
|---|---|
| 基准不足 | 哪个残差、指标、数据结构或现实机制表明不足？ |
| 升级内容 | 新增哪些变量、参数、机制或算法？ |
| 新增假设 | 假设依据及适用边界是什么？ |
| 预期收益 | 哪个指标、稳定性或现实解释应改善？ |
| 复杂度代价 | 参数、计算、调试与解释成本增加多少？ |
| 回退条件 | 改善不显著或不稳定时回到哪一方案？ |

## 四、阶段门禁

进入算法设计前必须满足：

- 数据结构指纹已完成，或明确列出暂时无法核验的字段；
- 数据处理规则有依据并规划处理前后对比；
- 已建立常识基线和数学基准模型；
- 复杂模型存在可核查的升级证据；
- 模型适用条件与数据结构一致；
- 无依据的参数、阈值和权重标为待验证。
