# 数学建模竞赛解题指导

> 本 skill 提供的矩阵、cookbook、playbook、代码模板，全部是**知识参考**而非**决策指令**。
> 对于同一道赛题，不同队伍理应有不同的建模路径。矩阵里的推荐只是技术起点——
> 你的任务是结合题目具体约束、数据特征和团队判断，做出**有理由的选择**，而非照搬推荐。

## 工作模式路由

在判断阶段前先选择工作模式，避免所有请求都机械执行完整流程。

| 模式 | 触发 | 执行方式 |
|---|---|---|
| **全流程模式** | 完整赛题、从零分析或要求完整方案 | 执行阶段0—8并应用全部质量门禁 |
| **局部协助模式** | 只问公式、模型、代码、图表或某项检验 | 直接进入相关阶段，执行最小必要检查，**不强制创建完整目录** |
| **方案审查模式** | 已有模型、代码、结果或论文片段 | 按数据、假设、模型必要性、实现一致性、检验和复现审查，不无理由推翻已有方案 |

全流程模式加载 `references/competition-execution.md`，维护团队里程碑、变量、参数和约束字典、运行与复现清单及 AI 核验记录。局部信息不足时明确适用边界，不把局部回答包装成完整赛题结论。

## 完整流程

```
阶段0: 环境初始化
  ├─ 建立文件夹结构
  ├─ 创建空术语表格
  └─ 识别比赛类型、用户语言偏好

阶段1: 逐题分析（← 每道题独立，逐题等待确认）
  ├─ 问题一分析 → 输出md → 反问检验理解 → 更新术语表
  ├─ 问题二分析 → 同上
  ├─ 问题三分析 → 同上
  └─ 问题四分析 → 同上
      └─ 全部完成后：整体常识校验 + 子问题关系图

阶段1.5a: 文献检索
  ├─ 基于阶段1关键词搜索（5次上限）
  ├─ 输出文献清单（含下载链接）
  └─ 等待用户下载并转换为MD

阶段1.5b: 文献精读
  ├─ 读取所有论文MD
  ├─ 提取：背景/模型/适用条件/算法/结论
  └─ 输出文献结果报告（供给建模指导）

阶段2: 模型设计
  ├─ 逐题给出候选模型（必须有文献依据，标注具体论文）
  ├─ 适用条件审查（不符合→告知，问是否补论文）
  ├─ 局限性/科学性声明
  └─ 等待确认后进入算法设计

阶段3: 算法设计与条件化求解工程
  ├─ 基于cookbook + 文献算法
  ├─ 通用算法契约 → 算法专项检查
  ├─ 使用数学规划求解器时再执行求解器专项检查
  ├─ WebSearch预期输出范围
  └─ 等待确认后进入检验方案设计

阶段4: 模型检验方案设计（🆕）
  ├─ 逐子问题设计检验方案（灵敏度/误差/假设验证/对比实验）
  ├─ 每项检验：检验什么→用什么方法→预期什么结果→不合格怎么处理
  ├─ 检验方案必须可执行（有具体参数、有代码路径）
  └─ 等待确认后进入图表规划

阶段5: 图表规划（🆕）
  ├─ 基于已确定的模型+算法+检验方案，逐问题列出需要哪些图
  ├─ Figure Contract（每张图：核心结论 + 数据来源函数 + 原型分类）
  ├─ 检验结果可视化：灵敏度曲线、对比验证图、自洽性示意
  ├─ Claim-Figure 覆盖检查（覆盖模型核心结论 + 检验结论）
  └─ 等待确认后进入实现

阶段6: 算法实现
  ├─ 强制先查cookbook和代码模板
  ├─ 基于模板改写（变量名→题中符号，注释→题中语义）
  ├─ Step 3.5 公式自我验证（保留）
  └─ 代码写完不直接交，进入结果分析

阶段7: 结果分析（🆕）
  ├─ 运行代码产出数值结果 + 生成阶段5规划的全部图表
  ├─ 执行阶段4设计的全部检验方案
  ├─ 与预期范围对比
  ├─ 不符合→展开讨论（原因分析，不自行合理化）
  └─ 符合→生成结果分析报告 + 检验报告

阶段8: 论文衔接
  ├─ 整合全部阶段产出 + 图表 + 检验结果
  ├─ 输出论文草稿片段
  └─ [PAPER_READY] 信号
```

## Step 0: 判断用户入口

先确定工作模式，再判断用户在哪个阶段切入：

- **有新题目文本，从零开始** → 阶段0
- **已有问题分析结果，需要模型推荐** → 阶段2
- **需要先查文献再看选什么模型** → 阶段1.5a
- **已确定模型，需要算法展开和代码** → 阶段3
- **建模已完成，需要衔接论文** → 阶段8
- **用户直接指定了模型名**（如"用 GA 求解"）→ 阶段3，跳过阶段0-2
- **用户输入匹配已知题型** → 加载对应 Playbook 获取完整解题示范（12 本 Playbook 覆盖国赛 A/B/C + 美赛 D/E/F 全部题型）

### 阶段识别规则

| 用户说 | 切入阶段 |
|--------|---------|
| "这道题怎么做" + 粘贴题目 | 阶段0 |
| "帮我分析这道题" | 阶段0 |
| "帮我搜一下类似问题的文献" | 阶段1.5a |
| "有没有类似题目的论文可以参考" | 阶段1.5a |
| "选什么模型好" | 阶段2 |
| "XGBoost 和随机森林怎么选" | 阶段2 |
| "帮我写 GA 代码" | 阶段3 |
| "这个公式怎么推导" | 阶段3 |
| "帮我设计检验方案" | 阶段4 |
| "帮我规划论文图表" | 阶段5 |
| "建模做完了，准备写论文" | 阶段8 |
| "帮我写摘要" | 阶段8 → 引导切换 paper skill |

局部协助模式允许跳过无关阶段，但不能跳过与当前结论直接相关的数据结构、基准方案和核心验证检查。

### 阶段1：逐题分析

**原则**：
- 每次只分析一道子问题，输出一个独立 md 文件
- 此阶段**禁止推荐模型**，只做输入/输出/约束/本质判定
- 每完成一题，反问用户确认理解；用户确认后才进入下一题

**自动加载**：`references/problem-decomposition.md` + `references/data-audit-and-baseline.md`

**每道题的输出模板**：

```markdown
# 问题{X}分析

## 1. 题目原文提炼
[用自己的话重述该问题的要求，1-2段]

## 2. 数学本质判定
- 类型：[从12种中选，可混合]
- 判定理由：[为什么是这个类型，引用题目具体表述]

## 3. 输入/输出/约束
| 维度 | 内容 |
|------|------|
| 已知输入 | [题目给定的参数、数据] |
| 待求输出 | [需要得到什么，精度要求] |
| 硬约束 | [不可违反的条件] |
| 软约束 | [尽量满足的条件] |

## 4. 与前一问题的关系
[仅问题二/三/四填写：问题X的输出如何作为本问题的输入/约束]

## 5. 常识校验
- 数量级估算：[用最简近似心算结果大致范围]
- 与题给基准值对比：[如有]

## 6. 文献检索关键词
- 中文：[2-4组]
- 英文：[2-4组]
```

若题目提供数据，完成逐题本质判定后还必须输出 `问题分析/数据审计报告.md`，至少检查观测单位、独立性、重复测量或层次、时间/空间顺序、截尾、类别不平衡、缺失与异常、单位量纲及数据泄漏。时间数据采用按时间验证，不得随机划分导致未来信息泄漏；类别不平衡时不得只报告总体准确率，必须关注关键类别及其错误代价。

**完成后动作**：
1. 输出问题分析 md 并展示
2. 更新术语表格（新增本问题涉及的核心概念和符号）
3. 反问：提出 **2-4 个具体问题**来检验理解

### 🚨 反问质量铁律（提问前逐条自检，任一不合格→重写）

| # | 铁律 | 违规示例 | 为什么不行 |
|---|------|---------|-----------|
| 1 | **禁止问分析中已明确回答的内容** | "输入变量有哪些？""输出是什么？" | 分析里已经写了，用户不需要回答你就能在分析里找到答案——这是阅读理解题，不是理解检验 |
| 2 | **禁止问"你是否理解/同意/确认"** | "你是否同意上述分析？""请确认你的理解" | 用户只能说"是"——这不是问题，是形式主义。检验不出任何东西 |
| 3 | **禁止问用户无法独立判断的问题** | "你觉得用几何方法还是数值方法更合适？" | 阶段1不讨论模型选择。用户没有足够信息做此判断，答了也是猜 |
| 4 | **必须有两种以上合理的不同回答** | — | 如果 90% 的人会给出相同答案，这个问题没有检验价值。**只有能答错的问题才是好问题** |
| 5 | **必须具体到数值或场景，不能笼统** | "问题一的输出如何影响问题二？" | 太笼统 → 用户答"作为输入"也算对。改为："问题一的 θ=4.36° 在问题二中作为什么参数使用？如果 θ 变成了 5.0°（加了 15%），问题二的 N 大概会怎样变化？" |
| 6 | **禁止超过 4 个问题** | 连问 6-7 个 | 问题越多越像考试，用户疲劳后随便答。2-4 个高质量问题 > 6 个敷衍问题 |

### 提问前自检流程

```
在呈现问题给用户之前，对每个问题逐一检查：
1. 这个问题在我刚才的分析中是否已经明确回答过？ → 是 → 删除
2. 用户是否只能说"是/对/同意"？ → 是 → 删除
3. 是否只有一种合理的回答？ → 是 → 删除
4. 是否具体到数值/场景/具体参数？ → 否 → 重写
5. 保留的问题是否 ≥2 且 ≤4？ → 否 → 调整
```

### 问题类型（每道题从以下类型中选 2-3 种，不要全部同一类型）

| 类型 | 适用条件 | 目的 |
|------|---------|------|
| **歧义消解型** | 题目表述有歧义，两种理解导致不同结论 | 暴露隐藏的理解分歧 |
| **隐含假设型** | 分析中做了假设但未明确说"我做了一个假设" | 让用户意识到建模依赖的假设 |
| **数据流连锁型** | 本问题的输出是后续问题的输入 | 测试用户是否理解问题间的量化依赖 |
| **边界条件型** | 题目给的约束在极端情况下可能失效 | 测试用户是否考虑过边界情况 |

**输出格式**：

```markdown
## 检验理解的提问

> 请回答以下问题，确认我们对问题{X}的理解一致。每个问题的正确答案不止一种——目的是暴露我们各自隐含的假设。

1. [类型：歧义消解/隐含假设/数据流连锁/边界条件]
   [具体问题，含具体参数/数值/场景]
   
2. [类型]
   [具体问题]

3. [类型]
   [具体问题]
```

4. 等待用户回答后，确认或修正理解，然后进入下一题分析

**全部完成后**：
- 做一次整体常识校验（跨问题数量级是否矛盾）
- 输出子问题关系图（文字或 mermaid 流程）
- 更新完整术语表

**完成后**：进入阶段1.5a。

### 阶段1.5a：文献检索

**目标**：搜集论文——仅此而已。知道「有哪些论文」和「它们用了什么方法」，**不做任何模型推荐**。

**🚨 硬性上限（防止无限搜索，必须遵守）**：
- **最多执行 5 次 WebSearch 调用**（不是每个检索式都搜，是总共 5 次）
- **找到 5-8 篇高度相关论文后立即停止**，不需要穷尽所有检索式
- **T2/T3 回退仅在用户明确要求时执行**，不要自动级联回退
- **如果前 3 次搜索已经找到满意结果，直接跳到步骤 4 整理证据，不再继续搜**

**🚨 阶段边界铁律（本阶段禁止做的事）**：

| 禁止 | 违规示例 | 为什么 |
|------|---------|--------|
| **禁止推荐"哪个方法最适合本题"** | "SoC 用于 Q1-Q2、Dijkstra 用于 Q3" | 论文还没下载、还没精读，摘要不足以判断适用性。模型推荐是阶段2的工作 |
| **禁止写"建议优先下载 X X X"** | "建议优先下载文献#1-4和#6" | 你还没读论文内容，不知道哪篇最有价值。全部下载，精读后再判断 |
| **禁止按子问题归类"该用什么方法"** | "Q1 覆盖推导 → SoC法" | 这是模型设计结论，不是检索结果。检索结果只能说"文献#3用了SoC法解覆盖问题" |

**自动加载**：`../math-modeling-paper/references/literature-review.md`（跨 skill 读取，仅加载第一部分「文献检索」，不展开全文）

**步骤**：

1. 从阶段1已生成的检索关键词中，**只挑最核心的 2-3 组**（不是全部），中英文各至少 1 组
2. **告知用户**：简要列出建议的检索式，说明信源分级
3. **询问用户**：「是否需要我代为搜索？预计 3-5 次搜索即可覆盖核心文献（中英文各半）。如你已自行检索过，可以直接告诉我找到的文献，我们跳过这步。」
   - 用户同意 → 执行搜索
   - 用户拒绝或已有文献 → 跳过搜索，直接请用户提供找到的文献
4. **执行搜索（遵守硬性上限）**：
   - **中英文分配**：5 次搜索中，英文 2-3 次 + 中文 2-3 次
   - **中文期刊识别**：优先采信标注为「核心期刊」「EI 收录」「SCI 收录」「CSSCI」「CSCD」的中文论文
   - 每次搜索后检查：是否已找到 5+ 篇相关论文？是→停止搜索
   - 是否已用满 5 次 WebSearch？是→停止搜索
   - 从检索结果中提取：类似问题用了哪些方法？各方法效果对比？是否有公认基准方法？
   - **标注期刊含金量**：英文优先 SCI Q1/Q2，中文优先一级学报/核心期刊
5. **输出文献清单**（含下载链接）：

```markdown
## 文献检索结果

### 检索策略
| 轮次 | 检索式 | 信源 | 命中数 | 相关数 |
|------|--------|------|--------|--------|
| | | | | |

### 检索到的论文

| # | 论文标题 | 作者/年份 | 期刊/级别 | 用了什么方法 | 与本赛题的关联 |
|---|---------|----------|----------|------------|-------------|
| 1 | | | | | |
| 2 | | | | | |

> ⚠️ "与本赛题的关联"列只描述客观事实（如"该论文解的是卫星覆盖连续性问题"），**不做推荐判断**（如"此方法最适合Q1""建议用于问题二"）。模型推荐是阶段2的工作。

### 📥 下载链接汇总

| 序号 | 论文标题 | DOI | 下载方式 |
|------|---------|-----|---------|
| 1 | [标题] | 10.xxxx | `paper-fetch <DOI> --out 参考文献/` |
| 2 | [标题] | 10.xxxx | 同上 |
```

**完成后**：告知用户"请下载上述论文并转换为MD格式放入 `参考文献/MD/`，完成后告诉我继续。" **不写"建议优先下载"，不指定哪篇最重要。**

**目标**：在写代码之前，先规划好如何检验模型。检验不是跑完代码后的附加题，而是建模的一部分——它定义了"什么结果算通过"。

**触发**：阶段3算法设计确认后。

**原则**：

### 公式自我验证（必做）

**目的**：防止阶段1拆题不够深导致阶段6代码凭空编造。

**必须执行的三项检查**：

#### (a) 题给基准值交叉验证

将公式代入题目给定的数值，检查是否与题目中出现的参照值一致：

```
| 公式计算结果 | 题给参照值 | 偏差 | 判定 |
|-------------|-----------|------|------|
| [代入数值] | [题目中出现的参照值] | [偏差%] | ✅/⚠️ |
```

- 偏差 ≤5% → ✅ 通过
- 偏差 5%-15% → ⚠️ 标注差异，说明可能原因（如天线方向图边缘衰减、大气损耗等物理因素），可继续
- 偏差 >15% → ❌ **公式大概率有误，必须回到几何要素清单重新推导，不得自行合理化**

#### (b) 极端情形退化检验

令某个参数取极端值，检查公式是否退化到合理的物理结果：

```
| 极端情形 | 退化结果 | 是否合理 |
|---------|---------|---------|
| α→0（天线无张角） | θ→0（无覆盖） | ✅ |
| h→0（贴地卫星） | θ→0 | ✅ |
```

**每种机理/几何本质的子问题至少测试 2 种极端情形。**

#### (c) 文献公式对照

与阶段1.5检索到的文献中同类公式逐项对比：

```
| 本文符号 | 文献符号 | 本文公式 | 文献公式 | 是否一致 |
|---------|---------|---------|---------|---------|
| θ | γ (Luders 1961) | arcsin(...)-α | arcsin(...)-α | ✅ |
```

**验证通过标志**：在公式推导下方输出验证结果：

```
> ✅ 公式验证通过
> (a) θ≈4.38°，题给506km反推θ≈4.55°，偏差3.7%——在合理范围（天线方向图边缘衰减）
> (b) 极端退化：α→0时θ→0 ✅；h→∞时θ→arccos(R/(R+h))→π/2 ✅
> (c) 与 Luders(1961) Eq.(7) 一致 ✅
```

**如任一项为 ❌，禁止继续，必须先修正公式。**

## 阶段间规则

1. **每阶段必须停留**，等待用户确认后再进入下一阶段
2. **用户可跳过阶段**：如用户说"直接给我代码"，相当于跳到阶段3。阶段1.5（文献检索）建议执行但可跳过——如用户已自行检索、有明确模型偏好或时间紧迫，可直接进入阶段2
3. **用户可回退**：
   - 阶段2发现模型不满足适用条件 → 退回阶段1.5a补搜论文
   - 阶段3发现算法不可行 → 退回阶段2换模型
   - 阶段7结果有明显偏差 → 退回阶段2或3修改模型/算法
   - 阶段7检验不通过 → 退回阶段2或3
4. **Playbook 参考**：在阶段1末尾检查是否匹配已知题型模板。如匹配，加载对应 playbook **作为思路参考**——playbook 展示的是一种可行路径，不是唯一路径。你遇到的题目和 playbook 的例题一定不同：数据不同、约束不同、要求不同。playbook 的价值在于让你看到「这类题一般怎么想」，而不是「这道题应该照搬什么」。永远从你的题目出发，而不是从 playbook 出发
5. **语言偏好**：首次交互时确认用户偏好 Python 还是 MATLAB。物理/工程类（A题）默认 MATLAB，数据/ML 类（C题）默认 Python，优化类（B题）两者均可
6. **检验优先**：阶段4的检验方案定义了"什么结果算通过"。阶段7必须执行全部检验，不允许跳过。检验不通过必须回退修改，不允许带着偏差进论文
7. **图表服务检验**：阶段5的图表规划基于阶段2-4的完整方案，图表服务于模型结论和检验结果的可视化，不本末倒置
8. **条件化执行**：非求解器算法跳过求解器专项指标，执行本算法的收敛、稳定性或正确性检查；不适用项必须说明理由
9. **求解失败处理**：数学规划不可行时先诊断冲突约束与最小松弛；超时时报告当前可行解、`bound` 和 gap，不把超时等同于无解
10. **团队同步**：全流程模式维护唯一的变量、参数和约束字典；模型变化时同步更新数学表达、代码、结果与论文
11. **AI 核验**：AI 生成的公式、参数和文献必须回到题面、运行结果或权威来源回源核验；待验证内容不得进入最终结论
12. **时间紧迫**：可以压缩候选模型和文献数量，但不能跳过数据结构检查、基准方案和核心验证
