# 基于候选架次分解与分层优化的 海上人员直升机运输调度

## 摘要

针对海上人员直升机运输场景中人员拼载优化、航线路径规划、海上燃油补给及有限机队排班优化等核心难题，本文综合考虑五次海上停靠上限、单航段座位容量、飞行安全余油、人员运输时间窗、飞机与机场机型归属匹配、同机周转间隔等多重刚性约束，构建了“需求分批-可行架次生成-人员分配-飞机精准排班”四层分层优化模型。研究以总飞机飞行使用时间为第一优先级优化目标，在总耗时相同的前提下，依次最小化飞行架次、人员总在途时间、燃油消耗量，并最大化航班座位利用率，形成多目标层级优化体系。

针对单向出海人员运输优化的问题一，本文按起终点差异对1600名出海人员聚类分组，通过动态规划算法确定各组最优分批规模；结合机场、机型及海上设施停靠顺序的组合适配策略，采用带支配剪枝的燃油标号算法完成全航段燃油合规性校验。研究先通过近邻节约算法生成初始可行方案，再引入融合路线拆除、动态重分批、贪心插入、节点交换算子的自适应大邻域搜索（ALNS）算法迭代优化人员拼载与航线组合。最终优化结果为96个飞行架次，总飞机使用时间15458min，人员总在途时间118213min，总燃油消耗124350.10kg，座位利用率达 $48.0341\%$

针对兼具出海、返航及设施间穿梭的多类型人员运输问题二，为精准刻画单架次航班内人员动态上下机过程，本文定义人员专属上下机序号，依据航段占用情况实时核算动态载客容量，严格遵循海上设施“先下后上”的作业规则更新座位占用状态。采用有序取送自适应大邻域搜索（ALNS）算法，在每次人员运输组合重构后，同步迭代优化机场适配、机型选择、停靠顺序与燃油补给方案。该方案可高效完成4000名人员的运输任务，最终输出106个飞行架次，总飞机使用时间18886 min，人员总在途时间249922 min，总燃油消耗144928.00 kg，座位利用率大幅提升至84.6616%。

针对含临时紧急任务的机队排班优化问题三，本文提出时间窗优先的两阶段反馈排班算法。第一阶段针对3840名常规非临时人员，生成时间兼容的人员运输批次，完成24架直升机的精细化时刻排班；第二阶段在整体时间预算约束下，通过深度受限增广换位策略嵌入160名临时人员运输任务，并将航线优化缩减结果反向反馈至第一阶段，实现全流程迭代改进。最终方案共投入23架直升机、166个飞行架次，总作业耗时 $31209\mathrm{min}$ ，人员总在途时间 $253889\mathrm{min}$ ，总燃油消耗 $239683.10\mathrm{kg}$ ，圆满完成全部常规任务且临时任务覆盖率达 $100\%$ ，达成数据集人数约束上界，该核心指标实现全局最优。

本文构建的分层多目标调度框架与改进邻域搜索算法，有效解决了复杂约束下海上直升机运输多场景调度难题，模型兼具强约束适配性与算法鲁棒性，可灵活适配不同人员规模、不同停靠场景的海上直升机运输调度任务，同时算法架构可迁移至船舶运输、无人机物资配送等多类动态取送调度场景，具备极强的工程推广价值与实际应用价值。

关键词：直升机运输调度；取送路径优化；燃油标号算法；自适应大邻域搜索；分层排班模型

## 一、问题重述

## 1.1 研究背景

海上生产设施远离陆地，日常换班、增储上产、应急处置和临时作业均依赖直升机完成跨海人员运输。与普通城市客运不同，海上航线必须同时面对两类限制：一是直升机座位和燃油均为稀缺资源，部分远距离航线需要在指定设施进行补给；二是多日排班还受到具体飞机数量、机场归属、运营时段和人员时间的共同约束。若仅按照逐条需求安排直飞，虽容易实施，却会造成大量空座、重复航段与设备占用；若将全部需求一次性写入整数规划，又会因路径、装载和时刻的强耦合而难以求解。

因此海上人员运输需要同时协调人员拼载、设施访问顺序、机型选择、燃油补给和飞机占用。增加同一架次的停靠设施有利于提高拼载程度，却会带来绕行和停靠时间；选择大座位机型能够容纳更多人员，但其速度、油耗和可达范围也随之变化；进入多日排班后，单条路线即使满足容量与燃油约束，也可能因人员时间窗或具体飞机冲突而无法执行。因此，本文需要在逐架次检验物理可行性的基础上统筹路线选择、人员分配与机队排班。

## 1.2 研究任务

现已知 3 个陆地机场、52 个海上设施之间的距离，以及 3 种直升机的性能参数。每一航段的飞行时间由航段距离和机型速度确定，并向上取整至整数分钟；直升机在普通海上停靠点停留 10 分钟，在加油设施完成加油时停留 20 分钟。每架次须从某一陆地机场起飞并返回同一机场，中途不得经停其他陆地机场，且海上着陆次数不超过 5 次。现需根据不同运输需求和机队条件，制定人员分配、飞行路线及多日排班方案。

问题一 在直升机数量充足且不考虑人员时间要求的条件下，对 1600 名由陆地前往海上设施的人员进行运输安排。需要确定每名人员所乘架次、各架次的起降机场与机型、海上设施访问顺序以及加油位置，使全部人员均能到达指定设施，并保证各航段载客量和剩余燃油满足安全要求。在此基础上，优先使总飞机使用时间尽可能小，并综合评价座位利用率、总燃油消耗、人员总在途时间和总架次数。

问题二 在问题一的基础上，将运输需求扩展为出海、海返和海上设施间穿梭三种类型，其中分别包含1600、1600和800名人员。由于人员可在不同设施上下机，同一架次各航段的载客量会随停靠过程动态变化；当同一设施同时存在下机和上机需求时，应先完成下机，再利用释放的座位安排上机。需要建立联合运输方案，合理确定人员的上、下机位置以及架次访问顺序，保证每名人员从起点到终点始终乘坐同一架直升机，并在满足容量、燃油和停靠次数约束的条件下，优化总飞机使用时间及其他运输效率指标。

问题三 进一步考虑人员最早可离开起点时刻、最晚到达终点时刻和任务类型，并使用分属3个机场的24架具体直升机完成多日运输计划。每架飞机的归属机场和机型固定，每个架次应在规定运营时段内起飞并于当日返场，同一架飞机相邻两个架次之间还需保留不少于30分钟的地面周转时间。先在不安排临时任务的情况下，完成应急处置、增储上产和常规倒班任务，并求得最小总飞机使用时间。随后以该时间为上限重新安排全部运输任务，在保证非临时任务全部完成的基础上，尽可能增加得到满足的临时任务人数，并进一步改善座位利用、燃油消耗、人员在途时间和时间窗服务质量。

## 二、问题分析

三个问题的共同矛盾是局部拼载的收益与全局绕行的代价。对此，本文采用将数据驱动的候选架次生成与整数规划分配相结合的路线：先把距离、机型和需求转换为可行架次，再用离散决策完成全局选择，最后通过邻域搜索改进候选集。总体流程见图1。

## 2.1 问题一分析

问题一是以减少总飞机使用时间为首要目标的候选架次选择与人员分配问题。增加单个架次的停靠设施数能够提高拼载程度并减少架次，但会延长飞行距离和停靠时间；机场、机型与加油位置的不同组合也会改变路线的时间成本与燃油可行性。因此问题一的关键在于协调拼载收益与绕行代价。

基于此，本文首先根据设施需求量和空间关系生成候选设施组，并搜索相应的访问次序；其次，对不同机场、机型和加油方案进行组合，逐航段检验座位容量与余油量，筛选出物理可行的候选架次；最后建立集合划分模型，统一确定执行架次及人员分配方案。模型严格优先减小总飞机使用时间，在总时间相同时依次比较架次数、人员总在途时间、燃油消耗和座位利用率。

## 2.2 问题二分析

问题二的核心变化是人员运输方向由单向出海扩展为出海、海返和穿梭并存，使载客量随人员上下机过程动态变化。例如，出海人员在某设施下机后，空出的座位可由该设施出发的海返或穿梭人员使用；但增加停靠设施也会延长飞行和服务时间。因此，需要同时判断人员的上下机次序、逐航段载客量以及合并后的完整架次时间。

为此，对每名人员设置上、下机序号，并根据其是否经过某一航段计算实际载客人数，从而刻画同站先下后上以及航段容量变化。在此基础上生成联合取送候选架次，再由集合划分模型比较联合运输与拆分运输方案，统一确定架次选择和人员分配，保证每名人员由同一个架次完成运输且途中不换乘。

## 2.3 问题三分析

问题三在联合取送模型上进一步加入人员时间要求和有限机队，使路线可行性不仅取决于容量与燃油，还取决于具体飞机能否在相应时段执行。由于非临时任务必须完成，而临时任务可根据剩余运力选择性安排，该问题具有先确定基准运力、再分配剩余运力的分层决策特征。

据此，建立两阶段字典序优化模型。第一阶段仅安排非临时任务，求得其最小总飞机使用时间；第二阶段以该值为时间预算，重新优化全部路线与排班，最大化临时任务满足数，并进一步改善其他评价指标。对于每个入选架次，还需匹配机场和机型相符的具体飞机，并通过时间递推、人员时间窗及同机周转约束协调各架次的执行次序，最终实现路线选择、人员分配、飞机指派和时刻安排的联合优化。

## 三、模型假设

1. 飞行速度采用对应机型的额定速度，不计入天气、临时禁飞等外部扰动。

2. 直升机单位里程油耗不随载客量变化，海上停靠期间不消耗飞行燃油。

3. 任意两地点间严格按照给定距离飞行。

## 五、通用模型与评价指标

## 5.1 航段时间与候选架次

由距离除以速度得到小时数，换算为分钟后向上取整。机型 $m$ 从地点 $\ell$ 飞往 $\ell'$ 的航段时间为

$$
\mathrm{fly} (\ell , \ell^ {\prime}, m) = \left\lceil \frac {6 0 \mathrm{dist} (\ell , \ell^ {\prime})}{v _ {m}} \right\rceil ,
$$

(1)

其中系数60用于小时与分钟的量纲转换。候选架次 $r$ 表示一个完整可执行方案，包含起降机场 $a_{r}$ 、机型 $m_{r}$ 、有序停靠序列

$$
\pi_ {r} = \big (s _ {r 0}, s _ {r 1}, \ldots , s _ {r, n _ {r}}, s _ {r, n _ {r} + 1} \big), \qquad s _ {r 0} = s _ {r, n _ {r} + 1} = a _ {r}, \quad n _ {r} \leq 5,\tag{2}
$$

以及各站加油选择 $w_{r,i}$ 。若候选路线中存在重复设施，人员的下机序号取其上机后第一次到达终点的位置。

## 5.2 燃油递推与停靠时间

飞机从机场满油起飞，即 $\mathrm{rem}_{r,0} = U_{m_r}$ 。到达第 $i$ 个海上设施后，若该设施允许且选择加油，则离站油量补至油箱容量；否则保持原油量：

$$
\operatorname{depFuel} _ {r, i} = \operatorname{rem} _ {r, i} + w _ {r, i} \left(U _ {m _ {r}} - \operatorname{rem} _ {r, i}\right), \quad w _ {r, i} \leq 1 _ {\left\{s _ {r, i} \in F ^ {R} \right\}}, \quad w _ {r, 0} = w _ {r, n _ {r} + 1} = 0.\tag{3}
$$

下一站到达油量满足

$$
\mathrm{rem} _ {r, i + 1} = \mathrm{depFuel} _ {r, i} - \mu_ {m _ {r}} \mathrm{dist} (s _ {r, i}, s _ {r, i + 1}), \qquad \mathrm{rem} _ {r, i + 1} \geq R _ {m _ {r}}.\tag{4}
$$

不加油和加油停靠的最短时间分别为 10 和 20 分钟，故不含额外等待时的架次使用时间为

$$
c _ {r} = \sum_ {i = 0} ^ {n _ {r}} \operatorname{fly} \left(s _ {r, i}, s _ {r, i + 1}, m _ {r}\right) + \sum_ {i = 1} ^ {n _ {r}} \left(1 0 + 1 0 w _ {r, i}\right).\tag{5}
$$

## 5.3 全局评价指标

## (1) 总飞机使用时间指标

$$
T = \sum_ {r \in \mathcal {R}} c _ {r} x _ {r}.\tag{6}
$$

该指标统计所有执行架次从起飞到返回同一机场的时间总和，是三个问题共同的首要优化目标。

## (2) 总架次数指标

$$
N = \sum_ {r \in \mathcal {R}} x _ {r}.\tag{7}
$$

每个被执行的候选架次计一次，用于衡量机队出动规模和调度组织复杂度。

## (3) 总燃油消耗指标

$$
G = \sum_ {r \in \mathcal {R}} x _ {r} \mu_ {m _ {r}} \sum_ {i = 0} ^ {n _ {r}} \mathrm{dist} (s _ {r, i}, s _ {r, i + 1}).\tag{8}
$$

该指标为所有执行架次逐航段油耗之和。

## (4) 人员总在途时间指标

人员 p 在架次 r 上的在途时间为 $A_{r,v_{pr}} - D_{r,u_{pr}}$ ，因此

$$
W = \sum_ {p \in P} \sum_ {r \in \mathcal {R}} z _ {p r} (A _ {r, v _ {p r}} - D _ {r, u _ {p r}}).\tag{9}
$$

## (5) 座位利用率指标

座位利用率以客座公里衡量, 既反映载客人数, 也避免短航段与长航段被同等计数:

$$
U = \frac {\sum_ {r} x _ {r} \sum_ {i = 0} ^ {n _ {r}} Q _ {r , i} \mathrm{dist} (s _ {r , i} , s _ {r , i + 1})}{\sum_ {r} x _ {r} \sum_ {i = 0} ^ {n _ {r}} s _ {m _ {r}} \mathrm{dist} (s _ {r , i} , s _ {r , i + 1})}.\tag{10}
$$

上述指标按照严格字典序比较：首先最小化 T；仅当两个方案的 T 完全相同时，再依次最小化 N、W 和 G，最后最大化 U。因此，次级指标不会以增加总飞机使用时间为代价得到改善。

## 六、问题一的建立与求解

## 6.1 模型建立

## 6.1.2 候选架次生成

1. 生成候选设施组合。分别以每个设施为核心，根据设施间距离筛选空间邻近的设施，并由此生成包含核心设施、规模不超过 5 个设施的候选组合。

2. 确定设施访问顺序。对候选设施组合 $C = \{f_1, f_2, \ldots, f_q\}$ 和起降机场 $a$ ，先选取一个设施构成初始往返路线

$$
\pi = (a, f _ {1}, a).
$$

对尚未加入路线的设施 f，依次计算将其插入相邻停靠点 $s_{i}$ 与 $s_{i+1}$ 之间所产生的航程增量

$$
\Delta_ {i} (f) = \operatorname{dist} \left(s _ {i}, f\right) + \operatorname{dist} \left(f, s _ {i + 1}\right) - \operatorname{dist} \left(s _ {i}, s _ {i + 1}\right).
$$

将设施 f 插入使 $\Delta_{i}(f)$ 最小的位置，直至组合内设施全部进入路线。随后选取路线中的两个位置，反转其间的连续设施序列；若反转后的总航程更短，则接受该次调整，并重复该过程直至路线不再改进。当组合内设施数量较少时，直接枚举全部访问顺序，以避免插入过程遗漏更优排列。每个设施组合分别连接各个共同可选机场，形成若干首末机场相同的候选路线。

3. 匹配机型并检验燃油可行性。按各航段的实际载客人数筛除座位不足的机型，按每次到达后的剩余燃油量筛除低于最低安全余油量的机型。

4. 形成候选架次集。将通过航段容量与燃油检验的路线记为候选架次 r。对每个候选架次保存其使用时间 $c_{r}$ 、可服务人员集合、人员下机序号、各航段距离及燃油变化，由此构成候选架次集 $R_{1}$ ，供后续集合划分模型统一选择架次并分配人员。

## 6.1.3 集合划分

人员分配变量的取值定义为

$$
z _ {p r} = \left\{ \begin{array}{l l} 1, & \text {人员} p \text {由候选架次} r \text {从起点运送至目的地}, \\ 0, & \text {否则}. \end{array} \right.\tag{11}
$$

候选架次集合 $R_{1}$ 在生成时已记录其承运人员集合；对于不具备人员 p 所需起终点关系的架次，不建立对应的 $z_{pr}$ 变量。人员唯一分配与架次启用约束为

$$
\sum_ {r \in \mathcal {R} _ {1} (p)} z _ {p r} = 1, \qquad z _ {p r} \leq x _ {r}, \qquad \forall p \in P _ {1}, r \in \mathcal {R} _ {1} (p),\tag{12}
$$

其中 $\mathcal{R}_{1}(p)$ 表示能够把人员 p 由起点送至目的地的候选架次集合。第一项要求每名人员恰由一个架次完成运输；第二项表示人员只能分配给已执行架次。令人员 p 的目的设施在路线 r 中的首次出现序号为 $v_{pr}$ ，各航段载客量递推为

$$
Q _ {r, 0} = \sum_ {p \in P _ {1}} z _ {p r},\tag{13}
$$

$$
Q _ {r, i} = Q _ {r, i - 1} - \sum_ {p \in P _ {1}} z _ {p r} 1 _ {\{v _ {p r} = i \}}, \quad i = 1, \dots , n _ {r}.\tag{14}
$$

并满足逐航段容量约束

$$
0 \leq Q _ {r, i} \leq s _ {m _ {r}}, \quad i = 0, \dots , n _ {r}.\tag{15}
$$

首先在人员唯一分配、航段容量和候选架次物理可行条件下最小化

$$
T = \sum_ {r \in \mathcal {R} _ {1}} c _ {r} x _ {r},\tag{16}
$$

记当前搜索得到的最小总飞机使用时间为 $T^{*}$ 。固定 $T = T^{*}$ 后，继续按照 N, W, G, -U 的顺序比较方案，不允许次级指标增加 T。

## 6.2 算法求解

## 6.2.1 算法介绍

本文采用动态规划-燃油标号-节约合并-自适应大邻域搜索求解。前三个模块生成满足全部物理约束的初始解；随后以路线组为搜索单元，通过多种破坏、修复算子重构人员组合，并以人员重插和跨路线交换补充局部搜索。算法用 C++20 实现，Release 模式下单线程运行。

## 6.2.2 候选集生成与合并准则

对 1600 名人员按起终点组合分组，共得到 104 个不同的运输关系。对同一起终点组，先枚举批次人数 $q = 1, \ldots, 48$ 。对每个 q 枚举共同可选机场、三种机型和设施访问次序，调用燃油标号搜索获得时间最短的可行架次。令 $C(q)$ 为运送 q 人的最小架次时间， $D(j)$ 为完成该组前 j 人的最小时间，则

$$
D (j) = \min _ {1 \leq q \leq \min (4 8, j)} \{D (j - q) + C (q) \}, \quad D (0) = 0.\tag{17}
$$

由回溯式(17)得到初始批次。对每个批次依次枚举共同可选机场、机型和必经设施排列；一个排列经燃油标号扩展后若能返回原机场，则形成候选架次 $r$ ，否则删除。路线标号写为

$$
\lambda = (s, j, b, f, t),
$$

其中 s 为当前位置，j 为已按序完成的必经设施数，b 为海上停靠次数，f 为离站余油，t 为累计时间。由标号 $\lambda$ 飞向下一设施后，先扣除航段油耗，再根据该设施是否允许加油形成“不加油”或“补满油”两个后继标号；凡出现 $f < R_{m_{r}}$ 、b > 5 或不能返场的标号立即删除。相同 $(s, j, b)$ 下，若某标号满足 $f_{1} \geq f_{2}$ 且 $t_{1} \leq t_{2}$ ，则标号 2 被标号 1 支配并删除。所有到达返场状态的非支配标号中，累计时间最小者进入批次候选集。

将各批次的可行候选架次汇总后，按 $c_{r}$ 保留每个 “机场-机型” 组合下时间最短的路线，由此得到初始候选集。该过程的逻辑为

批次人员 $\longrightarrow$ 机场、机型、设施排列 $\longrightarrow$ 燃油标号校验 $\longrightarrow$ 可行候选架次.

在初始批次上执行节约合并。每个批次只考察设施距离最近的 14 个活动批次；对批次 $r_{1}, r_{2}$ 重新枚举合并后的机场、机型和停靠顺序。记 $c_{r_{1} \oplus r_{2}}$ 为两个批次合并运输后的最短可行架次时间，则合并节约量定义为

$$
\Delta T = c _ {r _ {1}} + c _ {r _ {2}} - c _ {r _ {1} \oplus r _ {2}}.\tag{18}
$$

$\Delta T > 0$ 表示合并比两个批次分别执行节省时间。仅当两批人员存在共同可选机场、合并后海上停靠不超过5次，且容量、起终点访问和燃油标号搜索均可行时，合并架次 $r_1 \oplus r_2$ 才进入候选集和最大优先队列；每次选取 $\Delta T$ 最大的候选合并，直至不存在正节约量的可行组合。

## 6.2.3 ALNS 强化搜索

节约合并所得方案作为 ALNS 初始解。破坏层采用三类算子：相关路线拆除优先移除设施集合和地理位置相近的 2 至 6 条路线，随机路线拆除增加搜索多样性，最差路线拆除则优先移除单位人员使用时间较高的路线。修复层采用两类算子：一是对被移除人员按同起终点重新动态分批，并在较大近邻范围内执行路线合并；二是随机打乱人员次序后逐人贪心插入，每次插入均重新选择机场、机型、设施访问顺序和加油策略。

每轮候选方案都重新进行取送先后、逐段容量和燃油校验。比较时依次考察 T、N、W、G 和 -U，仅接受字典序优于当前方案的候选解。破坏与修复算子的初始权重均为 1；每 25 轮根据实际改进次数更新为

$$
\omega_ {o} \leftarrow 0. 8 \omega_ {o} + 0. 2 \left(1 + \frac {5 n _ {o} ^ {+}}{n _ {o}}\right),\tag{19}
$$

其中 $n_{o}$ 和 $n_{o}^{+}$ 分别为算子 o 在本周期的调用次数和成功改进次数。完成路线组搜索后，再执行单人跨路线重插和两路线人员交换，并对发生变化的路线重新规划。该机制使搜索能够跳出仅依靠正节约合并形成的局部最优。

## 6.2.4 求解步骤

具体求解过程如下:

(1) 数据输入。读入 55 个地点的距离矩阵、三种机型参数及 1600 条人员需求；

(2) 参数初始化。设置最大海上停靠次数为 5、最大批次人数为 48、近邻候选数为 14，初始化路线缓存和不可行路线集合；本文对近邻数在 [8,20] 内预调，取 14 时可兼顾合并覆盖范围和计算时间；

(3) 动态分批。按式(17)求解各起终点组的批次划分，并回溯得到初始架次；

(4) 候选集生成。对每一批次枚举机场、机型和访问次序，调用燃油标号搜索，并将各“机场-机型”组合下时间最短的可行路线加入候选集；

(5) 节约合并。计算 $\Delta T = c_{r_{1}} + c_{r_{2}} - c_{r_{1} \oplus r_{2}}$ ，建立最大优先队列，反复接受正节约量最大的有效合并并更新近邻，直至队列为空；

(6) ALNS 改进。依概率选择破坏与修复算子，按式(19)每 25 轮更新权重；随后执行人员重插、跨路线交换和固定主目标下的次目标搜索；

(7) 结果输出。输出架次路线表和人员分配表，并由回读校验模块重新计算五项评价指标。

正式计算采用随机种子 20260817、2000 轮搜索，运行时间为 75.504 s。强化搜索前的可行基线为 100 架次、15767 min；最终得到 96 架次、15458 min，主目标进一步减少 309 min。

## 7.1.3 动态载客量

人员 p 仅在从 $u_{pr}$ 到 $v_{pr}$ 之间的航段占用座位，因此第 i 航段载客量可直接写为

$$
Q _ {r, i} = \sum_ {p \in P _ {2}} z _ {p r} 1 _ {\{u _ {p r} \leq i <   v _ {p r} \}}, \qquad 0 \leq Q _ {r, i} \leq s _ {m _ {r}}.\tag{22}
$$

等价地，引入第 $i$ 站的下机人数和上机人数

$$
L _ {r, i} = \sum_ {p \in P _ {2}} z _ {p r} 1 _ {\{v _ {p r} = i \}}, \qquad B _ {r, i} = \sum_ {p \in P _ {2}} z _ {p r} 1 _ {\{u _ {p r} = i \}},\tag{23}
$$

再按离站后的载客量递推

$$
Q _ {r, i} = Q _ {r, i - 1} - L _ {r, i} + B _ {r, i}, \quad i = 0, \dots , n _ {r}, \quad Q _ {r, - 1} = 0.\tag{24}

式(24)先扣除下机人数再加入上机人数，使同站释放的座位能够立即复用。该机制见图6。

## 7.2 算法求解

## 7.2.1 算法介绍

问题二采用有序取送 ALNS 算法。其初始解仍由动态分批、燃油标号和节约合并生成，ALNS 的破坏、修复、人员重插与交换框架沿用问题一；不同之处在于每次路线重构后均重新确定人员上、下机序号，并按人员所占用的连续航段区间检验容量。因此，算法优化的不是设施组合本身，而是同时满足取送顺序的人员-路线组合。

## 7.2.2 联合取送判定

问题二共有 4000 名人员和 264 个不同起终点组合。同起终点组仍按下式动态分批：

$$
D (j) = \min _ {1 \leq q \leq \min (4 8, j)} \{D (j - q) + C (q) \}, \qquad D (0) = 0.\tag{27}
$$

对给定设施排列，确定每名人员的上、下机序号；若不存在 $u_{pr} < v_{pr}$ ，则删除该排列。
第 i 航段载客量直接计算为

$$
Q _ {r, i} = \sum_ {p \in P _ {2}} z _ {p r} 1 _ {\{u _ {p r} \leq i <   v _ {p r} \}}, \qquad 0 \leq Q _ {r, i} \leq s _ {m _ {r}}.\tag{28}
$$

问题一已经给出的燃油标号、破坏与修复算子不再重复。对两个批次合并或 ALNS 重构后，重新枚举共同机场、机型和不超过 5 个海上停靠点的访问顺序，并计算

\Delta T = c _ {r _ {1}} + c _ {r _ {2}} - c _ {r _ {1} \oplus r _ {2}}.\tag{29}

只有同时满足 $u_{pr} < v_{pr}$ 、逐航段不超载、燃油安全且 $\Delta T > 0$ 的合并方案才进入最大优先队列。

## 8.1.2 时间递推与人员时间窗

人员上下机位置仍由起终点决定：

$$
\begin{array}{l} u _ {p r} = 0 \quad (o _ {p} = \text {LAND}), \qquad s _ {r, u _ {p r}} = o _ {p} \quad (o _ {p} \in F), \\ v _ {p r} = n _ {r} + 1 \quad (d _ {p} = \text {LAND}), \qquad s _ {r, v _ {p r}} = d _ {p} \quad (d _ {p} \in F), \\ 0 \leq u _ {p r} <   v _ {p r} \leq n _ {r} + 1. \end{array}\tag{31}

## 8.1.3 具体飞机指派与不重叠约束

$$
\sum_ {k \in K} y _ {r k} = x _ {r}, \qquad y _ {r k} \leq 1 _ {\{a _ {r} = a (k) \}} 1 _ {\{m _ {r} = m (k) \}}.\tag{39}
$$

若架次 r 与 $r'$ 由同一架飞机执行，则两个占用区间不能重叠，且二者必须满足

$$
H _ {r ^ {\prime}} \geq E _ {r} + 3 0 \quad \text {或} \quad H _ {r} \geq E _ {r ^ {\prime}} + 3 0.\tag{40}
$$

即前一架次返场后至少间隔 30 min，后一架次方可起飞。该约束直接对应排班程序中对占用区间 $\left[H_{r}, E_{r} + 30\right)$ 的不重叠检验。

## 8.2 算法求解

## 8.2.1 算法介绍

问题三采用时间窗优先的两阶段反馈排班算法。第一阶段生成时间相容的混合起终点批次，完成24架具体飞机的时刻安排，并通过人员迁移、冗余架次消除和路线重规划压缩非临时任务时间；第二阶段以深度受限增广换位接纳临时人员，并在固定主目标下改善人员在途时间。若第二阶段产生更短的路线集合，则剥离临时人员后反馈为新的第一阶段方案，再执行第二阶段，直至时间预算不再下降。四类任务人数依次为40、360、3440和160。

## 8.2.2 时间区间传播与飞机指派

第一阶段先按 “任务优先级-最晚到达时刻-最早出发时刻” 排列 3840 名非临时人员。对于允许跨日选择的人员，枚举其时间窗覆盖的日期以及单人可行路线，把该人员分配到当前已分配人数最少的可行日期。每日内部沿用同起终点动态分批和节约合并，再按优先级、最晚到达时刻及时间窗宽度从紧到松排列批次。

对于给定批次和候选架次 r，利用人员在路线中的上、下机位置将时间窗反向传播到起飞时刻，得到

$$
\begin{array}{r l} & {\underline {{H}} _ {r} = \max \left\{0 6 {:} 0 0, \max _ {p \in P _ {r}} \left(e _ {p} - \Delta_ {p r} ^ {D}\right) \right\},} \\ & {\overline {{H}} _ {r} = \min \left\{1 8 {:} 0 0, 2 0 {:} 0 0 - c _ {r}, \min _ {p \in P _ {r}} \left(l _ {p} - \Delta_ {p r} ^ {A}\right) \right\},} \end{array}\tag{45}
$$

其中 $\Delta_{pr}^{D}$ 和 $\Delta_{pr}^{A}$ 分别为架次起飞至离开人员起点、到达人员终点的时间偏移。若 $H_{r} > \overline{H}_{r}$ ，则该架次不能承运此批人员。对其余候选，遍历机场和机型相符的具体飞机，在区间 $[H_{r}, \overline{H}_{r}]$ 内寻找计及 30 min 周转的最早可用时段，并按“架次时间最短、起飞时刻最早、飞机编号最小”的顺序确定指派。若整个批次无法排入现有飞行计划，则将其按人数二分并重新排入队列。

第二阶段先按最晚到达和最早出发时刻排列临时人员，并尝试插入依次经过其起点、终点且时间窗相容的架次。若直接插入被满载航段阻塞，则采用深度为3的增广换位：从覆盖阻塞航段的人员中选出1至2人暂时移出，插入当前人员，再递归为被移出人员寻找其他可行架次。人员调整后，程序在固定T下重插人员以减少在途时间，并重新规划同机场、同机型路线；若由此缩短总时间，则把剥离临时人员后的方案反馈给第一阶段。

## 8.2.3 求解步骤

具体步骤如下:

(1) 数据输入。读入 4000 名人员的任务类型与时间窗，以及 24 架飞机的机场归属和机型；

(2) 参数初始化。设运营起飞区间为 06:00-18:00、最晚返场时刻为 20:00、同机周转时间为 $30 \mathrm{~min}$ ；近邻数沿用 14，其调试区间为 [8,20]；

(3) 任务排序与日期分配。按应急、生产、倒班的优先级及时间窗紧迫程度排序，将人员放入当前负载最小的可行日期；

(4) 批次与路线生成。逐日执行动态分批和节约合并，并依据式(45)删除起飞区间为空的路线；

(5) 具体飞机排班。在机场和机型匹配的飞机已有架次区间中寻找最早可用时段；无法排入的批次按人数二分后重新调度；

(6) 增广换位。先直接插入临时人员；遇到满载航段时移出 1 至 2 名阻塞人员，并在深度 3 内递归寻找替代架次；

(7) 反馈改进。在固定 $T$ 下执行人员重插和路线重规划；若总时间下降，则剥离临时人员并反馈为新的第一阶段方案；

(8) 终止与输出。时间预算不再下降后终止，输出带日期、飞机编号和到离时刻的路线表。

算法单线程运行 39.705 s，完成两次有效反馈更新后得到最终方案。第一阶段时间预算为 31209 min，第二阶段在该预算内完成全部 160 名临时人员。

/** 公历日期转自纪元起的天数（逆算法见 civilFromDays）。 */
long long daysFromCivil(int year, unsigned month, unsigned day) {
    year -= month <= 2;
    const int era = (year >= 0 ? year : year - 399) / 400;
    const unsigned yoe = static_cast<unsigned>(year - era * 400);
    const unsigned doy = (153 * (month + (month > 2 ? -3 : 9)) + 2) / 5 + day - 1;
    const unsigned doe = yoe * 365 + yoe / 4 - yoe / 100 + doy;
    return era * 146097LL + static_cast<long long>(doe) - 719468LL;
}

/** 天数转回公历日期。 */
std::tuple<int, unsigned, unsigned> civilFromDays(long long z) {
    z += 719468;
    const long long era = (z >= 0 ? z : z - 146096) / 146097;
    const unsigned doe = static_cast<unsigned>(z - era * 146097);
    const unsigned yoe = (doe - doe / 1460 + doe / 36524 - doe / 146096) / 365;
    int year = static_cast<int>(yoe) + static_cast<int>(era * 400);
    const unsigned doy = doe - (365 * yoe + yoe / 4 - yoe / 100);
    const unsigned mp = (5 * doy + 2) / 153;
    const unsigned day = doy - (153 * mp + 2) / 5 + 1;
    const unsigned month = mp < 10 ? mp + 3 : mp - 9;
    year += month <= 2;
    return {year, month, day};
}

    if (candidate < dp[served]) {

    previous[served] = size;
    }
    }
    }
    if (dp[count] == inf) fail("No initial feasible route for OD group " + demands[people .front()].origin + " -> " + demands[people.front()].destination);

    std::vector<int> sizes;
    for (int remaining = count; remaining > 0;) {
    const int size = previous[remaining];
    if (size <= 0) fail("Broken OD partition dynamic program");
    sizes.push_back(size);
    remaining -= size;
    }
    std::reverse(sizes.begin(), sizes.end());
    int offset = 0;
    for (int size : sizes) {
    Cluster cluster;
    cluster.id = static_cast<int>(clusters.size());
    cluster.people.assign(people.begin() + offset, people.begin() + offset + size);
    cluster.choice = *choiceBySize[size];
    clusters.push_back(std::move(cluster));
    offset += size;
    }
    }
    return clusters;
}

bool quickMergeCompatible(const Graph& graph, const std::vector<Demand>& demands, const Cluster& lhs, const Cluster& rhs) {
    std::vector<int> people = lhs.people;
    people.insert(people.end(), rhs.people.begin(), rhs.people.end());
    if (compatibleAirports(demands, people).empty()) return false;
    return demandFacilities(graph, demands, people).size() <= kMaxSeaStops;
}

/**
 * 两批次设施集合之间的最短距离，作为合并候选的近似评分。 */
int clusterDistance(const Graph& graph, const std::vector<Demand>& demands, const Cluster& lhs, const Cluster& rhs) {
    const auto a = demandFacilities(graph, demands, lhs.people);
    const auto b = demandFacilities(graph, demands, rhs.people);
    int result = std::numeric_limits<int>::max();
    for (int i : a) for (int j : b) result = std::min(result, graph.dist(i, j));
    return result;
}

/**
 * 尝试合并两个批次；合并后重新选择最优架次，不可行则返回空。 */
std::optional<Cluster> evaluateMerge(const Graph& graph, RoutePlanner& planner, const std::vector<Demand>& demands, const Cluster& lhs, const Cluster& rhs) {
    if (!quickMergeCompatible(graph, demands, lhs,rhs)) return std::nullopt;
    Cluster merged;
    merged.people = lhs.people;
    merged.people.insert(merged.people.end(), rhs.people.begin(), rhs.people.end());
    const auto choice = bestChoice(graph, planner, demands, merged.people);
    if (!choice) return std::nullopt;
    merged.choice = *choice;
    return merged;
}

/**
 * 按权重轮盘选择破坏/修复算子。
 * 注意：uniform_real_distribution 的具体映射随标准库实现而异，
 * 因此固定种子只在同一平台/编译器下保证逐位一致（见 README 补充说明）。
 */
int weightedOperator(std::mt19937& random, const std::vector<double>& weights) {
    const double total = std::accumulate(weights.begin(), weights.end(), 0.0);
    std::uniform_real_distribution<double> draw(0.0, total);
    double value = draw(random);
    for (int i = 0; i < static_cast<int>(weights.size()); ++i) {
    value -= weights[i];
    if (value <= 0.0) return i;
    }
    return static_cast<int>(weights.size()) - 1;
}

    std::optional<std::pair<long long, long long>> feasibleStartInterval(
    const RouteChoice& choice, const std::vector<Demand>& demands,
    const std::vector<int>& people, long long day) {
    long long lower = day + 6 * 60;
    long long upper = std::min(day + 18 * 60, day + 20 * 60 - choice.plan.duration);
    for (std::size_t i = 0; i < people.size(); ++i) {
    const Demand& demand = demands.at(people[i]);
    lower = std::max(lower, demand.earliest - choice.plan.departureOffset.at(choice.
    pickup.at(i)));
    upper = std::min(upper, demand.latest - choice.plan.arrivalOffset.at(choice.delivery.
    at(i)));
    }
    if (lower > upper) return std::nullopt;
    return std::pair{lower, upper};
}

    last = std::max(last, dateFloor(demand.latest));

    return {first, last};
}

/** 在 [lower, upper] 内寻找可容纳 duration 分钟任务的空闲起点，并预留 30 分钟周转。 */
std::optional<long long> earliestGap(const AircraftResource& resource, long long lower, long long upper, int duration) {
    long long candidate = lower;
    auto intervals = resource.occupied;
    std::sort(intervals.begin(), intervals.end());
    for (const auto [start, end] : intervals) {
    if (end <= candidate) continue;

    if (candidate > upper) return std::nullopt;
    }
    return candidate <= upper ? std::optional<long long>(candidate) : std::nullopt;
}

int reoptimizeTimedRoutePlans(const Graph& graph, RoutePlanner& planner,
    const std::vector<Demand>& demands,
    std::vector<Sortie>& sorties) {
    int changed = 0;
    for (auto& sortie : sorties) {
    RouteChoice incumbent{sortie.plan, sortie.pickup, sortie.delivery};
    std::optional<RouteChoice> best;
    const auto choices = enumerateChoices(graph, planner, demands, sortie.people, true);
    for (const auto& choice : choices) {
    if (choice.plan.airport != sortie.plan.airport ||
    choice.plan.aircraft != sortie.plan.aircraft) continue;
    if (choice.plan.duration > sortie.plan.duration) continue;
    const long long day = dateFloor(sortie.start);
    const auto interval = feasibleStartInterval(choice, demands, sortie.people, day);
    if (!interval || sortie.start < interval->first || sortie.start > interval->
    second) continue;
    if (choiceBetter(graph, choice, incumbent) &&
    (!best || choiceBetter(graph, choice, *best))) {
    best = choice;
    }
    }
    if (best) {
    sortie.plan = std::move(best->plan);
    sortie.pickup = std::move(best->pickup);
    sortie.delivery = std::move(best->delivery);
    ++changed;
    }
    }
    return changed;
}
