# 属性数据库

![[总览/属性库.base]]

## 平时怎么用

默认打开“日常通用（8 项）”，查看 `title`、`type`、`status`、`tags`、`topics`、`source`、`related`、`aliases` 的用途。它们是可复用的日常字段，不要求每篇都填齐。

需要处理某个旧属性时，按名称查找，先看“用途分类”和“处理建议”，再打开详细记录。记录提供真实使用数量、值类型、已有 Base 或脚本依赖，以及使用位置样例。

“查找使用位置”列会生成内置属性检索式，例如 `[related_notes]`。可将其复制进 Obsidian 搜索；详细记录中也有直接打开搜索的链接。实际查询包含模板和管理记录；表格中的“内容笔记数”快照排除了它们。

## 分类与默认处理

| 分类 | 默认处理 |
|:--|:--|
| 日常通用 | 复用标准名，按实际内容选择，避免为每篇填齐而堆空字段 |
| 按需可选 | 只在有日期、计划、复习、优先级等用途时填写 |
| 学习与课程 | 课程、习题、复习或方法场景专用；共享原子卡不填课程归属 |
| 课堂采集 | 保留采集、时间和真实性边界，空占位另行核查 |
| 资料与来源 | 文献或输入资料需要追溯时使用 |
| 导入转换 | 保留转换追溯和脚本协议，不复制到普通手写笔记 |
| 标签系统 | 标签数据库与维护脚本依赖，不扩散到学习笔记 |
| 软件与管理 | Obsidian、工具协议或数据库本身使用，按场景保留 |
| 课表配置 | 课表和归档匹配使用，出现次数少也应保留 |
| 项目流程 | 局限于具体数模或研究项目；普通笔记不复用 |
| 待归并 | 已发现职责重叠，先核对数据与调用方，再分批迁移 |
| 报告统计候选 | 通常更适合正文统计表；保留数值和含义，核查读取依赖后再停用属性 |
| 报告结构候选 | 嵌套报告结果可考虑改为正文结构化表格，先保留内容与协议 |

“归并与精简候选”视图共有 39 项：4 个字段名归并候选、32 个报告统计字段、2 个嵌套报告字段，以及语义不清的 `exam_content`。这里只登记建议，没有删除原笔记中的字段或数值。

## 已明确的归并方向

| 旧字段 | 建议方向 | 前提 |
|:--|:--|:--|
| `related_notes` | `related` | 核对并保留全部真实关联链接 |
| `linked_knowledge` | `related` | 共享条目按规范维护；数模模块先核对其自身协议 |
| `topic` | `topics` | 确认是主题含义，判断保留完整短语还是拆成列表 |
| `type_tag` | `exam_types` | 习题生成脚本仍会产出旧字段，先同步脚本和题型取值 |

以下字段不能因为名字相近直接合并：

- `created`、`updated`、`date`、`reviewed_at`、`review_date` 分别可能代表创建、更新、事件、实际审查和下次计划。
- `source_context` 是来源片段与位置，不等同于 `source` 的出处索引。
- `completion_status` 保存重建或录音缺失边界，不应简单并入 `status` 后丢失说明。
- `chapter` 和 `chapters` 可分别表示单章和跨章范围。
- `knowledge_tags`、`method_tags` 保留角色区分，统一标签搜索仍使用 `tags`。

## 数据与维护边界

统计快照：2026-10-27。磁盘 frontmatter 中共有 164 种属性；另登记 Obsidian 运行时的原生 `cssclasses`，总计 165 条记录。管理记录与模板不计入“内容笔记数”，避免标签数据库的 1349 条记录抬高使用频率。

属性数据库直接读取 `总览/属性库/条目/属性-字段名.md`。它只复用已有的 `title`、`type`、`status`、`scope`、`description`、`note`、`total` 七个属性键，**没有为管理属性再新增一批属性键**。分类使用 `scope`，用途使用 `description`，处理建议使用 `note`，内容使用次数快照使用 `total`；更细的证据放在正文。

记录不填写 `tags`，不全部反链数据库；它们不会成为概念标签结果，也不会形成所有条目连向一个 Base 的局部图谱。

低频、空值或无 Base 引用都不能单独证明字段无用。例如 `meeting_code` 多数为空但采集脚本仍会使用；`review_date`、`due_date`、`next_action` 当前主要出现在空模板中，但已有视图引用；`cssclasses` 是系统字段。处理前先查职责与依赖。

今后新增属性先查此库。一次性报告的统计与说明优先写在正文；确需新属性时再登记用途、值形式、适用场景和调用方。分类与建议可直接在数据库中编辑，数量是本次扫描快照。
