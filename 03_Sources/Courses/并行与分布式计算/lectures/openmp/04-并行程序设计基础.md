# 并行程序设计基础

## 1. 并行程序设计的特点与难点

并行硬件的发展速度很快，但软件的发展往往滞后。并行程序设计需要把算法、编程模型与具体硬件联系起来，既要保证计算结果正确，也要控制任务划分、通信、同步等额外开销。

### 1.1 抽象与性能之间的矛盾

高级编程模型能够减少开发者需要处理的细节。例如，OpenMP 通过编译指导语句和运行时支持提高共享内存并行程序的开发效率。但抽象层次提高后，开发者对底层执行细节的控制可能受到限制。

当目标是充分利用特定硬件的性能时，开发者往往需要掌握更底层、也更复杂的接口，例如 CUDA。因而，编程便利性与性能优化所需的细粒度控制之间存在矛盾。

### 1.2 编译器自动发现并行性的局限

编译器很难自动识别程序中复杂的并行性，并保证并行化后的执行仍然安全、正确。串行程序中的数据依赖、控制依赖以及运行时行为，都会影响自动并行化的效果。

### 1.3 管理开销带来的编程负担

并行程序除了执行实际计算，还需要处理以下工作：

- **任务和数据的划分与分配**：决定哪些计算可以并行，以及由哪个执行单元承担。
- **数据交换**：把计算所需的数据送到适当的位置。
- **同步和互斥**：协调执行顺序，避免对共享数据的冲突访问。
- **性能平衡**：避免少数执行单元承担过多工作，而其余执行单元处于等待状态。

这些工作占用开发和调试时间，也是并行程序复杂性的重要来源。

### 1.4 性能可移植性与生态问题

在一种硬件上经过优化的程序，迁移到另一种硬件后，不一定能够保持相同的性能。例如，针对 NVIDIA GPU 优化的 CUDA 程序，迁移到 AMD GPU 或国产芯片时，通常还需要适配相应的平台和工具。

HPC 领域存在 MPI、OpenMP、CUDA、HIP 等多种编程模型和生态。模型之间的差异增加了软件开发、优化和移植的复杂度。

应对方向包括：发展具有性能可移植性的编程框架，推进编译器与硬件架构的协同设计，以及使用 AI 辅助编程。

## 2. 进程、线程与 CPU 核心

### 2.1 进程与线程

**进程（Process）**是程序在计算机中的一次执行过程，是操作系统进行资源分配的基本单位。它具有完整的生命周期，通常拥有独立的地址空间，并能够与其他进程并发执行。

**线程（Thread）**是进程内部的执行单元，也是操作系统进行 CPU 调度和分派的基本单位。同一进程中的线程共享进程的内存等资源，各线程可以被独立调度。

| 比较项 | 进程 | 线程 |
| --- | --- | --- |
| 主要作用 | 承载程序执行并拥有所分配的资源 | 承载进程内部的执行路径 |
| 地址空间 | 不同进程通常拥有独立地址空间 | 同一进程内的线程共享地址空间 |
| 资源与开销 | 拥有独立资源，创建与切换需要管理这些资源 | 通常较轻量，创建与切换开销相对较小 |
| 并发与调度 | 多个进程能够并发执行 | 每个线程可以被独立调度 |

进程和线程的生命周期可以用三个基本状态来理解：

- **就绪态**：已经具备运行条件，等待系统调度。
- **运行态**：正在占用 CPU 执行指令。
- **阻塞态**：由于等待 I/O 或其他事件，暂时无法继续执行。

状态变化并不是简单的单向流程。例如，就绪状态下的线程获得 CPU 后进入运行态；运行时等待 I/O 会进入阻塞态；等待的事件完成后，线程重新进入就绪态。

### 2.2 CPU 核心与软件线程

**CPU 核心（Core）**是 CPU 中的物理执行单元，提供执行计算任务所需的硬件资源。**软件线程**则是程序中的执行路径，承载具体的指令，并由操作系统调度到硬件上执行。

### 2.3 超线程技术

**同时多线程（Simultaneous Multithreading，SMT）**是一种硬件执行技术：一个物理核心为多个硬件线程保留各自的体系结构状态，并让它们共享核心的执行资源，从而同时推进多个线程的指令执行。

**超线程技术（Hyper-Threading）**是 Intel 对 SMT 的一种实现。支持超线程的一个物理核心可向操作系统提供两个逻辑处理器，操作系统可以分别向它们调度软件线程。两个逻辑处理器共享该核心的执行单元、缓存等资源，因此逻辑处理器数量增加不等于物理核心数量或计算能力成倍增加。

当一个线程不能充分利用执行资源时，另一个线程可能利用空闲资源，提高核心利用率。实际性能收益取决于工作负载与资源竞争情况。参见 [Intel 超线程技术说明](https://www.intel.com/content/www/us/en/developer/articles/guide/hyper-thread-tuning-guide-for-video-ai-workload.html)。

## 3. 并行度与并行粒度

**并行度（Degree of Parallelism，DOP）**表示可以同时执行的子进程或计算活动的数量。

**并行粒度（Granularity）**表示两次并行或交互操作之间所执行的计算负载。粒度越小，单次并行工作所包含的计算越少；粒度越大，单次并行工作所包含的计算越多。

按计算活动的层次，可以区分：

1. **指令级并行**：在指令执行层次利用并行性。
2. **线程级并行**：由多个线程承担并行工作。
3. **进程级并行**：由多个进程承担并行工作。
4. **任务级并行**：将计算组织为可并行执行的任务。

在总计算工作量固定的情况下，把工作分成更多、更小的部分，通常能够增加并行度，但也会增加任务管理、交互和同步开销。相反，增大粒度通常会减少任务数量，使可利用的并行度下降。

并行度与粒度之间存在权衡，实际关系还受到任务依赖、问题规模和硬件资源的影响。

任务分配的原则是：**让系统的大部分时间用于实际计算，减少空闲、通信和同步所占的时间。**因此，粒度不能只追求越小越好，也不能只追求越大越好，需要结合问题规模与系统开销选择。

## 4. 进程的同构性：SPMD 与 MPMD

### 4.1 SPMD：单程序、多数据

**SPMD（Single Program, Multiple Data）**中，各个进程执行同一个程序，但处理不同的数据。这是一种同构进程结构，常见于并行循环和数据并行计算。

“同一个程序”并不要求每个进程在每一时刻都执行相同的语句。程序可以根据进程编号选择不同的分支，从而让同一程序承担不同任务，例如：

```text
if (mynodeID == i) S(i)
```

其中，`mynodeID` 表示当前处理结点或进程的编号；编号为 `i` 的执行单元执行任务 `S(i)`。

### 4.2 MPMD：多程序、多数据

**MPMD（Multiple Program, Multiple Data）**中，不同进程可以执行不同的程序。这是一种异构进程结构，常对应任务并行、功能并行或控制并行，程序通常由不同的并行块组成。

例如，要执行三个不同的并行任务，可以编写三个程序 `S1`、`S2`、`S3`，分别编译，然后通过脚本加载到三个处理结点上：

```text
run S1 on node1
run S2 on node2
run S3 on node3
```

这些程序各自使用顺序语言编写，并通过通信库调用完成交互。

### 4.3 两种结构的关系

为拥有大量处理器的计算机编写完全异构的程序，会增加程序数量与维护难度。SPMD 可以通过进程编号和条件分支表达不同角色，因此也能够组织多个不同的并行任务。

对于可扩展并行机，SPMD 能够表达广泛的并行任务结构。具体实现仍需要相应的数据划分、通信与同步支持。

## 5. 并行程序设计模型

编程模型规定了程序员如何表达并行计算，以及数据如何组织、通信和同步由谁负责。下面介绍隐式并行、数据并行、共享变量和消息传递四种模型。

### 5.1 隐式并行（Implicit Parallel）

程序员使用熟悉的串行语言编写程序，由编译器与运行支持系统将串行程序自动转换为并行代码。

它的主要特点是：

- 程序语义相对简单，可移植性较好。
- 程序员面对的是串行、单线程的逻辑，因而较容易调试和验证正确性。
- 自动发现的并行性往往较细，属于细粒度并行。
- 性能高度依赖编译器发现并行性的能力；复杂依赖和分析限制可能降低并行效率。

这里的“单线程”指源程序的编程视角；转换后的执行代码可以具有并行性。

### 5.2 数据并行（Data Parallel）

数据并行是 SIMD 的自然编程模型，对数组等聚合数据结构中的多个元素实施并行操作。

在单地址空间的数据并行模型中，数据之间的交互由编译系统或运行时隐式处理。

**优点**是编程相对简单，串行程序和并行程序可以保持较一致的结构。**不足**是程序性能在很大程度上依赖编译系统，以及用户对该系统的了解；可利用的并行性主要局限于数据级，粒度通常较小。

### 5.3 共享变量（Shared Variable）

共享变量模型是 SMP 和 DSM 的自然模型。多个线程在同一地址空间中执行，可以采用 SPMD 或 MPMD 的组织方式。

其特点包括：

- **单一地址空间**：线程可以访问共享变量。
- **显式同步**：程序员需要表达线程间的必要协调。
- **隐式数据分布**：程序员通常不需要以消息传递方式明确将数据分配到独立地址空间。
- **隐式通信**：通过对共享变量的读写完成数据交换。

典型代表是 **OpenMP（Open Multi-Processing）**。共享数据便于线程交换信息，但共享访问的正确性仍需要适当的同步与互斥。

### 5.4 消息传递（Message Passing）

消息传递是 MPP 和 COW 的自然模型。程序由多个异步并行执行的进程组成，各进程具有自己的地址空间。

其特点包括：

- **多地址空间**：进程不能直接把其他进程的普通局部数据当作自己的变量访问。
- **显式同步**：通过程序中的通信和同步操作协调执行。
- **显式数据映射与负载分配**：程序员决定数据与计算如何分配到各进程。
- **显式通信**：通过消息交换完成进程之间的数据传递。

这一模型能够适用于不同类型的并行机，也可以与数据并行、共享变量模型混合使用。典型代表包括 **PVM（Parallel Virtual Machine）** 和 **MPI（Message Passing Interface）**。

### 5.5 模型比较

| 模型 | 主要编程视角 | 地址空间 | 交互或通信 | 主要控制方式 |
| --- | --- | --- | --- | --- |
| 隐式并行 | 编写串行程序，由系统发现并行性 | 由具体实现决定 | 由编译器与运行时处理 | 自动并行化 |
| 数据并行 | 对数组等聚合数据并行操作 | 本节讨论单地址空间模型 | 隐式交互 | 编译系统负责大量执行细节 |
| 共享变量 | 多线程访问共享数据 | 单一地址空间 | 共享变量读写，隐式通信 | 显式同步 |
| 消息传递 | 多进程分工与交换消息 | 多地址空间 | 显式通信 | 显式数据映射、负载分配与同步 |

## 6. 五种基本的并行化范式

并行化范式描述的是如何组织任务和执行关系。它与编程模型的侧重点不同：一种范式可以采用不同的编程模型实现。

### 6.1 相并行（Phase Parallel）

相并行把程序划分为一组超级步，也称为“相”。在每个相内部，各执行单元独立完成计算；相与相之间进行通信和同步。

![相并行示意图](assets/04-并行程序设计基础/phase-parallel.png)

*图 3：相并行。`C` 表示各执行单元的计算，`Synchronous Interaction` 表示相之间的同步交互。*

其执行节奏为：

```text
各执行单元计算 → 通信与同步 → 各执行单元计算 → 通信与同步 → …
```

在这种相并行结构中，计算与通信分阶段进行，二者不重叠。同步使下一个相能够使用上一相产生并交换的数据。

### 6.2 主从并行（Master-Slave Parallel）

主从并行也称为放牧式并行。主进程承担串行控制和任务协调工作，子进程负责具体子任务的计算。

![主从并行示意图](assets/04-并行程序设计基础/master-slave-parallel.png)

*图 4：一个主进程（Master）与多个子进程（Slave）交互。箭头表示任务和结果的传递。*

这种范式容易与相并行结合：主进程可以在一个计算阶段分配工作，在阶段结束时协调结果和下一轮任务。它的主要限制是主进程可能成为瓶颈；当任务数量和子进程数量增加时，集中协调的负担也会增加。

### 6.3 分治并行（Divide and Conquer Parallel）

父进程把计算负载分割为多个子问题，并指派给子进程。子进程并行完成各自的计算后，由父进程归并结果。

![分治并行示意图](assets/04-并行程序设计基础/divide-and-conquer-parallel.png)

*图 5：分治并行的分解与归并。图的上半部分逐层分割任务，下半部分逐层汇合结果。*

基本过程为：

```text
分解问题 → 并行求解子问题 → 归并结果
```

负载分割是否均衡，会直接影响子进程的工作量和等待时间。若子问题的计算量差异较大，分治结构可能产生负载不均衡，需要调整划分方法或任务调度方式。

### 6.4 流水线并行（Pipeline Parallel）

一组进程按流水线方式完成作业。不同进程负责流水线中的不同阶段，并可同时对不同数据项重叠执行操作。

![流水线并行示意图](assets/04-并行程序设计基础/pipeline-parallel.png)

*图 6：三个处理阶段 `P1 → P2 → P3` 组成流水线。一个阶段的输出送到下一阶段。*

例如，`P2` 处理前一个数据项时，`P1` 可以处理下一个数据项，`P3` 可以处理更早进入流水线的数据项。流水线的并行性来自不同阶段对不同数据项的重叠执行。

### 6.5 工作池并行（Work Pool Parallel）

工作池把待执行任务放入一个公共任务池，各进程从池中取出任务并执行。执行过程中还可以产生新任务，再放回任务池，供其他进程获取。

![工作池并行示意图](assets/04-并行程序设计基础/work-pool-parallel.png)

*图 7：多个执行进程 `P1`、`P2`、`P3` 从工作池（Work Pool）获取任务，也可以把新任务放回池中。*

各进程持续领取任务，直到全部任务完成。若执行中的任务可能产生新任务，任务池暂时为空不代表整个计算已经结束，还需确认没有尚未完成的任务会产生后续工作。工作池能够根据执行进度动态分配工作，因此较容易实现负载平衡。

其限制是，简单工作池不适合直接处理存在未满足依赖关系的任务；任务不能仅因为进入任务池就立即执行，还需要满足相应的前置条件。

### 6.6 五种范式比较

| 范式 | 任务组织方式 | 协调方式 | 主要特点 |
| --- | --- | --- | --- |
| 相并行 | 分为多个计算相 | 相之间统一通信与同步 | 计算与通信不重叠 |
| 主从并行 | 主进程协调，子进程计算 | 主进程集中分配与收集 | 易与相并行结合，主进程可能成为瓶颈 |
| 分治并行 | 逐层分解，再逐层归并 | 父子任务之间交接结果 | 需要关注实际负载划分 |
| 流水线并行 | 按处理阶段组成流水线 | 阶段间传递数据 | 不同阶段可重叠执行 |
| 工作池并行 | 多个执行单元动态领取任务 | 公共任务池 | 易于负载平衡，依赖任务需要额外处理 |
