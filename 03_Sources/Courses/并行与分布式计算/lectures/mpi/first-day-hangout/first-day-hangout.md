# 从 OpenMP 到 MPI：后半程课程导览

**并行与分布式计算 · first-day-hangout**

后半程围绕一个问题展开：怎样把一个科学计算任务分给多个进程，让它们通过通信合作，并用数值结果和实验数据说明程序是否正确、是否有效？

## 一、我们在课程中的位置

整门课共 48 学时：前半程 24 学时学习 OpenMP，后半程 24 学时学习 MPI。MPI 部分共 12 次课，前 11 次学习与练习，第 12 次进行大作业考核与 PPT 答辩。

OpenMP 部分已经建立了线程协作、共享变量、同步与性能分析的基础。MPI（Message Passing Interface，消息传递接口）部分将进一步关注进程的本地数据、工作划分和数据交换。课程中先在同一 Dev Container 内运行多个 MPI 进程，学习这种编程模型；多个进程不等于多台节点，单容器实验也不能直接代表集群上的性能。

MPI 是接口标准。课程环境采用其开源实现 Open MPI，MPICH 是另一种开源实现；后续将结合标准接口学习程序编写与运行。

## 二、学完后应该能够做什么？

| 学习目标 | 可以展示的证据 |
|---|---|
| 解释进程与数据的组织 | 画出各 rank 的任务和数据，说明需要交换的内容，区分 rank、节点与核心。 |
| 独立构建和运行程序 | 用 Makefile 编译、改变进程数运行，解释 MPI 程序结构、通信器以及 rank/size。 |
| 设计正确的通信 | 选择点对点或集合通信，解释消息匹配，发现并修复典型死锁。 |
| 完成并验证数值计算 | 从模型和算法出发，建立串行基线，再实现数据划分与边界交换，核对并行结果。 |
| 用证据说明自己的工作 | 保存代码与修改记录、实验条件、正确性结果和性能数据，并在答辩中解释设计与局限。 |

## 三、学习路线与每次课的计划

学习路线是：**认识进程与数据 → 学会通信与协作 → 建立数值模型和串行算法 → 实现 MPI 并行程序 → 整理证据并答辩**。

| 讲次 | 主要内容 | 练习与预期产出 |
|---|---|---|
| 1 | 硬件背景、消息传递、Git 协作 | 区分核心、线程、进程、rank 与节点；完成个人分支上的提交与 Pull Request。 |
| 2 | MPI 程序结构、SPMD、通信器、rank/size | 用 Makefile 编译运行 Hello World，观察普通变量的进程本地性。 |
| 3 | 点对点通信与消息匹配 | 完成 Ping-Pong 与环形传递，说明发送与接收如何配对。 |
| 4 | 数据划分与并行数值积分 | 用 Send/Recv 汇总局部积分计算 π，与串行结果比较。 |
| 5 | 死锁与非阻塞通信 | 分析通信依赖，修复会相互等待的程序，使用合理的通信顺序或非阻塞操作。 |
| 6 | 广播与规约：Bcast/Reduce | 用集合通信改写 π 计算，解释数据分发与结果汇总。 |
| 7 | Scatter/Gather 与分布式数组 | 分发数组、局部处理、收集结果，并检查整体正确性。 |
| 8 | 邻居通信与相邻数据交换 | 通过奇偶排序理解邻居交换，为网格边界通信作准备。 |
| 9 | 热传导方程与数值求解思路 | 理解温度场、初边值条件和时间推进，先建立数学模型与求解思路。 |
| 10 | 热传导离散与串行求解 | 建立差分格式，实现串行时间推进，检查稳定性条件和数值结果。 |
| 11 | 热传导的 MPI 并行实现 | 划分计算域、交换边界数据，验证并行结果，分析计算与通信开销。 |
| 12 | 大作业考核与 PPT 答辩 | 提交项目材料，用结果、图表和代码回答设计与验证问题。 |

热传导是数值计算的主要教学案例。第 9–11 次按“**模型与数值思路 → 离散与串行算法 → MPI 并行实现**”推进。共轭梯度法（CG）作为选学拓展，不替代这条主线。

## 四、怎样使用讲义、示例和实验环境？

课程采用现有的 VS Code Dev Container，示例程序统一由各目录内的 Makefile 管理。学习一个例子时，先阅读讲义与程序详解，预测输出，再运行原程序；修改代码后重新编译，最后记录结果并解释变化。

配套材料的分工如下：

- `lectures/mpi/`：Markdown 讲义与课堂 PDF。
- `examples/mpi/`：示例源码、Makefile、README 和 `程序详解.md`。
- `docs/`：环境搭建、Git 与 SSH 配置、常见问题。
- `git-practice/`：个人分支、提交与 Pull Request 的上机实验。

例如，在容器终端试跑已发布的 Hello World：

```bash
cd /workspace
cd examples/mpi/01_hello_world
make
make run NP=1
make run NP=2
make run NP=4
```

记录 rank 与进程总数的对应关系，输出顺序可以变化。`NP` 设置请求启动的进程数，不是节点数。后续讲义和示例会随教学进度发布。

## 五、最后的大作业要完成什么？

大作业由**每位学生个人完成**，允许自选 MPI 科学计算题目，形成一个**能够复现、具有正确性验证的项目**，第 12 次课用 PPT 展示并答辩。项目应有明确的计算目标、实际的 MPI 数据划分与通信，以及可核对的实验结果。课堂练习是项目的积累：数据划分、通信、验证与计时都应逐步整理。

热传导可以作为贯穿课程的参考项目：说明求解的问题与初边值条件，建立数值算法和串行程序，再将网格分给多个 rank，交换计算所需的边界数据，并比较数值结果和运行时间。扩展可以围绕划分方式、通信组织、问题规模或可视化展开；基础结果应先可靠。

可自选的方向包括数值积分、矩阵或向量运算、并行排序、热传导等数值模拟，也可选择其他适合消息传递的科学计算问题。选题时先说明算法与数据依赖，选择自己能够完成并验证的规模。热传导是参考题，并非统一必选题。

具体提交日期和评分细则，将在大作业任务书中公布。本导览先说明共通的项目材料与答辩要求。

### 需要提交的项目材料

| 材料 | 应包含的内容 |
|---|---|
| 源码与 Makefile | 可编译的程序、明确的构建与运行入口。 |
| README | 实验环境、编译和运行命令、参数含义、输出位置及复现步骤。 |
| 实验数据与图表 | 正确性比较、运行时间、进程数与问题规模；保留原始数据。 |
| 项目报告 | 数学问题、数值算法、数据划分、通信设计、验证方法、结果与局限。 |
| 答辩 PPT | 用图、结果和必要的代码片段说明项目；与提交的程序和数据一致。 |

### 怎样证明程序正确、怎样讨论性能？

先用小问题和单进程运行检查，再保持相同的输入、问题规模、数值参数及停止条件核对多进程结果。以热传导为例，应使用相同网格、时间步长和初边值条件。可以与串行程序或适用的已知解比较，说明误差及容许范围；涉及浮点运算时，结果不一定逐位相同。

性能实验应记录硬件或容器环境、问题规模、进程数与计时范围。固定同一问题比较时间，给出串行基线或单进程基线；二者应明确标注。若使用加速比，说明其定义，例如 $S_p=T_{\mathrm{ref}}/T_p$，其中 $T_{\mathrm{ref}}$ 是写明的参考程序耗时，$T_p$ 是采用 $p$ 个 MPI 进程的耗时。重复测量并保留原始记录；即使没有加速，也可以依据数据分析通信、负载或可用计算资源的影响。

`MPI_Wtime` 可以测量本进程的经过时间；不同节点的时钟不保证同步，不能直接拿两个进程的绝对时间戳相减。计时方法和各进程结果的汇总方式，会在后续练习中讲解。

## 六、PPT 答辩应该讲清哪些事情？

建议按下列顺序组织，不规定必须使用多少页：

1. **问题与目标**：求解什么，为什么需要并行，输入和输出是什么。
2. **模型与数值算法**：任务的数学描述、算法或离散、串行基线；热传导等问题还应说明初边值条件。
3. **并行设计**：数据怎样划分，各 rank 做什么，何时交换哪些数据。用图说明。
4. **正确性验证**：对照对象、误差标准、小规模与不同进程数的结果。
5. **性能实验与分析**：实验条件、原始数据整理出的图表、开销和限制。
6. **结论与工作说明**：完成了什么、还有哪些问题、自己的实现与改进，以及参考代码或工具帮助的使用情况。

准备回答：改变进程数为什么仍能得到正确结果？关键数据交换有什么作用，例如热传导少一次边界交换会怎样？计时包含了哪些部分？出现没有加速的结果时，证据支持什么解释？

## 七、考核关注的能力

| 关注点 | 答辩与材料中应能看到的证据 |
|---|---|
| 正确性 | 清楚的验证方法、对照结果和误差说明。 |
| 并行设计 | 数据划分、通信参与者和依赖关系能够解释。 |
| 实验分析 | 条件与计时口径明确，结论由真实数据支持。 |
| 工程复现 | 源码、Makefile、README 与提交材料相互对应。 |
| 答辩说明 | 能解释代码和结果，说明自己的工作及参考材料或辅助工具的使用。 |

这些是项目准备的关注点；具体分值以正式大作业任务书为准。
