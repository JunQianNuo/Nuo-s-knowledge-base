## 一、可可靠还原的内容

### 1. 从手动分工到 parallel for

上一节用线程号和线程总数手动划分循环：

    for (long i = tid + 1; i <= n; i += thread_count) {
        /* 每个线程处理一部分迭代 */
    }

OpenMP 可用工作共享结构自动完成迭代分配：

    #pragma omp parallel for
    for (long i = 1; i <= n; ++i) {
        /* 各次迭代必须可独立执行 */
    }

只有当不同迭代之间不存在会改变语义的数据依赖时，循环并行化才是安全的。

### 2. 变量作用域

- `shared`：线程共享同一存储位置，多个线程同时写入时可能发生数据竞争；
- `private`：每个线程有独立副本，默认不继承并行区外的初值；
- `firstprivate`：每个线程有独立副本，并从进入并行区前的值初始化；
- OpenMP 工作共享循环的迭代变量通常具有预定的 private 属性；
- 循环体中的临时变量宜在循环体内部定义，使其自然成为每次迭代的局部量。

### 3. 累加与 reduction

积分、求和等循环若直接让线程共同执行

    sum += value;

会产生数据竞争。课件给出的规范方式是：

    #pragma omp parallel for reduction(+:sum)
    for (long i = 1; i <= n; ++i) {
        sum += value_of(i);
    }

`reduction(+:sum)` 为每个线程维护局部部分和，并在并行循环结束时合并。并行累加顺序与串行不同，浮点结果可能出现机器精度范围内的末位差异。
