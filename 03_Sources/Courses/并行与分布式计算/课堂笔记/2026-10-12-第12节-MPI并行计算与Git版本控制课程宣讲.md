## 一、从共享内存到消息传递

OpenMP 面向共享内存：线程可访问同一地址空间，通过同步结构协调共享数据。MPI 面向分布式内存：每个进程有独立地址空间，数据交换必须通过显式消息完成。

```mermaid
flowchart LR
    A[整体问题] --> B[划分数据与任务]
    B --> C[多个MPI进程独立计算]
    C --> D[进程间通信]
    D --> E[汇总结果]
    E --> F[评估负载与通信开销]
```

设计 MPI 程序时需同时考虑：

- 如何划分数据和计算；
- 哪些进程之间需要通信；
- 如何减少通信次数与数据量；
- 如何避免部分进程空闲造成负载不均；
- 计算收益能否覆盖通信与同步开销。

在集群节点之间可用 MPI，在单个节点内部可用 OpenMP，从而形成 MPI + OpenMP 混合并行。

## 二、MPI程序的基本运行方式

Open MPI 是 MPI 标准的一种实现。典型编译和运行命令为：

```bash
mpicc -std=c11 hello.c -o hello_mpi
mpirun -np 4 ./hello_mpi
```

`mpicc` 是封装了必要头文件和链接参数的编译器驱动；`-np 4` 表示启动 4 个进程。每个进程通过 rank 区分自己的身份，并依据 rank 执行相应任务。

多个进程的标准输出到达终端的先后顺序不确定。因此，屏幕上打印顺序既不等于 rank 顺序，也不能用来证明进程真实执行顺序。

## 三、Git与SSH工作流

课堂要求通过版本控制管理课程项目，基本流程为：

1. 在课程代码平台 fork 仓库；
2. 本地生成 SSH 密钥；
3. 将公钥添加到账户；
4. 使用平台给出的 SSH 地址克隆自己的仓库；
5. 在个人仓库中提交和同步代码。

生成密钥可使用：

```bash
ssh-keygen -t ed25519
```

克隆时使用课程平台实际提供的地址：

```bash
git clone git@host:account/repository.git
```

不要把私钥上传到仓库或发送给他人；平台只需要公钥。

## 五、易错点

1. 把 MPI 进程误认为共享同一内存；
2. 只增加进程数，不分析通信开销和负载均衡；
3. 依据终端输出顺序推断执行顺序；
4. 复制他人仓库而不 fork，失去独立提交路径；
5. 上传 SSH 私钥或把密钥写入代码仓库。
