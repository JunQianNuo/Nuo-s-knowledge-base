## 二、为什么每个进程要多存两个节点（00:00–06:39）

### 1. 三点格式跨过了分区边界

计算全局第5个节点需要第4、5、6个节点的旧值。如果第5个节点属于rank 1，而第4个属于rank 0，rank 1必须先接收第4个节点；反过来，rank 0更新第4个节点需要rank 1的第5个节点。相邻进程互相复制边界数据，而不用交换整个局部向量。

每个进程负责$m$个内部节点，本地数组分配$m+2$个位置：

| 本地下标$j$ | 用途 |
|---|---|
| $0$ | 左幽灵节点，保存左邻居的末个内部值，或物理左边界 |
| $1,\ldots,m$ | 本进程负责更新的内部节点 |
| $m+1$ | 右幽灵节点，保存右邻居的首个内部值，或物理右边界 |

> 一句话来说：幽灵节点是邻居数据在本进程中的副本，让靠近分区边界的三点计算仍可直接访问相邻数组元素。

“不负责存储”应理解为不拥有该全局未知量，不能理解成不占内存。它确实占用本地存储，但不作为本进程独立更新、重复汇总的未知量。教师以总规模1000万、分给100个进程为例：每个进程约10万内部数据，再加两个位置，额外空间比例约为$2/100000$。这说明**此规模下存储开销小**，不保证小问题的通信耗时也小。

教师提示二维、三维也要交换分区边界，大作业若涉及二维问题需要沿用这一思路；本次没有给出可恢复的完整二维分区图或实现，不把一维的“两个元素”直接套到二维。

### 2. 全局编号与本地编号

课堂使用偏移量$o$，以

$$
i=o+j,\qquad 1\le j\le m
$$

把内部节点的本地编号$j$变为全局编号$i$。初始化时先由$i$得到空间坐标，再计算初始温度，不能把每个进程的$j$直接当成全局空间编号。

**课堂小练习**：$N=11$、3个进程，中间rank 1的$o=4,m=3$。其本地下标$0,1,2,3,4$分别对应全局编号$4,5,6,7,8$；中间三个才是本进程的内部节点。左ghost取得rank 0的全局第4个值；右ghost取得rank 2的全局第8个值。

**补充解释：按已有差分记号还原一致的划分。**若$N$表示区间段数，则物理端点为$0,N$，待更新内部节点共$N-1=10$个。与课堂$o=4,m=3$相符的分块为：

| rank | 负责的全局内部节点 | $m$ | $o$ | 左ghost来自哪里 | 右ghost来自哪里 |
|---|---|---:|---:|---|---|
| 0 | $1,2,3,4$ | 4 | 0 | 物理端点$0$ | rank 1的$j=1$，全局$5$ |
| 1 | $5,6,7$ | 3 | 4 | rank 0的$j=4$，全局$4$ | rank 2的$j=1$，全局$8$ |
| 2 | $8,9,10$ | 3 | 7 | rank 1的$j=3$，全局$7$ | 物理端点$11$ |

这里rank 0的数组长6，另外两个长5；录音中的“五个数”可对应中间进程，不能推广为所有进程都恰好五个数。原分区图未随录音保存，上表是与已确认编号一致的解释，不冒充屏幕原图。

## 三、交换方向与MPI_Sendrecv（06:39–18:32）

### 1. 用可预测的数据检查交换

教师使用内部节点值$100+i$演示交换，物理两端温度为20℃。上述中间进程交换后应是

$$
\underbrace{104}_{\text{左ghost}},\quad105,106,107,\quad
\underbrace{108}_{\text{右ghost}}.
$$

左右两个物理边界的ghost应为20。先预测这种人工初始化的结果，比直接观察复杂温度曲线更容易发现发错方向、收错位置等问题。课堂使用三个进程运行halo演示；目标名在转写中不够可靠，不伪造可复制的完整启动命令。

### 2. 两次组合收发

对本进程定义`left=rank-1`、`right=rank+1`，在最左/最右端把不存在的邻居设为`MPI_PROC_NULL`。录音提到标签71、72以及每次传一个双精度值。

**补充代码示意**（假定每个进程至少有一个内部节点，数组长度为$m+2$）：

```c
int left  = (rank == 0)        ? MPI_PROC_NULL : rank - 1;
int right = (rank == size - 1) ? MPI_PROC_NULL : rank + 1;

if (left  == MPI_PROC_NULL) old[0]     = 20.0;
if (right == MPI_PROC_NULL) old[m + 1] = 20.0;

MPI_Sendrecv(&old[1], 1, MPI_DOUBLE, left, 71,
             &old[m + 1], 1, MPI_DOUBLE, right, 71,
             MPI_COMM_WORLD, MPI_STATUS_IGNORE);
MPI_Sendrecv(&old[m], 1, MPI_DOUBLE, right, 72,
             &old[0], 1, MPI_DOUBLE, left, 72,
             MPI_COMM_WORLD, MPI_STATUS_IGNORE);
```

第一调用：把首个内部值发向左边，同时从右边接收其首个内部值，放进本进程右ghost。第二调用：把末个内部值发向右边，同时从左边接收其末个内部值，放进左ghost。每个rank执行同样代码，各rank通过消息匹配形成交换；不需要root逐个调度。

`MPI_Sendrecv`将一次发送和一次接收放在同一调用中，可以避免简单链式移位中“所有人都先阻塞发送”的循环等待；发送与接收缓冲区必须分离。它是阻塞调用，本rank返回后才能依次进行后续操作，但不意味着所有rank在绝对同一时刻完成。[Open MPI接口说明](https://docs.open-mpi.org/en/v5.0.7/man-openmpi/man3/MPI_Sendrecv.3.html)

> [!warning] 边界值与通信量的边界
> `MPI_PROC_NULL`表示不存在的进程，不能替代20℃这一物理条件；程序仍须填好物理边界。每个rank只交换常数个标量，全系统每轮传输的标量数为$O(P)$，其中$P$是进程数；这不是“实测通信时间只随$P$线性增长”的结论。若分块出现$m=0$，上面访问首末内部节点的代码还需额外处理，本示意不覆盖该情况。

## 四、从串行迭代改为局部迭代（18:32–24:50）

### 1. 每个时间层先交换，再更新

**先修公式回顾（沿用11月2日已核对记号）**：一维热方程$T_t=\alpha T_{xx}$在网格上的显式更新为

$$
u_i^{n+1}=u_i^n+r\left(u_{i-1}^n-2u_i^n+u_{i+1}^n\right),
\qquad r=\frac{\alpha\Delta t}{\Delta x^2}.
$$

$n$为时间层，$i$为空间全局编号，$\alpha$是热扩散系数。MPI版本保持公式不变，只把本地循环变成$j=1,\ldots,m$，由两个ghost补齐邻居值。

**补充伪代码**：

```text
建立本地分块、old和next
对j=1至m，用i=o+j、x_i=iΔx计算初值
每个时间步：
    在old中设置物理边界，交换左右ghost
    对j=1至m：
        next[j] = old[j] + r*(old[j-1]-2*old[j]+old[j+1])
    交换old与next的指针
汇总最终old的内部节点
```

只更新内部节点，不把ghost作为独立未知量演化。指针交换避免整段复制；下一时间层仍须先保证当前`old`的物理边界及ghost有效。

> 一句话来说：并行化主要改变“邻居旧值从哪里来”和“自己算哪一段”，不改变这道一维差分公式。

**补充数值条件**：沿用先修笔记的一维稳定限制$0\le r\le1/2$；不满足时，即便MPI通信完全正确也可能发生数值振荡或发散。此处是帮助检查实现的提醒，不声称本次录音重新推导了稳定性。

### 2. root读取参数后广播

教师以rank 0收集时间步长、空间步长、扩散系数等参数，再广播给所有进程。虽然本机演示只有少量输入，这种组织方式模拟多节点计算中的统一输入分发。录音还提到先广播整数状态/参数，再广播数值参数。

所有进程必须使用一致的问题参数和通信调用顺序；广播得到的是每个进程的本地副本，不能当作共享内存。具体参数结构与教师工程的变量名未完整保存，不臆造其结构体或命令行选项。

## 五、把不等长结果拼回去（24:50–29:54）

### 1. 为什么用Gatherv

各rank内部节点数可能不同，不能直接用相同数量的`MPI_Gather`拼接。`MPI_Gatherv`允许root为每个rank指定接收数量`recvcounts[p]`和写入位置`displs[p]`。`displs`的单位是接收数据类型的extent；普通`MPI_DOUBLE`数组中可按元素位置理解，不能当成字节偏移。[Open MPI接口说明](https://docs.open-mpi.org/en/v5.0.7/man-openmpi/man3/MPI_Gatherv.3.html)

**补充例子**：上面分块的内部长度为$4,3,3$。若root把内部节点紧凑存入长度10的数组，则

$$
\mathrm{recvcounts}=(4,3,3),\qquad
\mathrm{displs}=(0,4,7).
$$

各rank从`&old[1]`发送$m$个内部值，不重复发送ghost。若直接写入包含两个物理端点的完整数组，并使内部第一个值落到全局下标1，则位移为$(1,5,8)$，端点另外填写。必须先明确接收缓冲区的定义，不能混用这两组位移；该对照为补充解释，不是教师源码摘录。

### 2. 正确性需要两类对照

课堂分别比较：

1. **MPI解与串行数值解**：采用同样网格、步长、初边值条件和终止时间，比较同一数值算法的实现；课堂称差异应很小、接近机器精度量级，不是要求任意实现逐位相同。
2. **数值解与解析解**：比较离散近似与真实解，得到离散误差。节点上的最大绝对误差可记为

$$
E_\infty=\max_i\left|u_i-T(x_i,t_{\mathrm{final}})\right|.
$$

这是有限个网格节点上的最大值，不是对整个连续空间逐点取上确界的实测结果。MPI与串行相符并不保证二者都正确，还要检查解析参考解、边界、步长和误差收敛。

### 3. 二阶收敛的正确说法

录音29:09附近“区间长度翻倍，误差变为四分之一”与紧接着“区间个数平方成反比”的表述不一致。**按后者核对**：固定总长度，网格段数$N$翻倍意味着$\Delta x$减半；若处在二阶收敛区间，误差约为原来的$1/4$，不是$\Delta x$翻倍后误差变小。

**补充解释**：当前格式的总体误差通常包含$O(\Delta t)+O(\Delta x^2)$；要观察整体随空间网格二阶收敛，时间步长须相应受控，例如固定$r$时$\Delta t\propto\Delta x^2$，并满足光滑性、稳定性等条件。不能仅凭空间差分二阶就断言任意时间步长下总误差都是二阶。

## 七、如何测量MPI并行时间（01:16:36–01:24:27）

### 1. 每个进程自己计时，再取最大值

准确函数名为`MPI_Wtime()`，不是纪要中的`MPI_Wall_time`。它返回本进程所在节点的墙钟秒数；同一进程前后相减得到该进程的耗时，不能把一个rank的结束读数减去另一个rank的开始读数，因为不同节点时钟不保证同步。[Open MPI官方说明](https://docs.open-mpi.org/en/v5.0.7/man-openmpi/man3/MPI_Wtime.3.html)

课堂先用`MPI_Barrier`让所有进程到达测量起点，再计时，最终用`MPI_Reduce`和`MPI_MAX`取得最慢rank的耗时。

**补充代码示意**：

```c
MPI_Barrier(MPI_COMM_WORLD);
double start = MPI_Wtime();
/* 本次约定的时间迭代区间：包括每轮必要的halo交换与更新 */
double local_seconds = MPI_Wtime() - start;
double max_seconds = 0.0;
MPI_Reduce(&local_seconds, &max_seconds, 1, MPI_DOUBLE,
           MPI_MAX, 0, MPI_COMM_WORLD);
if (rank == 0) {
    printf("iteration wall time = %.6f s\n", max_seconds);
}
```

屏障保证所有参与者到达后才允许继续，不承诺不同进程纳秒级同时离开，也不自动使时钟同步。最大值表示本次计时区间里最慢进程完成所需的时间；将局部耗时相加会重复累计并行发生的时间，不能当作用户等待的总墙钟时间。

### 2. 先说清测量区间

课堂输出的最大耗时字段只测**时间迭代段**，不包含此前初始化、MPI设置及后续文件输出等完整程序成本。记录加速比时应保留这个边界，不能拿它与串行的“从启动到CSV写完”混比。

教师还区分wall time与CPU time。**补充核对**：wall time是实际经过时间，包括测量段里的等待；CPU time反映进程实际占用CPU的时间。多个进程的CPU时间之和不保证随进程数不变，通信、忙等和调度都可能改变它；算法复杂度描述随输入规模的增长规律，也不能直接等同某次CPU秒数。

## 八、为什么小问题看不到加速（01:24:27–01:27:17）

课堂预告：在1600个网格的小问题上，从1到2到4个进程，耗时可能几乎不降；在16万个网格等更大问题上才更容易看出加速，但也不会必然线性。详细加速比及扩展性分析安排到下节课。

**补充解释**：固定问题规模时，理想计算量可分成约$1/P$，但通信、同步等成本仍在。局部更新太少时，这些成本可能抵消计算收益。加速比可写为

$$
S(P)=\frac{T_1}{T_P},\qquad \eta(P)=\frac{S(P)}P.
$$

$T_1,T_P$须采用相同问题、精度、终止时间、构建配置和计时范围。固定总问题规模的比较与随进程数增加问题规模的弱扩展实验不同；本次只提到弱扩展，未完整讲清实验设定，不能据录音填出性能曲线或精确加速比。

## 九、自测（新编）

### 自测1：收发方向与汇总

采用本节$N=11$的划分，若rank 1发送`old[1]`到rank 0，该值应写到rank 0的哪个本地下标？若root只拼接10个内部值，三个rank的发送数量与接收位移分别是什么？为什么不能把$m+2$个元素全部拼起来？

> [!hint]- 提示
> 先区分“拥有的内部值”和“邻居值副本”；位移按接收缓冲区的实际布局计算。

> [!solution]- 解析
> rank 1的`old[1]`对应全局5，应写入rank 0的右ghost，即`old[5]`，因为该rank的$m=4$。发送数量为$(4,3,3)$，紧凑内部数组的位移为$(0,4,7)$。ghost重复保存邻居未知量，直接汇总会重复内部数据，还会混入物理边界。

### 自测2：计时是否公平

某次3进程迭代局部耗时为0.19、0.24、0.21秒，串行同一迭代范围为0.48秒。求并行时间、加速比与效率。若串行计时还包括输出CSV，而并行不包括，这个加速比能直接采用吗？

> [!hint]- 提示
> 并行任务要等最慢进程完成；先统一测量范围，再比较。

> [!solution]- 解析
> 并行时间取0.24秒，$S(3)=0.48/0.24=2$，效率$\eta(3)=2/3$。若两侧计时范围不同，这组比值不能作为公平加速比，应统一范围重测。数字为新编题设，不是课堂实测。
