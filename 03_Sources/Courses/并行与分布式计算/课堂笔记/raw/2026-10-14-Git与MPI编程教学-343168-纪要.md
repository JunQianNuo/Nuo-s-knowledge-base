一、Git版本控制与代码提交流程

会议首先演示了如何使用Git进行日常的代码修改、分支管理以及向云端仓库提交合并请求的完整流程。

1. 分支创建与代码修改

-   新建本地分支：为避免直接修改主分支（master），开发者应使用 git checkout -b 命令创建并切换到新的本地分支进行开发。

-   修改文件并暂存：在VS Code中修改文件后，可通过 git diff 命令或编辑器内置功能查看具体修改记录，确认无误后使用 git add 命令将修改暂存。

-   提交修改记录：使用 git commit -m "message" 命令将暂存的修改提交到本地仓库，并附带清晰的修改说明信息。

2. 云端同步与合并请求

-   推送分支至云端：本地分支需使用 git push --set-upstream origin <分支名> 命令在云端建立对应分支并推送代码。

-   创建Pull Request：在GitHub网页端发起Pull Request，选择本地分支作为源分支，目标仓库的主分支作为目标分支，以申请代码合并。

-   代码审查与冲突处理：合并请求提交后需由目标仓库管理者进行审查，若系统提示存在冲突，则需检查并修改冲突文件后方可完成合并。

二、MPI并行编程基础

会议随后转入MPI（消息传递接口）编程教学，重点讲解了并行计算的基本架构与核心概念。

1. 并行计算基本架构

-   多进程执行模型：MPI与OpenMP不同，它是直接开启多个独立的进程同时运行，进程间可通过通信域进行数据交换。

-   标准执行流程：MPI程序的标准执行流程包含初始化（MPI_Init）、获取进程信息、执行本地任务以及结束运行（MPI_Finalize）四个核心步骤。

-   进程编号与总数获取：在初始化后，程序可通过 MPI_Comm_rank 获取当前进程在通信域中的唯一编号（rank），并通过 MPI_Comm_size 获取通信域内的总进程数。

2. 通信域与局部变量机制

-   通信域划分与隔离：通信域（MPI_Comm）用于指定进程间数据交换的上下文，预定义的 MPI_COMM_WORLD 包含所有进程，而 MPI_COMM_SELF 仅包含当前进程，可用于实现进程间的分组与隔离。

-   局部变量特性：MPI中的rank和size等变量均为局部变量，各进程独立占有自己的内存区域，彼此之间不直接共享数据。

-   基于Rank的任务分配：开发者可通过判断进程的rank值，为不同的进程分配特定的本地工作任务。

3. 数据操作与进程间通信

-   局部数据修改：每个进程拥有独立的局部变量，可通过代码逻辑对特定进程（如rank为0的进程）的局部数据进行赋值和修改。

-   数据传递需求：MPI基于本地变量进行运算，若需将某个进程修改后的数据（如rank 0的变量值）同步至其他进程，必须通过MPI的数据传递函数来实现。

三、Makefile编译配置讲解

会议最后详细解析了用于管理MPI程序编译的Makefile文件结构与变量定义。

1. Makefile变量定义

-   编译器与核心数配置：Makefile顶部定义了编译器变量（CC = mpicc）和默认进程数（NP ?= 4），其中问号表示允许在运行时覆盖默认值。

-   编译参数设置：配置了C11标准、警告信息输出以及优化器参数，以确保代码的正确性与执行效率。

2. 编译与运行命令

-   目标文件编译：通过 make all 命令，利用 mpicc 编译器将源文件（.c）编译生成可执行的目标文件。

-   并行程序运行：make run 命令会调用 mpirun -n $(NP) ./$(TARGET) 指令，根据设定的进程数运行当前目录下的目标可执行文件。

-   清理目标文件：make clean 命令用于删除编译生成的目标文件，方便重新编译和管理项目。
