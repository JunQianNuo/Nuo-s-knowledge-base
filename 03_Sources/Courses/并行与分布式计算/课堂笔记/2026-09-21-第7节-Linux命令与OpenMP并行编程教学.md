## 一、本节课核心脉络

本节延续上一节的 Linux 实践，先学习文本查看、排序过滤、进程监控和硬件信息命令，再练习 Vim 与 Shell 脚本。后半节进入 OpenMP：理解共享内存与 Fork-Join 模式，使用条件编译检查编译器是否启用 OpenMP，最后通过 argc、argv 读取命令行参数，并布置命令行四则运算程序。

## 二、文本查看、排序与过滤

| 目的 | 命令示例 | 课堂要点 |
|:--|:--|:--|
| 输出完整文件 | cat file | 适合短文件；输入部分文件名后可用 Tab 补全 |
| 分页查看长文件 | more file | 避免内容一次滚出屏幕；可逐行或逐页向下浏览 |
| 排序文本行 | sort file | 默认按当前区域设置和字符顺序排序 |
| 搜索匹配行 | grep "word" file | 从文本中筛选包含指定模式的行 |
| 查看文件头尾 | head file、tail file | 课件列出的常用文本查看方法 |
| 字段化处理 | awk '{print $1}' file | 适合按列提取和处理文本 |

这些命令可以通过管道组合。例如：

    grep "error" app.log | sort | head

Shell 会把前一条命令的标准输出交给后一条命令，因而可用多个小工具完成复杂处理。课堂要求课后继续练习 sed、awk、grep，并能在下一节演示和口头说明。

## 三、进程与硬件信息

### 1. top：动态观察资源

top 会持续刷新进程的 CPU、内存等使用情况，适合观察计算程序是否真正占用资源。退出动态界面后，终端不再持续刷新。

### 2. lscpu 与处理器拓扑

lscpu 可查看架构、物理核心、逻辑处理器、缓存和 NUMA 节点等信息。需要区分：

- 物理核心是实际执行计算的硬件单元；
- 逻辑处理器可能来自超线程，不能简单等同于相同数量的物理核心；
- L1、L2、L3 缓存容量和共享方式会影响数据访问成本；
- NUMA 表示不同处理器访问不同内存区域的延迟和带宽可能不同。

课堂将 NUMA 与前面讲过的非一致内存访问联系起来：即使程序能够创建很多线程，数据放置不合理也会拖慢并行程序。线程数只是性能上限的一部分，缓存、内存带宽和访问局部性同样重要。

Linux 也把许多系统信息暴露为虚拟文件，因而可以用 cat 查看，例如处理器信息文件。具体路径和字段可能随系统而异，使用前应先核对当前发行版。

## 四、Vim 的基本操作

Vim 打开后默认处于普通模式，不能像普通编辑器那样直接输入正文。

1. 按 i 进入插入模式并编辑。
2. 按 Esc 返回普通模式。
3. 输入 :w 保存。
4. 输入 :q 退出。
5. 输入 :wq 保存并退出。
6. 输入 :q! 放弃未保存修改并强制退出。

课堂使用 Vim 的目的不是要求今后所有作业都在其中完成，而是让大家理解终端环境下编辑文件的基本方式。真正掌握的关键是亲自创建、修改、保存并重新查看文件。

## 五、Shell 脚本与自动化

Shell 脚本把多条命令按顺序写入文件，以便重复执行。首行 shebang 指定解释器，例如：

    #!/usr/bin/env bash

一个简单脚本可以完成“创建目录、进入目录、创建文件、写入内容、编译程序、运行程序”等连续任务。科研计算中，还可让脚本在长时间计算结束后自动整理结果和调用绘图程序，减少人工值守。

执行脚本前通常需要赋予权限：

    chmod +x demo.sh
    ./demo.sh

也可以显式交给解释器：

    bash demo.sh

> [!warning] 脚本会批量执行命令
> 在脚本中使用 rm、mv、sudo 或通配符前，应先打印并核对路径，避免把一次输入错误放大为批量破坏。

## 六、OpenMP 与 Fork-Join 模式

OpenMP 是面向共享内存系统的并行编程模型，支持 C、C++ 和 Fortran。它由编译制导、运行时库函数和环境变量组成，能够在串行程序中逐步加入并行区域。

典型执行过程是：

1. 程序由单个主线程串行开始。
2. 遇到并行域时，主线程 Fork 出一个线程团队。
3. 各线程并行执行并行域中的工作。
4. 到达并行域末尾后同步并 Join，恢复为主线程串行执行。
5. 后续遇到新的并行域时可再次 Fork。

共享内存意味着线程能访问同一地址空间，但不代表所有变量都应共享。循环下标、临时变量等常需设为 private；真正需要协作的数据才设为 shared。若多个线程无同步地写同一位置，会发生数据竞争。

## 七、条件编译与 GCC

OpenMP 编译器在启用 OpenMP 时会定义宏 _OPENMP，可用条件编译检测：

    #include <stdio.h>

    int main(int argc, char *argv[])
    {
    #ifdef _OPENMP
        printf("OpenMP is enabled.\n");
    #else
        printf("OpenMP is not enabled.\n");
    #endif
        return 0;
    }

用 GCC 编译时，-fopenmp 会启用 OpenMP 支持：

    gcc -Wall test.c -o test
    gcc -Wall -fopenmp test.c -o test_omp

第一条命令通常进入未定义 _OPENMP 的分支，第二条进入已定义分支。-Wall 打开常见警告，-o 后面的参数指定输出文件名。若编译失败，应逐项核对源码文件名、选项拼写、输出名和错误信息，不要只反复执行同一条命令。

## 八、argc、argv 与命令行参数

C 程序的入口可写为

    int main(int argc, char *argv[])

其中：

- argc 是命令行参数总数；
- argv 是参数字符串数组；
- argv[0] 通常是程序自身的调用名称；
- argv[1] 到 argv[argc-1] 才是用户输入的其余参数。

例如执行

    ./compute 12 + 3

通常有 argc=4，argv[1] 为 "12"，argv[2] 为 "+"，argv[3] 为 "3"。所有参数最初都是字符串，运算前要用 strtod、strtol 等函数转换并检查转换是否成功。程序还应先检查参数数量，并处理除数为零、未知运算符等错误。

## 九、课堂作业：命令行四则运算

要求编写一个 C 程序，从命令行读取两个数字和运算符，实现加、减、乘、除。例如：

    ./compute 8.5 "*" 2

建议实现步骤：

1. 检查 argc 是否符合预期；
2. 将两个数字字符串转换为数值；
3. 根据运算符选择运算；
4. 除法前检查除数是否为零；
5. 输出结果或清晰的错误信息；
6. 编写 Shell 脚本自动完成编译和运行。

课堂允许借助 AI 理解语法和排查问题，但要求本人完成调试并能解释参数如何进入程序。除四则运算外，课后还需练习常用文本命令、编写含三四条命令的脚本，并在 WSL 中熟悉权限相关操作。

## 十、易错点

> [!warning] 易错点
> - cat 适合短文件；长文件优先使用 more 或 less。
> - NUMA 不是“所有内存访问速度一致”，恰恰强调访问代价可能不一致。
> - Fork-Join 中的 Fork 是创建线程团队，不是复制整个 OpenMP 程序。
> - 共享内存不等于没有数据竞争；共享变量的并发写入仍需同步。
> - 未加 -fopenmp 时，编译器可能忽略 OpenMP 制导，_OPENMP 也不会按预期定义。
> - argv 中的数字仍是字符串，不能直接进行数值加减。
> - shell 中星号可能被展开为文件名，作为乘号参数时应加引号。
