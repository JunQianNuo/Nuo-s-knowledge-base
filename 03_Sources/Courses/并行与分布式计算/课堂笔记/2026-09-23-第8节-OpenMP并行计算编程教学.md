## 二、OpenMP 运行时环境

使用 OpenMP 运行时函数前需包含头文件：

    #include <omp.h>

| 函数 | 含义 |
|:--|:--|
| `omp_get_num_procs()` | 返回可供程序使用的处理器数量 |
| `omp_get_thread_limit()` | 返回运行时允许的线程数上限 |
| `omp_get_thread_num()` | 返回当前线程在线程组中的编号 |
| `omp_get_num_threads()` | 返回当前并行域中的线程总数；串行区通常为 1 |
| `omp_get_max_threads()` | 返回后续并行域默认可使用的最大线程数 |
| `omp_set_num_threads(n)` | 设置后续并行域期望使用的线程数 |
| `omp_in_parallel()` | 判断当前是否位于活动并行域 |
| `omp_get_wtime()` | 返回墙钟时间，可用于计时 |
| `omp_get_wtick()` | 返回墙钟计时器的分辨率 |

`omp_set_num_threads(n)` 设置的是运行时请求，不保证在任何环境中都一定创建 $n$ 个线程；动态调节、线程上限和运行环境都可能影响实际线程数。

## 三、并行域与隐式同步

    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        int team_size = omp_get_num_threads();
        printf("thread %d of %d\n", tid, team_size);
    }

主线程进入并行域后创建线程组，各线程执行同一段结构化代码；离开并行域末尾时默认存在隐式屏障，所有线程到达后才继续执行后面的串行代码。

多个线程的 `printf` 顺序是不确定的，输出交错不代表线程编号错误。每次运行的调度次序也可能不同，不应依赖打印先后来推断程序逻辑。

## 四、共享变量与私有变量

并行域外定义的变量通常共享，并行域内的自动局部变量通常为线程私有。也可显式使用 `private`：

    int value = 10;

    #pragma omp parallel private(value)
    {
        value = omp_get_thread_num();
    }

`private(value)` 会为每个线程创建独立副本，初值通常未定义；它不会自动把并行域外的原值复制进去。若需要复制初值，应根据语义使用 `firstprivate`。

若多个线程同时读写共享变量且缺少同步，就可能发生数据竞争。尤其不能让所有线程无保护地执行 `sum += local_sum`。可使用 `critical`、原子操作或 `reduction` 等方式安全合并结果。

## 五、用 Makefile 管理编译与运行

Makefile 可把编译选项、目标文件和运行命令固化下来。例如：

    CC = gcc
    CFLAGS = -O2 -fopenmp
    TARGET = pi

    .PHONY: all run clean

    all: $(TARGET)

    $(TARGET): pi.c
    	$(CC) $(CFLAGS) pi.c -o $(TARGET)

    run: $(TARGET)
    	./$(TARGET)

    clean:
    	rm -f $(TARGET)

常用命令：

- `make`：构建默认目标；
- `make run`：构建后运行；
- `make clean`：删除构建产物；
- `.PHONY`：声明不代表真实文件的目标，避免与同名文件冲突。

> [!warning] 配方行必须使用 Tab
> Makefile 中命令行开头通常必须是真正的制表符，而不是若干空格。复制代码后若出现 “missing separator”，应首先检查缩进。

## 六、中点积分法计算圆周率

利用

$$
\pi=\int_0^1\frac{4}{1+x^2}\,dx,
$$

将区间等分为 $n$ 份，步长 $h=1/n$，中点 $x_i=(i-\frac12)h$，于是

$$
\pi\approx h\sum_{i=1}^{n}
\frac{4}{1+x_i^2}.
$$

串行程序的核心循环为：

    double h = 1.0 / n;
    double sum = 0.0;

    for (long i = 1; i <= n; ++i) {
        double x = (i - 0.5) * h;
        sum += 4.0 / (1.0 + x * x);
    }

    double pi = h * sum;

## 七、手动划分循环

设线程号为 `tid`，线程总数为 $p$。可以让第 `tid` 个线程处理

$$
i=tid+1,\ tid+1+p,\ tid+1+2p,\ldots
$$

对应代码为：

    double total = 0.0;

    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        int p = omp_get_num_threads();
        double local_sum = 0.0;

        for (long i = tid + 1; i <= n; i += p) {
            double x = (i - 0.5) / n;
            local_sum += 4.0 / (1.0 + x * x);
        }

        #pragma omp critical
        total += local_sum;
    }

    double pi = total / n;

每个线程只写自己的 `local_sum`，退出循环后再安全合并到 `total`。由于每个线程只进入临界区一次，竞争远小于在每次循环中都锁住共享和。

### 用 reduction 简化归并

课件提供的更常用写法是归约：

    double sum = 0.0;

    #pragma omp parallel for reduction(+:sum)
    for (long i = 1; i <= n; ++i) {
        double x = (i - 0.5) / n;
        sum += 4.0 / (1.0 + x * x);
    }

`reduction(+:sum)` 为每个线程维护私有部分和，并在并行区末尾做加法归并，语义比手写共享更新更清晰。

## 八、计时与加速分析

可用 `omp_get_wtime()` 记录前后时间。若串行时间为 $T_1$，$p$ 线程时间为 $T_p$，加速比定义为

$$
S_p=\frac{T_1}{T_p}.
$$

课堂实验中，在增大积分步数后，4 线程曾观察到接近 4 倍的加速。这是具体机器和任务规模下的实验结果，不是普遍保证。

- 工作量太小时，创建线程、同步和计时开销可能大于并行收益；
- 线程数超过可有效利用的硬件并不一定更快；
- 内存带宽、缓存、调度和串行部分都会限制加速；
- 性能比较应保持算法、编译优化和输入规模一致，并多次运行。

## 九、AI 辅助代码的检查原则

课堂提醒可借助 AI 生成代码，但必须做语义验证：

1. 是否正确启用 `-fopenmp`；
2. 循环边界和步长是否覆盖所有任务且不重复；
3. 共享变量是否存在数据竞争；
4. `private`、`firstprivate`、`reduction` 的含义是否使用正确；
5. 结果是否与串行基准一致；
6. 加速是否来自真实计算，而非遗漏了工作。

代码能编译只说明语法基本通过，并不能证明并行结果正确。

## 十、易错点

1. 在并行域外调用 `omp_get_num_threads()`，通常只能得到 1。
2. 假设线程打印顺序固定。
3. 误以为 `private` 会继承外部变量初值。
4. 多线程直接更新共享累加变量，产生数据竞争。
5. Makefile 配方行用空格代替 Tab。
6. 任务过小却据一次计时断言并行加速。
