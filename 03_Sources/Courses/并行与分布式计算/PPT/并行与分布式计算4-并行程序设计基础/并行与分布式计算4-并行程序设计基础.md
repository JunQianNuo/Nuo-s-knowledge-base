## 并行程序设计基础

## **并行程序设计的特点与难点**

- 硬件飞速发展，软件滞后，技术先行,缺乏理论指导
- 抽象与性能的矛盾：高级编程模型（如OpenMP）能提高开发效率，但往往牺牲了性能优化的细粒度控制。而为了榨取硬件极致性能，开发者又不得不使用更底层更复杂的接口（如CUDA）。
- 编译器的局限：很难自动发现并安全地利用程序中复杂的并行性。
- 编程难度高,开发者45%到90%的时间都花在了管理“开销任务”
    - 任务/数据的划分/分配
    - 数据交换
    - 同步和互斥
    - 性能平衡
- 性能可移植性差：为一种硬件（如NVIDIA GPU的CUDA）优化的代码，很难直接迁移到另一种硬件（如AMD GPU或国产芯片）上高效运行。
- 标准与生态的碎片化：HPC领域存在多种编程模型（MPI、OpenMP、CUDA、HIP等），它们各自为政，缺乏统一标准，进一步加剧了软件开发和移植的难度。
- 应对措施：发展性能可移植性编程框架、编译器与硬件架构协同设计、AI辅助编程

## **进程 (Process) 与线程 (Thread)**

- 进程：资源分配的基本单位
    - 程序在计算机中的一次执行过程，是操作系统进行资源分配和调度的独立实体。
    - 具备动态性（有完整生命周期）、独立性（拥有独立地址空间）和并发性（宏观上同时运行）。
- 线程：CPU调度的基本单位
    - 进程内部的最小执行单元，是操作系统进行CPU调度和分派的基本单位
    - 轻量化（创建与切换开销极小）、资源共享（同进程线程共享内存）、独立调度（单线程独立执行）
- 状态流转与调度机制：进程与线程的生命周期均围绕“就绪→运行→阻塞”三大状态动态转换。
    - 就绪态等待系统调度
    - 运行态占用CPU执行指令
    - 阻塞态则因等待I/O或事件暂停。

## **CPU核心 (Core) 与线程 (Thread)**

- CPU核心：物理基石
    - 真正的计算“大脑”，是CPU的物理执行单元
    - 同一时刻单个物理核心仅能执行一个线程指令，是处理所有计算任务的硬件基础。
- 线程：任务载体
    - 软件层面的执行路径与任务流，是操作系统调度的基本单位
    - 线程承载着具体的程序指令，依赖CPU核心的算力来运行和完成。
- 超线程技术（hyperthreading）：将单物理核心模拟为双逻辑核心，利用等待I/O的间隙切换执行线程，大幅减少核心空闲时间，显著提升多任务并发处理效率。

## **并行程度**

- 并行度(Degree of Parallelism, DOP): 同时执行的分进程数。
- 并行粒度(Granularity): 两次并行或交互操作之间所执行的计算负载.
    - 指令级并行
    - 线程级并行
    - 进程级并行
    - 任务级并行
- 并行度与并行粒度大小常互为倒数
    - 增大粒度会减小并行度
    - 增加并行度会增加系统(同步)开销
- 分配原则：使系统大部分时间忙于计算, 而不是闲置或忙于交互。

## **进程的同构性**

- SPMD:各个进程是同构的，多个进程对不同的数据执行相同的代码，常对应并行循环，数据并行结构，单代码
- MPMD:各个进程是异构的，多个进程执行不同的代码（一般是任务并行，或功能并行，或控制并行的同义语），常对应并行块，多代码
- 要为有大量处理器的计算机编写一个完全异构的并行程序是很困难的用MPMD方法执行3个并行任务，用户需写3个程序, 分别编译生成3个可执行程序S1 S2  S3, 用shell脚本将它们加载到3个处理结点上:

run S1 on node1

run S2 on node2

run S3 on node3

S1, S2和S3是顺序语言程序加上进行交互的库调用。

用SPMD程序执行多个并行任务

- if (mynodeID==i) S(i)

因此, 对于可扩展并行机来说, 只要支持SPMD就足够了并行程序设计模型

- 隐式并行（Implicit Parallel）：
    - 程序员用熟悉的串行语言编写相应的串行程序
    - 通过编译器和运行支持系统将串行程序自动转化为并行代码
    - 语义简单，可移植性好
    - 单线程，易于调试和验证正确性
    - 细粒度并行
    - 效率很低

并行程序设计模型

- 数据并行（Data Parallel）：
    - SIMD的自然模型
    - 并行操作于聚合数据结构（数组）
    - 单一地址空间
    - 隐式交互作用
    - 优点：编程相对简单,串并行程序一致
    - 缺点:程序的性能在很大程度上依赖于所用的编译系统及用户对编译系统的了解；并行粒度局限于数据级并行,粒度较小。

并行程序设计模型

- 共享变量(Shared Variable)：
    - SMP, DSM的自然模型
    - 多线程：SPMD, MPMD
    - 单一地址空间
    - 显式同步
    - 隐式数据分布
    - 隐式通信
    - 典型代表：OpenMP（Open Multi-Processing）

9

并行程序设计模型

- 消息传递(Message Passing）：
    - MPP、COW的自然模型
    - 多进程异步并行
    - 多地址空间
    - 显式同步
    - 显式数据映射和负载分配
    - 显式通信
    - 适用于所有并行机，可以与数据并行和共享变量并行混用
    - 典型代表： PVM（Parallel Virtual Machine）、MPI（Message Passing Interface）

## **五种基本的并行化方法**

- 分治并行（Divide and Conquer Parallel）
    - 父进程把负载分割并指派给子进程
    - 子进程并行地完成各自的计算，其计算结果由父进程归并
    - 实际应用中容易导致负载平衡
