## **并行计算的基本概念**

- 并行计算（parallel computing）是使用多个计算资源（多个CPU或多核CPU）去解决可计算问题。
    - 问题被分解成可以被同时解决的离散部分；
    - 每一部分被细分成一系列指令；
    - 每一部分的指令可以在不同的CPU或者CPU核心上同时执行；
- 任何现代高性能计算（High performance computing）和超级计算(Super computing)都离不开使用并行计算技术。

## **并行计算的基本概念**

- 异构并行计算（Heterogeneous parallel computing）：利用不同架构的处理器协同工作，共同完成一个计算任务。它的核心思想是“让专业的硬件做专业的事”，从而突破单一处理器（如仅靠CPU）的性能瓶颈。
    - CPU擅长处理串行任务和分支预测，负责复杂逻辑控制、任务调度、I/O管理；
    - GPU拥有成千上万个核心，擅长向量和矩阵运算，负责大规模数据并行计算。

- 并行执行时间 $Tn = T comput + T paro+ T comm$

$T comput$ 为计算时间； $T paro$ 为并行开销时间； $T comm$ 为相互通信时间。

- 单次浮点数计算时间为 $ns$ 级。

- $T paro$ 包括进程管理（如进程生成、结束和切换等）时间，组操作（如进程组的生成与消亡等）时间和进程查寻（如询问进程的标志、等级、组标志和组大小等）时间。创建一个进程时间为ms级。
- $T comm$ 包括同步时间，通信（如点到点通信、整体通信、读／写共享变量等）时间和聚合操作（如归约、前缀运算等）时间。节点间通信为 $\mu s$ 级。

$T_{comm}=t_{0}+m/r_{\infty }$

$t_{0}$ ：通信启动时间；渐近带宽 $r_{\infty }$ ：传送无限长的消息时的通信速率

- 通信开销的测量：乒--乓方法（Ping-Pong Scheme）节点0发送m个字节给节点1；节点1从节点0接收m个字节后，立即将消息发回节点0。总的时间除以2，即可得到点到点通信时间，也就是执行单一发送或接收操作的时间。

if （my \_node \_id =0）  then /\*发送者\*/

start \_time =second（ ）

send an m-byte message to node 1

receive an m-byte message from node 1

end\_time = second（ ）

total\_time = end\_time – start\_time

communication\_time[i] = total\_time/2

else if （my\_node\_id = 1）  then  /\*接收者\*/

receive an m-byte message from node 0

send an m-byte message to node 0

endif

- 可一般化为热土豆法（Hot-Potato），也称为救火队法（Fire-Brigade) ：   $0\longrightarrow 1\longrightarrow 2\longrightarrow \ldots \longrightarrow n-1\longrightarrow 0$

- 通信开销的表达式

$T_{comm}=t_{0}+m/r_{\infty }$

$t_{0}$ ：通信启动时间；渐近带宽 $r_{\infty }$ ：传送无限长的消息时的通信速率

- 典型的整体通信：
    - 播送（Broadcasting）：处理器0发送m个字节给所有的n个处理器
    - 收集（Gather）：处理0接收所有n个处理器发来在消息，所以处理器0最终接收了mn个字节；
    - 散射（Scatter）：处理器0发送了m个字节的不同消息给所有n个处理器，因此处理器0最终发送了mn个字节；
    - 全交换（Total Exchange）：每个处理器均彼此相互发送m个字节的不同消息给对方，所以总通信量为 $mn2$ 个字节；
    - 循环移位（Circular-shift）：处理器i发送m个字节给处理器i+1，处理器n-1发送m个字节给处理器0，所以通信量为mn个字节。

## 算法级性能评测

- 并行系统的加速比：对于一个给定的应用，并行算法（或并行程序）的执行速度相对于串行算法（或串行程序）的执行速度加快了多少倍。
    - Amdahl定律适用于固定计算负载
    - Gustafson定律适用于可扩展问题
    - Sun Ni定律适用于存储受限问题
- 可扩展性（Scalability）评测标准
    - 等效率度量标准
    - 等速度度量标准
    - 平均延迟度量标准

## Amdahl定律

- $p$ ：处理器数；
- $W$ ：问题规模（计算负载、工作负载，给定问题的总计算量）；
    - $Ws$ 是问题的串行部分； $f = Ws/W$ 是串行部分占比；
    - $WP$ 是问题中可并行化部分； $1-f$ 为可并行部分占比；
    - $Ws +W p =W$ 。
- $Ts$  ：串行执行时间
- $Tp$ ：并行执行时间；
- $S$ ：加速比
- $E=S/p$ ：效率。

## Amdahl定律

- 出发点：
    - 固定的总计算负载；
    - 固定的可并行计算负载分布在多个处理器上。
- 加速公式：

$S\left(p\right)=\frac{W_{s}+W_{p}}{W_{s}+\frac{W_{p}}{p}}=\frac{f+\left(1-f\right)}{f+\frac{1-f}{p}}=\frac{p}{1+f\left(p-1\right)}$

- 加速极限：

$\lim_{p\longrightarrow \infty }S\left(p\right)=\frac{1}{f}$

- 考虑额外开销 $W_{0}$ 的修正公式：

$S^{'}\left(p\right)=\frac{W_{s}+W_{p}}{W_{s}+\frac{W_{p}}{p}+W_{0}}=\frac{f+\left(1-f\right)}{f+\frac{1-f}{p}+\frac{W_{0}}{W}}=\frac{p}{1+f\left(p-1\right)+p\frac{W_{0}}{W}}$

- 修正的加速极限：

$\lim_{p\longrightarrow \infty }S^{'}\left(p\right)=\frac{1}{f+\frac{W_{0}}{W}}$

## Gustafson定律

- 出发点：
    - 在相同的计算时间内增大问题计算规模，提高计算精度。
- 加速公式:

$S\left(p\right)=\frac{W_{s}+pW_{p}}{W_{s}+p\frac{W_{p}}{p}}=f+p\left(1-f\right)$

- 考虑额外开销 $W_{0}$ 的修正公式：

$S^{'}\left(p\right)=\frac{W_{s}+pW_{p}}{W_{s}+W_{p}+W_{0}}=\frac{f+p\left(1-f\right)}{1+\frac{W_{0}}{W}}$

## Sun 和 Ni定律

- 该定律也叫存储受限加速比模型（Memory-Bounded Speedup Model），其出发点为：
    - 在存储空间允许的前提下，尽量增大计算问题的规模以产生更精确的解。
    - $G\left(p\right)$ 反应存储容量增加到 $p$ 倍时并行工作负载的增加量，其具体形式取决于算法和内存访问特性。
- 加速公式 ：

$S\left(p\right)=\frac{W_{s}+G\left(p\right)W_{p}}{W_{s}+G\left(p\right)\frac{W_{p}}{p}}=\frac{f+G\left(p\right)\left(1-f\right)}{f+G\left(p\right)\frac{\left(1-f\right)}{p}}$

- 考虑额外开销 $W_{0}$ 的修正公式：

$S^{'}\left(p\right)=\frac{W_{s}+G\left(p\right)W_{p}}{W_{s}+G\left(p\right)\frac{W_{p}}{p}+W_{0}}=\frac{f+G\left(p\right)\left(1-f\right)}{f+G\left(p\right)\frac{\left(1-f\right)}{p}+\frac{W_{0}}{W}}$

- $G\left(p\right)=1$ 为Amdahl定律； $G\left(p\right)=p$ 为Gustafson定律； $G\left(p\right)>p代表$ 计算机负载比存储要求增加得更快，可以获得比Gustafson定律更高的加速比。

## 实际应用中的加速比

- 通信开销很低的算法可获得接近线性的加速比：比如矩阵相加。
- 类似于二叉树的分治类问题在树的同级可并行执行，但向根逐级推进时，并行度将逐渐减少，只能获得 $p/log_{2}p$ 的加速比。
- 通信密集类的应用问题： $S = 1 / C(p)$
- 超线性加速(Superlinear speedup)：
    - 在某些并行搜索算法中，允许不同的处理器在不同的分枝方向上同时搜索，当某一处理器一旦迅速地找到了解，它就向其余的处理器发出中止搜索的信号，这就会提前取消那些在串行算法中所作的无谓的搜索分枝，从而出现超线性加速现象。
    - 每个处理器均有少量的高速缓存，当某一问题执行在大量的处理器上，而其大多的数据均放在高速缓存中时，总的计算时间趋于减少，如果由于这种高速缓存效应所造成的计算时间下降补偿了由于通信等所造成的额外开销时间，则有可能造成超线性加速现象。
- 绝对加速：最佳并行算法与串行算法
- 相对加速：同一算法在单机和并行机的运行时间

## 可扩放性评测标准

- 并行计算的可扩放性（Scalability）：在确定的应用背景下，计算机系统（或算法或程序等）性能随处理器数的增加而按比例提高的能力。
- 影响加速比的因素
    - 处理器数与问题规模
    - 求解问题中的串行分量
    - 并行处理所引起的额外开销（通信、等待、竞争、冗余操作和同步等）
    - 加大的处理器数超过了算法中的并发程度
- 增加问题的规模有利于提高加速的因素：
    - 较大的问题规模可提供较高的并发度；
    - 额外开销的增加可能慢于有效计算的增加；
    - 算法中的串行分量比例不是固定不变的（串行部分所占的比例随着问题规模的增大而缩小）。
- 增加处理器数会增大额外开销和降低处理器利用率，所以对于一个特定的并行系统（算法或程序），它们能否有效利用不断增加的处理器的能力应是受限的，而度量这种能力就是可扩放性这一指标。

## 可扩放性评测标准

- 可扩放性:调整什么和按什么比例调整
    - 并行计算要调整的是处理数 $p$ 和问题规模 $W$ ，
    - 两者可按不同比例进行调整，此比例关系（可能是线性的，多项式的或指数的等）就反映了可扩放的程度。
- 并行算法和体系结构可扩放性研究的主要目的：
    - 确定解决某类问题用何种并行算法与何种并行体系结构的组合，可以有效地利用大量的处理器；
    - 根据算法在小规模处理机上的运行性能，预测该并行算法当移植到大规模处理机上后运行的性能；
    - 对固定的问题规模，确定在某类并行机上最优的处理器数与可获得的最大的加速比；
    - 用于指导改进并行算法和并行机体系结构，以使并行算法尽可能地充分利用可扩充的大量处理器。
- 目前无一个公认的、标准的和被普遍接受的严格定义和评判可扩放性的标准。

## 等效率度量标准

- 令 $t_{e}^{i}$  和 $t_{o}^{i}$ 分别是并行系统上第 $i$ 个处理器的有用计算时间和额外开销时间（包括通信、同步和空闲等待时间等）

$T_{e}=\sum_{i=0}^{p-1}t_{e}^{i}=T_{s}, T_{0}=\sum_{i=0}^{p-1}t_{0}^{i}$

- $T_{p}$  是 $p$ 个处理器系统上并行算法的运行时间，对于任意 $i$ 显然有 $T_{p}=t_{e}^{i}+t_{0}^{i}$ ，且 $T_{e}+T_{0}=pT_{p}$
- 加速比、效率

$S=\frac{T_{s}}{T_{p}}=\frac{pT_{e}}{T_{e}+T_{0}}=\frac{p}{1+T_{0}/T_{e}},E=\frac{S}{p}=\frac{1}{1+T_{0}/T_{e}}$

- 如果问题规模保持不变，处理器数 $p$ 增加，额外开销 $T_{0}$ 增大，效率 $E$ 下降。为了维持一定的效率，当处理数p增大时，需要相应地增大问题规模。由此定义函数 $f_{E}\left(p\right)$ 为问题规模随处理器数p变化的函数，为等效率函数（ISO-efficiency Function, Kumar1987）。

## 等速度度量标准

- $p$ 表示处理器个数， $W$ 表示要求解问题的工作量或称问题规模（在此可指浮点操作个数）， $T$ 为并行执行时间，定义并行计算的速度 $V=\frac{W}{T}$
- $p$ 个处理器的并行系统的平均速度定义为

$\overbar{V}=\frac{V}{p}=\frac{W}{Tp}$

- 令 $W'$ 表示当处理数从 $p$ 增大到 $p'$ 时，为了保持整个系统的平均速度不变所需执行的工作量，则可得到处理器数从 $p$ 到 $p'$ 时平均速度可扩放度量标准

$\Psi \left(p,p^{'}\right)=\frac{W/p}{W'/p'}=\frac{p^{'}W}{pW'}$

保持平均速度不变则有

$\Psi \left(p,p^{'}\right)=\frac{T}{T'}$

- 缺点：某些非浮点运算可能造成性能的变化

## 平均延迟度量标准

- 处理数从 $p$ 增大到 $p'$ 时，维持并行效率不变，平均延迟（ $\overbar{L}$ ）可扩放性度量标准定义为

$\Psi \left(E,p,p^{'}\right)=\frac{\overbar{L}\left(W,p\right)}{\overbar{L}\left(W',p'\right)}$

## 高性能计算基准测试程序

- Linpack (https://top500.org/project/linpack/，TOP500排名依据)
    - 核心算法：求解一个稠密线性方程组 $Ax = b$ 。其标准操作是采用列主元高斯消元法进行LU分解，计算量必须严格满足 $\frac{ 2}{3} n3 + O(n2)$ 次双精度浮点运算。
    - 测试目的：旨在衡量系统在计算密集型任务上的理论峰值浮点性能（FLOPS）。由于问题规整，系统能达到非常高的效率，因此其结果常被用作衡量系统峰值性能的标尺。
    - 特点：允许用户调整问题规模并深度优化软件，以追求最高性能。它主要考验处理器的理论计算能力。

## 高性能计算基准测试程序

- 重要补充：HPCG（High Performance Conjugate Gradients, https://www.hpcg-benchmark.org/）
    - 核心算法：使用预处理共轭梯度法来求解一个稀疏线性系统。其核心计算操作包括稀疏矩阵向量乘、向量更新、全局点积以及作为预条件子的对称高斯-赛德尔平滑等。
    - 测试目的：旨在模拟更接近真实科学计算应用的计算和访存模式，重点考验系统的内存带宽、网络延迟和整体平衡性。
    - 特点：HPCG的性能通常远低于HPL的峰值。它更多反映了系统在解决非规则、数据密集型问题时的实际性能，对系统设计者更有参考价值。
- HPL-AI / HPL-MxP（AI与混合精度, https://hpl-mxp.org/）：这是为适应AI计算趋势而设计的基准。它通过混合精度算法（如使用FP16/FP32）来求解线性方程组，旨在评估系统在AI相关任务上的性能，代表了HPC与AI融合的趋势。
