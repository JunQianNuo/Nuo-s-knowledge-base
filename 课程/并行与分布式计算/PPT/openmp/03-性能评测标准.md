# 并行计算性能评测标准

本讲依次讨论并行计算的基本概念、并行机的性能指标、加速比性能定律，以及可扩展性评测标准，最后介绍高性能计算基准测试程序。

## 1. 并行计算的基本概念

### 1.1 串行计算

**串行计算（serial computing）**将问题分解成离散的指令序列，并按顺序逐条执行。从程序执行模型来看，后续步骤需要等待前面的步骤完成。

![串行计算：一个问题的指令序列由一个 CPU 顺序执行](assets/03-性能评测标准/slide-02-image-01.png)

串行程序按顺序描述计算步骤。现代 CPU 的流水线、超标量等机制仍可能使多条指令在硬件内部重叠执行。

### 1.2 并行编程的历史背景

Gill 在 1958 年对并行编程的讨论指出：

> “……并行计算并不是什么新的思想，只是将它扩展应用于计算机而已”。作者也不认为这种扩展应用会存在什么无法克服的困难。但也不要期待有效的并行编程方法与技术能够在一夜之间诞生。期间还需要有许多的工作和实验要做。毕竟，今天的编程技术（串行）是若干年来艰苦的探索才取得的。现在编程工作似乎成了一种令人单调乏味的工作，事实上，并行编程的出现将会使编程工作者们重新恢复探索精神……

出处：Gill, S. (1958), “Parallel Programming”, *The Computer Journal*, vol. 1, April, pp. 2–10。

Peter S. Pacheco 的 *Parallel Programming with MPI* 是学习 MPI 并行编程的参考书。

### 1.3 并发与并行

**并发（concurrency）**指多个任务在同一时间段内推进，它们可以交替使用同一计算资源。**并行（parallelism）**指多个任务在不同计算资源上同时执行。

可以用两条排队队列和咖啡机说明区别：一台咖啡机处理两条队列时，可以让两条队列交替得到服务；两台咖啡机则可以同时服务两条队列。

![并发：一台咖啡机处理两条等待队列](assets/03-性能评测标准/slide-04-image-01.png)

![并行：两台咖啡机同时处理两条等待队列](assets/03-性能评测标准/slide-04-image-02.png)

### 1.4 并行计算与多核架构

**并行计算（parallel computing）**使用多个计算资源，例如多个 CPU 或多核 CPU，协同解决可计算问题。其基本过程为：

1. 将问题分解成可以同时求解的离散部分。
2. 将每一部分细分为一系列指令。
3. 将不同部分的指令分配给不同 CPU 或 CPU 核心，同时执行。

现代高性能计算（high performance computing）和超级计算（supercomputing）广泛采用并行计算技术。

![并行计算：问题分解后由多个 CPU 同时执行](assets/03-性能评测标准/slide-05-image-01.png)

下图展示多 CPU、多物理核心架构：每个核心拥有寄存器、算术逻辑单元等计算资源，核心及处理器之间通过缓存、总线和主存协作。

![多 CPU、多物理核心与缓存、主存结构](assets/03-性能评测标准/slide-05-image-02.png)

### 1.5 异构并行计算

**异构并行计算（heterogeneous parallel computing）**利用不同架构的处理器协同完成计算任务。核心思想是根据硬件特点分配适合的工作，从而突破单一处理器的性能瓶颈。

- **CPU**：适合串行任务和复杂控制逻辑，承担任务调度、分支处理、I/O 管理等工作。
- **GPU**：具有大量计算核心，适合向量、矩阵运算及大规模数据并行计算。

## 2. 并行机的基本性能指标

### 2.1 性能参数表

以下表格中的 $n$ 表示处理器物理核心数；后文加速比模型中的 $p$ 也表示处理器数。

| 名称 | 符号或定义 | 含义 | 单位 |
| --- | --- | --- | --- |
| 机器规模 | $n$ | 处理器物理核心数目 | 无量纲 |
| 时钟速率 | $f$ | 时钟周期长度的倒数 | Hz |
| 工作负载 | $W$ | 计算操作数目 | Flop |
| 顺序执行时间 | $T_1$ | 程序在单处理器上的运行时间 | s |
| 并行执行时间 | $T_n$ | 程序在 $n$ 个处理器上的运行时间 | s |
| 速度 | $R_n=W/T_n$ | 每秒完成的浮点运算次数 | FLOPS |
| 加速比 | $S_n=T_1/T_n$ | 相对于串行执行的加速程度 | 无量纲 |
| 效率 | $E_n=S_n/n$ | 处理器数量转化为加速的程度 | 无量纲 |
| 峰值速度 | $R_{\mathrm{peak}}=nR'_{\mathrm{peak}}$ | 所有处理器理论峰值速度之和，$R'_{\mathrm{peak}}$ 为单个同类型处理器的峰值速度 | FLOPS |
| 利用率 | $U=R_n/R_{\mathrm{peak}}$ | 可达速度与理论峰值速度之比 | 无量纲 |
| 通信延迟 | $t_0$ | 传送零字节或单字消息的启动时间 | $\mu\mathrm{s}$ |
| 渐近带宽 | $r_\infty$ | 传送长消息时趋近的通信速率 | MB/s |

**Flop** 表示浮点运算次数，**FLOPS** 表示每秒浮点运算次数；**MFLOPS** 表示每秒百万次浮点运算，即 $10^6$ FLOPS。加速比效率 $E_n$ 和相对于硬件峰值的利用率 $U$ 是不同指标。

### 2.2 理论峰值与实测速度

- $R_{\mathrm{peak}}$：理论峰值速度。
- $R_{\max}$：基准测试得到的实测最大速度。

### 2.3 工作负载与浮点运算计数

**工作负载 $W$**是计算操作的数量。衡量程序工作量或计算成本时，可以采用执行时间、所执行的指令数、所完成的浮点运算数等指标。

**经过时间（elapsed time）**指应用程序从开始到结束所经过的实际时间，包括 CPU 计算、存储器访问、磁盘和 I/O 操作，以及操作系统开销等。

一次浮点加法、减法、乘法或除法通常分别计为 1 Flop。比较、类型转换和超越函数的开销需要另行说明，不能仅凭指令数量推算统一的浮点运算次数。

建立计算成本模型时，也可以选用加权计数。例如，下面的示例权重用简单算术操作作为成本基准：

| 操作 | 等效计算成本（示例权重） |
| --- | ---: |
| 加法、减法、乘法、比较、数据类型转换等 | 1 |
| 除法、开平方 | 4 |
| 正弦、余弦、指数类运算 | 8 |

这些权重用于示意成本估算，其数值应根据实际硬件和实现调整。加权成本与 FLOP 计数是不同口径；比较性能结果时应确认采用相同的计数方法。

**FMA（fused multiply-add，融合乘加）**将乘法和加法融合，完成

$$
D=A\times B+C.
$$

图中乘积保留中间精度，再与 $C$ 相加。按通常将一次乘法和一次加法分别计数的口径，一次标量 FMA 对应 2 次浮点运算。

![FMA：乘积保留中间精度后与 C 相加](assets/03-性能评测标准/slide-10-image-01.png)

### 2.4 并行执行时间的组成

并行执行时间可以分解为

$$
T_n=T_{\mathrm{comput}}+T_{\mathrm{paro}}+T_{\mathrm{comm}},
$$

其中：

- $T_{\mathrm{comput}}$：有用计算时间。
- $T_{\mathrm{paro}}$：并行管理开销，包括进程生成、结束和切换，进程组生成与消亡，以及查询进程标志、等级、组标志和组大小等操作。
- $T_{\mathrm{comm}}$：通信及相关开销，包括同步、点到点通信、整体通信、读写共享变量，以及归约、前缀运算等聚合操作。

单次浮点运算的 ns 级、创建进程的 ms 级、节点间通信的 $\mu\mathrm{s}$ 级可以作为数量级示例，说明管理和通信成本可能明显大于单次计算成本。具体数值需要在目标系统上测量。

常用的消息通信时间模型为

$$
T_{\mathrm{comm}}(m)=t_0+\frac{m}{r_\infty},
$$

其中 $m$ 是消息长度，$t_0$ 为通信启动时间，$r_\infty$ 为传送无限长消息时趋近的通信速率。计算时，$m$ 和 $r_\infty$ 的字节单位必须一致。

### 2.5 通信开销的测量：乒乓法

**乒乓法（ping-pong scheme）**的步骤是：节点 0 向节点 1 发送 $m$ 字节消息；节点 1 接收后立即将消息发回节点 0。测得往返时间后除以 2，估计一次单向点到点通信的时间。

```text
if my_node_id == 0 then              /* 发送者 */
    start_time = second()
    send an m-byte message to node 1
    receive an m-byte message from node 1
    end_time = second()
    total_time = end_time - start_time
    communication_time[i] = total_time / 2
else if my_node_id == 1 then         /* 接收者 */
    receive an m-byte message from node 0
    send an m-byte message to node 0
endif
```

这里将往返时间平分，需要两个方向的通信成本近似相同。

乒乓法可以推广为**热土豆法（hot-potato）**，也称**救火队法（fire-brigade）**，让消息沿处理器环依次传递：

$$
0\longrightarrow1\longrightarrow2\longrightarrow\cdots
\longrightarrow n-1\longrightarrow0.
$$

### 2.6 典型整体通信

点到点通信仍采用模型 $T_{\mathrm{comm}}=t_0+m/r_\infty$。整体通信由多个这样的传输过程组成，其时间还取决于通信算法和网络结构。

设 $n\ge2$，每条逻辑消息长度为 $m$ 字节，只统计不同处理器之间传递的数据，消息量如下：

| 通信操作 | 操作含义 | 跨处理器逻辑数据量 |
| --- | --- | --- |
| 播送（broadcast） | 处理器 0 将同一条消息分发到其余 $n-1$ 个处理器 | $m(n-1)$ 字节 |
| 收集（gather） | 其余处理器将各自消息汇集到处理器 0 | $m(n-1)$ 字节；根处理器含自身数据共拥有 $mn$ 字节 |
| 散射（scatter） | 处理器 0 向其余处理器分配不同消息块 | $m(n-1)$ 字节；含根处理器保留块的总数据为 $mn$ 字节 |
| 全交换（total exchange） | 每个处理器向其余 $n-1$ 个处理器各发送一条消息 | $mn(n-1)$ 字节 |
| 循环移位（circular shift） | 处理器 $i$ 向 $(i+1)\bmod n$ 发送消息 | $mn$ 字节 |

逻辑数据量与网络中的实际链路流量不同；后者还受路由、消息转发和通信算法影响。总字节量不能直接替代通信运行时间。

## 3. 算法级加速比性能定律

### 3.1 加速比与模型的适用范围

对于给定应用，**加速比**衡量并行算法或程序相对于串行算法或程序快了多少倍：

$$
S(p)=\frac{T_s}{T_p},\qquad E(p)=\frac{S(p)}p.
$$

这里 $T_s$ 为串行执行时间，$T_p$ 为使用 $p$ 个处理器时的并行执行时间。

| 定律 | 研究前提 |
| --- | --- |
| Amdahl 定律 | 固定计算负载 |
| Gustafson 定律 | 在固定计算时间内扩展问题规模 |
| Sun–Ni 定律 | 在存储容量约束下扩展问题规模 |

加速比以外，还可以使用等效率、等速度和平均延迟等标准研究系统的可扩展性。

以下模型使用的基本符号为：

- $p$：处理器数。
- $W$：基准问题的总工作负载。
- $W_s$：串行部分的工作负载。
- $W_p$：可以并行化的部分的工作负载，下标 $p$ 在此表示并行部分。
- $f=W_s/W$：串行部分占比。
- $1-f=W_p/W$：可并行部分占比。

因此

$$
W=W_s+W_p.
$$

推导时假定各处理器计算能力相同，并将工作负载按相同单处理器速度换算为执行时间。修正公式中的 $W_0$ 表示额外开销对应的等效工作量。

### 3.2 Amdahl 定律：固定工作负载

#### 基本公式

Amdahl 定律保持总计算负载 $W$ 不变，把固定的可并行计算部分分配到多个处理器。理想情况下，串行部分仍花费 $W_s$ 对应的时间，并行部分的时间缩短为 $W_p/p$。因此

$$
\begin{aligned}
S(p)
&=\frac{W_s+W_p}{W_s+W_p/p}\\
&=\frac{f+(1-f)}{f+(1-f)/p}\\
&=\frac{p}{1+f(p-1)}.
\end{aligned}
$$

当 $f>0$ 时，加速极限为

$$
\lim_{p\to\infty}S(p)=\frac1f.
$$

固定规模的问题中，即使处理器数不断增加，也无法消除串行部分形成的时间下限。

![Amdahl 模型：总工作负载固定，串行和可并行部分的总量固定](assets/03-性能评测标准/slide-17-image-01.png)

![Amdahl 模型：并行执行时间随处理器数增加而缩短，但串行时间保持不变](assets/03-性能评测标准/slide-17-image-02.png)

#### 考虑额外开销

增加额外开销 $W_0$ 后，修正加速比为

$$
\begin{aligned}
S'(p)
&=\frac{W_s+W_p}{W_s+W_p/p+W_0}\\
&=\frac{f+(1-f)}{f+(1-f)/p+W_0/W}\\
&=\frac{p}{1+f(p-1)+pW_0/W}.
\end{aligned}
$$

若 $W_0/W$ 在该模型中保持不变，且分母极限非零，则

$$
\lim_{p\to\infty}S'(p)=\frac{1}{f+W_0/W}.
$$

实际额外开销可能随 $p$ 变化，应先建立开销模型，再求修正加速比的极限。

#### 1024 个处理器的示例

令 $p=1024$，有

$$
S(1024)=\frac{1024}{1+1023f}.
$$

| 串行比例 $f$ | 加速比（近似值） |
| --- | ---: |
| 0% | 1024 |
| 1% | 91.2 |
| 2% | 47.7 |
| 3% | 32.3 |
| 4% | 24.4 |
| 100% | 1 |

![Amdahl 定律下 1024 个处理器的加速比与串行比例关系](assets/03-性能评测标准/amdahl-p1024.png)

### 3.3 Gustafson 定律：固定计算时间

Gustafson 定律的出发点是在相同的计算时间内扩大问题规模，提高计算精度。保持串行部分为 $W_s$，将可并行工作负载从 $W_p$ 扩展为 $pW_p$，使每个处理器仍承担 $W_p$ 的并行工作。于是

$$
\begin{aligned}
S(p)
&=\frac{W_s+pW_p}{W_s+pW_p/p}\\
&=\frac{W_s+pW_p}{W_s+W_p}\\
&=f+p(1-f)\\
&=p-(p-1)f.
\end{aligned}
$$

这里的 $f=W_s/(W_s+W_p)$ 以基准工作负载归一化，也对应无开销情况下并行运行时间中的串行比例。由于工作负载已经扩展，它不能直接视为扩展问题在串行运行时的串行比例。

![Gustafson 模型：工作负载随处理器数增加而增大](assets/03-性能评测标准/slide-19-image-01.png)

![Gustafson 模型：扩展工作负载后，并行执行时间保持不变](assets/03-性能评测标准/slide-19-image-02.png)

考虑额外开销后，修正公式为

$$
S'(p)
=\frac{W_s+pW_p}{W_s+W_p+W_0}
=\frac{f+p(1-f)}{1+W_0/W},
\qquad W=W_s+W_p.
$$

对于 1024 个处理器，无额外开销时有

$$
S(1024)=1024-1023f.
$$

| 串行比例 $f$ | 扩展规模加速比（近似值） |
| --- | ---: |
| 0% | 1024 |
| 1% | 1013.8 |
| 2% | 1003.5 |
| 3% | 993.3 |
| 4% | 983.1 |

![Gustafson 定律下 1024 个处理器的扩展规模加速比](assets/03-性能评测标准/gustafson-p1024.png)

Amdahl 与 Gustafson 模型的差别来自所固定的量和比较的问题规模不同。

### 3.4 Sun–Ni 定律：存储受限模型

Sun–Ni 定律也称**存储受限加速比模型（memory-bounded speedup model）**。其出发点是在存储空间允许的前提下，尽量增大计算问题的规模，以获得更精确的解。

令 $G(p)$ 表示存储容量增加到 $p$ 倍时，可并行工作负载相对于基准的增长倍数。其形式取决于算法及其存储需求。于是

$$
\begin{aligned}
S(p)
&=\frac{W_s+G(p)W_p}{W_s+G(p)W_p/p}\\
&=\frac{f+G(p)(1-f)}{f+G(p)(1-f)/p}.
\end{aligned}
$$

考虑额外开销后，有

$$
\begin{aligned}
S'(p)
&=\frac{W_s+G(p)W_p}{W_s+G(p)W_p/p+W_0}\\
&=\frac{f+G(p)(1-f)}{f+G(p)(1-f)/p+W_0/W}.
\end{aligned}
$$

该模型包含两个特殊情形：

- $G(p)=1$：退化为 Amdahl 定律。
- $G(p)=p$：退化为 Gustafson 定律。
- $G(p)>p$：计算负载比存储容量增长得更快，在相同模型参数下可以获得高于 Gustafson 模型的加速比。

![Sun–Ni 存储受限模型中的工作负载与执行时间变化](assets/03-性能评测标准/slide-21-image-01.png)

### 3.5 实际应用中的加速比

不同算法的计算结构和通信需求，会形成不同的加速行为。

1. **通信开销很低的算法**可能获得接近线性的加速比。例如矩阵相加的各元素运算可以独立执行。
2. **二叉树式分治问题**可以在同一层并行执行，但逐层向根推进时，可并行任务数量减少。某些工作量为 $\Theta(p)$、并行时间为 $\Theta(\log_2 p)$ 的树形计算，可获得 $\Theta(p/\log_2 p)$ 的加速比；具体结果仍取决于树结构、各层工作量和实现。
3. **通信密集型应用**受通信开销限制。若 $T_p$ 主要由通信时间 $T_{\mathrm{comm}}(p)$ 决定，则 $S(p)\approx T_s/T_{\mathrm{comm}}(p)$；增加处理器数未必能继续缩短执行时间。

**超线性加速（superlinear speedup）**是指实测加速比超过处理器数，即 $S(p)>p$。两种可能原因是：

- **并行搜索提前结束**：不同处理器同时搜索不同分支，某个处理器较早找到解后通知其他处理器停止，从而避免串行搜索原本需要经过的一些无效分支。
- **缓存效应**：数据分配到更多处理器后，更多数据能够放入各处理器的高速缓存。若由此减少的存储访问时间足以补偿通信等开销，就可能出现超线性加速。

比较加速比时，还应说明基准算法：

- **绝对加速比**：比较最佳串行算法与并行算法的运行时间。
- **相对加速比**：比较同一算法在单处理器和多个处理器上的运行时间。

## 4. 可扩展性评测标准

### 4.1 可扩展性的含义与影响因素

**可扩展性（scalability）**指在确定的应用背景下，计算机系统、算法或程序的性能随处理器数增加而按比例提高的能力。

影响加速比的主要因素包括：

- 处理器数与问题规模。
- 求解问题中的串行分量。
- 并行处理带来的通信、等待、竞争、冗余操作和同步等额外开销。
- 处理器数超过算法能够提供的并发程度。

扩大问题规模可能提高加速效果，因为较大的问题提供更多并发任务；额外开销的增长可能慢于有效计算量的增长；某些算法的串行部分比例也可能随着问题规模扩大而减小。

增加处理器数通常会增加额外开销，并可能降低处理器利用率。可扩展性评测需要回答：一个特定的并行系统能否有效利用持续增加的处理器。

### 4.2 调整什么，以及按什么比例调整

研究可扩展性时，需要同时考虑**处理器数 $p$**和**问题规模 $W$**。保持某项性能指标时，问题规模应随处理器数以怎样的比例增长，反映了系统的扩展能力；这种关系可能是线性的、多项式的，也可能是指数的。

并行算法与体系结构可扩展性研究的主要目的为：

1. 确定解决某类问题时，哪种算法与体系结构的组合可以有效利用大量处理器。
2. 根据小规模系统上的运行性能，预测算法迁移到大规模系统后的表现。
3. 对固定问题规模，确定最优处理器数与可获得的最大加速比。
4. 指导算法和体系结构的改进，使算法充分利用可增加的处理器资源。

判断可扩展性需要具体的应用背景和度量标准，不能仅靠一个指标作出全面判断。下面介绍三种度量。

### 4.3 等效率度量

令第 $i$ 个处理器的有用计算时间为 $t_e^{(i)}$，额外开销时间为 $t_o^{(i)}$。额外开销包括通信、同步、空闲等待等。定义总有用计算时间与总额外开销时间：

$$
T_e=\sum_{i=0}^{p-1}t_e^{(i)}=T_s,
\qquad
T_o=\sum_{i=0}^{p-1}t_o^{(i)}.
$$

在这一模型中，把每个处理器在整体运行区间内未进行有用计算的时间都计入额外开销，故

$$
T_p=t_e^{(i)}+t_o^{(i)},
\qquad
T_e+T_o=pT_p.
$$

因此

$$
\begin{aligned}
S
&=\frac{T_s}{T_p}
=\frac{pT_e}{T_e+T_o}
=\frac{p}{1+T_o/T_e},\\
E
&=\frac{S}{p}
=\frac{1}{1+T_o/T_e}.
\end{aligned}
$$

这里 $t_o$、$T_o$ 表示额外开销，$t_0$ 表示通信启动时间。模型中的 $T_e=T_s$ 假定总有用工作与串行基准一致。

问题规模固定时，增加 $p$ 往往使 $T_o$ 增大，从而使效率下降。若要保持固定效率 $E$，就需要相应增加有用工作量，使

$$
\frac{T_o}{T_e}=\frac1E-1
$$

保持不变。于是定义**等效率函数**

$$
W=f_E(p),
$$

表示为维持给定效率，问题规模需要随处理器数怎样增长。这一度量称为 isoefficiency function。

![等效率函数：不同算法为维持效率所需的问题规模增长曲线](assets/03-性能评测标准/slide-26-image-01.png)

图中，曲线 1 具有很好的扩展性，曲线 2 可以扩展，曲线 3 的扩展性很差。维持相同效率所需的问题规模增长越慢，越容易在实际资源条件下扩展。

等效率度量的优点是简单、可定量计算，通常只需较少参数；缺点是有时无法得到可计算的 $T_o(W,p)$ 模型。

### 4.4 等速度度量

令 $W$ 表示工作量，例如浮点操作次数；$T$ 表示并行执行时间。系统的计算速度定义为

$$
V=\frac WT.
$$

$p$ 个处理器的平均速度，即每个处理器对应的有效速度，为

$$
\widehat V=\frac Vp=\frac{W}{Tp}.
$$

处理器数由 $p$ 增加到 $p'$ 时，为保持平均速度不变，将工作量增大到 $W'$。平均速度可扩展性度量定义为

$$
\Psi(p,p')
=\frac{W/p}{W'/p'}
=\frac{p'W}{pW'}.
$$

由

$$
\frac{W}{Tp}=\frac{W'}{T'p'}
$$

可得

$$
\Psi(p,p')=\frac T{T'}.
$$

以下两组图区分固定规模加速与等速度扩展：

![固定问题规模时，处理器数增加使执行时间缩短](assets/03-性能评测标准/slide-28-image-01.png)

![保持平均速度时，问题规模扩展可能使执行时间增加](assets/03-性能评测标准/slide-28-image-02.png)

第一组关注“问题规模不变，执行时间变短”；第二组关注“平均速度不变，随着问题规模扩大，执行时间可能加长”。

等速度度量的优点是直观地使用易测量的性能速度指标；缺点是浮点操作计数可能无法体现非浮点操作对性能的影响。

### 4.5 平均延迟度量

处理器数从 $p$ 增大到 $p'$，调整工作量从 $W$ 到 $W'$，并维持并行效率 $E$ 不变。以平均延迟 $\widehat L$ 定义可扩展性度量：

$$
\Psi(E,p,p')
=\frac{\widehat L(W,p)}{\widehat L(W',p')}.
$$

下图把各处理器的执行区间分解为运行时间、开销延迟，以及启动前和结束后的空闲时间。整体并行执行时间由最晚完成的处理器决定。

![各处理器的运行时间、开销延迟与空闲时间](assets/03-性能评测标准/slide-29-image-01.png)

- 白色部分：启动前与结束后的空闲时间。
- 灰色部分：运行时间 $T_i$。
- 黑色部分：开销延迟 $L_i$。

平均延迟度量能够在更低层次衡量机器性能，但需要特定的软件与硬件支持才能获得平均延迟数据。

## 5. 高性能计算基准测试程序

### 5.1 Linpack / HPL

[Linpack / HPL](https://top500.org/project/linpack/) 是 TOP500 排名采用的测试依据。

**核心算法**是求解稠密线性方程组

$$
Ax=b,
$$

通过带主元的高斯消元进行 LU 分解。主要计算量为

$$
\frac23n^3+O(n^2)
$$

次双精度浮点运算。此处 $n$ 是矩阵阶数，与前文表示处理器数的 $n$ 不同。

**测试目的**是衡量系统在规整、计算密集型线性代数任务上的实测浮点性能。由于计算结构规整，系统可以达到较高效率，结果常被用作高性能计算能力的代表指标。

**特点**是允许调整问题规模并优化软件，以获得高性能，重点考察计算能力及相应实现效率。

基准测试得到的是实测性能 $R_{\max}$，理论峰值 $R_{\mathrm{peak}}$ 则由硬件规格计算。

### 5.2 HPCG

**[HPCG（High Performance Conjugate Gradients）](https://www.hpcg-benchmark.org/)** 是 HPL 的补充基准。

**核心算法**使用预处理共轭梯度法求解稀疏线性系统，核心计算操作包括：

- 稀疏矩阵向量乘。
- 向量更新。
- 全局点积。
- 作为预条件子的对称高斯–赛德尔平滑。

**测试目的**是模拟科学计算应用中的计算和访存模式，重点考察内存带宽、网络延迟和系统整体平衡性。

**特点**是其 FLOPS 结果通常明显低于 HPL 测得的结果，因为计算和数据访问模式不同。它从另一角度反映稀疏、数据访问密集型计算的运行能力，可为系统设计提供参考。

### 5.3 HPL-AI / HPL-MxP

[HPL-MxP](https://hpl-mxp.org/) 是使用混合精度求解线性方程组的基准。

这类基准通过混合精度算法，例如结合 FP16、FP32 等计算精度，求解线性方程组，用于评估混合精度计算能力。它体现了 HPC 与 AI 计算中混合精度技术的联系。
