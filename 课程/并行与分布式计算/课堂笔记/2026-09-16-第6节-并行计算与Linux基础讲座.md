## 二、并行程序设计为什么困难

硬件核心数快速增长，但编译器很难自动发现复杂程序中安全、有效的并行性。开发者往往需要显式处理：

- 任务和数据的划分、分配；
- 进程或线程之间的数据交换；
- 同步、互斥和竞态条件；
- 负载均衡；
- 通信、调度和线程切换等开销；
- 不同 CPU、GPU 和加速器之间的性能可移植性。

OpenMP 等高级模型能降低开发难度，但会减少底层控制；CUDA 等底层接口能深入优化，却带来更高复杂度和更差的可移植性。

## 三、进程、线程与 CPU 核心

| 概念 | 核心含义 | 资源关系 |
|:--|:--|:--|
| 进程 | 程序的一次独立执行，是资源分配的基本单位 | 通常拥有独立地址空间，隔离性强 |
| 线程 | 进程内的执行路径，是 CPU 调度的基本单位 | 同一进程的线程共享地址空间和多数资源 |
| 物理核心 | 真正执行机器指令的硬件单元 | 决定主要计算能力 |
| 逻辑核心 | 超线程等技术暴露给系统的执行上下文 | 利用流水线空隙提高吞吐，不等于增加同等物理算力 |

进程或线程通常在就绪、运行和阻塞状态之间转换。线程创建和切换开销较小，但共享内存会引入数据竞争；进程隔离更好，通信成本通常更高。

## 四、并行度、粒度与开销

- **并行度**：同一时刻参与计算的任务、线程或进程数量。
- **并行粒度**：两次通信或同步之间，每个执行单元承担的计算量。

粒度过细时，并行度虽高，但同步和通信占比会上升；粒度过粗时，任务数量不足，又可能让部分核心空闲。设计目标是让系统大部分时间做有效计算，而不是等待或交互。

## 五、SPMD、MPMD 与并行程序设计模型

### 1. SPMD 与 MPMD

- **SPMD**：单程序、多数据。各进程运行同一份代码，通过进程编号处理不同数据，是可扩展并行中的主流结构。
- **MPMD**：多程序、多数据。不同进程执行不同代码，适合任务或功能异构，但部署和维护更复杂。

SPMD 并不表示每个进程在每一时刻执行完全相同的语句；程序可根据进程编号进入不同分支。

### 2. 四类设计模型

| 模型 | 地址空间与通信 | 特点 |
|:--|:--|:--|
| 隐式并行 | 编译器从串行代码提取并行性 | 易写、易验证，但复杂并行性难自动发现 |
| 数据并行 | 对数组等聚合数据执行相同操作 | 适合 SIMD，表达简洁，受编译系统影响较大 |
| 共享变量 | 单一地址空间，隐式通信、显式同步 | 典型代表 OpenMP，适合共享内存节点 |
| 消息传递 | 多地址空间，显式发送、接收和同步 | 典型代表 MPI，适合分布式内存并可与 OpenMP 混合 |

混合并行常在单个节点内部使用 OpenMP 线程，在节点之间使用 MPI 进程。

## 六、五种基本并行化范式

| 范式 | 组织方式 | 主要风险或限制 |
|:--|:--|:--|
| 相并行 | 每一相内部独立计算，相与相之间统一通信和同步 | 相边界会形成等待，计算与通信难重叠 |
| 主从并行 | 主进程分配任务，工作进程计算并回传 | 主进程容易成为串行瓶颈 |
| 分治并行 | 递归拆分子问题，并行求解后归并 | 子问题不均会导致负载不平衡 |
| 流水线并行 | 不同处理器负责不同阶段，多个任务重叠推进 | 吞吐受最慢阶段限制，需要稳定任务流 |
| 工作池并行 | 空闲工作者从任务池动态领取任务 | 负载均衡较好，不适合强依赖任务 |

选择范式时应先识别任务依赖、数据位置和负载差异，再决定静态划分还是动态调度。

## 七、Linux、内核与 Shell

Linux 在服务器和高性能计算中常见，主要原因包括开放生态、稳定性、可定制性和良好的自动化能力。

- **内核**管理 CPU、内存、磁盘、设备和进程等资源。
- **Shell**是用户与操作系统交互的命令解释环境，可组合命令形成可重复执行的脚本。
- 图形桌面不是 Linux 内核本身；服务器即使没有图形界面，也可通过 Shell 完成管理和开发。

## 八、课堂演示的基础命令

| 意图 | 命令示例 | 说明 |
|:--|:--|:--|
| 查看当前位置 | `pwd` | 输出当前工作目录 |
| 查看目录内容 | `ls`、`ls -l` | `-l` 显示详细信息 |
| 切换目录 | `cd path`、`cd ..` | 分别进入目录、返回上一级 |
| 创建目录 | `mkdir demo` | 新建文件夹 |
| 创建空文件 | `touch a.txt` | 文件存在时会更新时间戳 |
| 复制 | `cp src dst`、`cp -r dir1 dir2` | 复制文件或递归复制目录 |
| 移动或改名 | `mv old new` | 目标可为新路径或新名称 |
| 删除 | `rm file`、`rm -r dir` | 删除通常不进入回收站 |
| 建立软链接 | `ln -s target link` | 类似快捷方式，保存目标路径 |
| 定位文件或程序 | `locate name`、`whereis cmd` | `locate` 依赖索引数据库 |

> [!warning] 删除命令必须谨慎
> 执行 `rm` 或 `rm -r` 前先用 `pwd`、`ls` 核对当前目录和目标；不要对不确定的绝对路径、通配符或系统目录执行递归删除。

## 九、易错点与练习建议

> [!warning] 易错点
> - 线程是软件执行单元，核心是硬件资源，二者不是同一概念。
> - 超线程提升的是资源利用率，通常不能带来两倍算力。
> - 共享内存不等于自动安全，读写共享数据仍需同步。
> - MPI 的显式通信更复杂，但可跨节点扩展；OpenMP 通常局限于共享内存节点。
> - 并行度越高不代表一定越快，必须同时计算通信与同步开销。

- 在个人目录建立练习文件夹，依次练习 `pwd`、`ls`、`cd`、`mkdir`、`touch`、`cp`、`mv` 和软链接。
- 用任务管理器或系统监视工具观察一个多线程程序对应的进程、线程和 CPU 使用率。
- 为“数组求和”分别设计相并行、分治归约和工作池方案，比较各自的同步点。
