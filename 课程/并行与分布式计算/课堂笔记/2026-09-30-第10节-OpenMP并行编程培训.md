## 二、parallel for

对各次迭代相互独立的规范循环，可写：

    #pragma omp parallel for
    for (int i = 0; i < n; ++i) {
        a[i] = b[i] + c[i];
    }

它等价于创建并行域并在其中用 `omp for` 分配循环迭代。运行时把迭代空间分给线程，程序员不再手动写 `i += thread_count`。

> [!warning] 循环变量通常自动私有
> OpenMP 工作共享循环的迭代变量 `i` 具有预定的 private 属性，不必重复声明。真正需要检查的是循环体中的临时变量、共享数组和累加变量。临时量最安全的写法是在循环体内部定义；共享累加应使用 `reduction`、`atomic` 或其他同步。

例如积分求和宜写成：

    double sum = 0.0;

    #pragma omp parallel for reduction(+:sum)
    for (long i = 1; i <= n; ++i) {
        double x = (i - 0.5) / n;
        sum += 4.0 / (1.0 + x * x);
    }

若把 `x` 定义在并行区外并保持 shared，多线程同时写入会造成数据竞争。

## 三、collapse 与嵌套循环

### 1. collapse

规则嵌套循环可用

    #pragma omp parallel for collapse(2)
    for (int i = 0; i < rows; ++i) {
        for (int j = 0; j < cols; ++j) {
            c[i][j] = a[i][j] + b[i][j];
        }
    }

`collapse(2)` 把两层迭代空间展平成一个更大的空间再分配。它适合外层迭代数太少、单层并行不能充分供给线程的情况。

使用条件包括：

- 合并的层数不能超过实际嵌套层数；
- 循环应满足 OpenMP 规范循环要求；
- 被合并循环之间不能夹杂破坏完美嵌套的语句；
- 各迭代必须没有会改变语义的循环依赖。

`collapse` 不保证一定最快；外层循环已经足够大时，额外展开未必有收益。

### 2. 嵌套并行

也可以在外层线程中再次创建内层线程组，但需启用足够的活动并行层级，例如：

    omp_set_max_active_levels(2);

嵌套并行可能造成线程过量、重复创建线程组和更高同步开销。一般优先尝试单个并行域、`collapse` 或任务机制，只有性能测量证明需要时再启用嵌套并行。

## 四、矩阵访问与缓存局部性

C 语言二维数组按行连续存储。对 `a[i][j]`，令 `i` 为外层、`j` 为内层时，内层访问相邻元素，空间局部性好；交换顺序后，相邻两次访问跨越整行，容易产生更多缓存未命中。

因此矩阵实验应比较：

- 相同运算量下的行优先与列优先遍历；
- 串行与不同并行策略；
- 不同矩阵规模和线程数；
- 多次运行后的稳定统计量，而非只看一次结果。

> [!warning] 全局数组不是“拥有更多内存”
> 大数组放在函数外或声明为 static，主要是避免有限的线程栈或调用栈空间；它并不会增加进程可用的总内存。更通用的办法是检查容量并使用堆分配，同时正确释放。

## 五、sections、master 与 single

### 1. sections

当任务是几段性质不同、彼此独立的代码，而不是规则循环时，可用：

    #pragma omp parallel sections
    {
        #pragma omp section
        task_a();

        #pragma omp section
        task_b();
    }

每个 `section` 恰好由线程组中的某个线程执行一次。段数少于线程数时，一些线程不会获得任务。

### 2. master

`master` 代码只由线程号 0 的主线程执行，末尾没有隐式屏障：

    #pragma omp master
    update_by_master();

### 3. single

`single` 代码由到达该处的任意一个线程执行一次；除非使用 `nowait`，末尾通常带隐式屏障：

    #pragma omp single
    initialize_once();

因此，“只执行一次”不等于“必须由主线程执行”。

## 六、critical 与显式锁

### 1. critical

    #pragma omp critical(sum_update)
    {
        total += local_sum;
    }

同一名称的临界区共用一把互斥锁；未命名临界区彼此互斥。`critical` 保证同一时刻只有一个线程进入，但每个遇到该结构的线程仍会执行该代码。

这与 `section` 不同：`section` 的代码段在整个线程组中只执行一次。

对简单的标量加法，`reduction` 通常比每次循环进入 `critical` 更清晰且更高效；`atomic` 适合受支持的单个内存位置读改写。

### 2. OpenMP 显式锁

    omp_lock_t lock;
    omp_init_lock(&lock);

    #pragma omp parallel
    {
        omp_set_lock(&lock);
        update_shared_state();
        omp_unset_lock(&lock);
    }

    omp_destroy_lock(&lock);

锁必须先初始化、后销毁，并保证所有控制路径最终释放锁。显式锁更灵活，也更容易造成死锁、漏解锁或过度串行化。

## 七、并行结果为什么会有微小差异

浮点加法不满足严格结合律：

$$
(a+b)+c
\ne
a+(b+c)
$$

在有限精度下可能出现末位差异。不同线程数与调度顺序会改变归约树，所以并行求和可能每次略有不同。应区分：

- 机器舍入量级的微小误差：可能是正常的非结合性；
- 结果大幅漂移或偶发异常：更像数据竞争、越界或未初始化变量。

测试时应与串行基准比较误差，重复运行，并使用绝对误差与相对误差阈值，而不是只要求逐位完全相等。

## 九、易错点

1. 对有循环依赖的循环直接使用 `parallel for`。
2. 把共享临时变量误当成线程私有。
3. 累加变量既未归约也未同步。
4. 认为 `collapse` 或更多线程必然更快。
5. 混淆 `master` 与 `single` 的执行线程和隐式屏障。
6. 混淆 `sections` 的“每段一次”和 `critical` 的“逐线程互斥执行”。
7. 显式锁未初始化、未释放或未销毁。
8. 把所有浮点末位差异都判定为程序错误，或反过来用“浮点误差”掩盖数据竞争。
