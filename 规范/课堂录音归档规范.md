# 课堂录音归档规范

> 适用范围：从腾讯会议自动拉取课堂/讲座录制，下载逐字稿与智能纪要，归档到课程目录，
> 并由 Agent 润色逐字稿生成课堂内容梳理。
>
> 关联：[[AI/CLI/会议办公/tmeet/README|tmeet CLI]]、[[课表|课表]]、[[规范/课程笔记生成规范|课程笔记生成规范]]

## 一、目标

1. **自动拉取**：定时（或手动命令）从腾讯会议获取课堂/讲座录制的**逐字稿**与**智能纪要**。
2. **自动归档**：依据课表（[[课表|课表]]）识别会议所属课程与**学期第几节**，
   归档到 `课程/<课程名>/课堂笔记/`。
3. **润色梳理**：由 Agent 读取原始逐字稿，润色生成课堂内容梳理笔记（status 由"待润色"改为"已完成"）。

## 二、依赖与前置

| 依赖 | 说明 |
|:--|:--|
| tmeet CLI | `npm install -g @tencentcloud/tmeet@latest`，需完成 `tmeet auth login`（RefreshToken 约 30 天有效，过期需重新登录） |
| 课表.md | vault 根目录，脚本自动解析 |
| Python 3 | 运行 `scripts/pull_tmeet_recordings.py` |
| pull_tmeet_recordings.exe | 可选：PyInstaller 打包的独立可执行文件（vault 根目录），内置定时任务管理，不依赖 Python |

> exe 与脚本功能一致，运行时仍通过 `tmeet` CLI 访问腾讯会议（需保持 tmeet 已安装并登录）。
> 打包命令（代码更新后需重新打包）：
> `python -m PyInstaller --onefile --clean --name pull_tmeet_recordings --distpath "D:\知识库" --workpath "D:\知识库\tmp\pyinstaller_build" --specpath "D:\知识库\tmp" "D:\知识库\scripts\pull_tmeet_recordings.py"`

登录状态检查：`tmeet auth status`（`user config is empty` = 未登录）。

## 三、工作流程

```
tmeet record list（时间范围）→ 逐条：smart-minutes（纪要）+ transcript-get（逐字稿，分页）
→ 课表匹配（课程 / 学期第几节）→ 归档 raw/ → 生成待润色占位笔记 → 更新 README 索引
→ [Agent] 润色逐字稿 → 课堂内容梳理
```

### 手动运行

```bash
# 查最近 7 天（默认）
python scripts/pull_tmeet_recordings.py
# 或 exe（自动定位 vault 根目录）
pull_tmeet_recordings.exe

# 指定时间范围 / 只看不下载 / 强制重下
python scripts/pull_tmeet_recordings.py --start 2026-09-01 --end 2026-09-07
python scripts/pull_tmeet_recordings.py --dry-run
python scripts/pull_tmeet_recordings.py --force    # 已存在的记录重新下载
python scripts/pull_tmeet_recordings.py --no-archive-unmatched  # 未匹配课表的会议不下载

# 自定义知识库目录（exe 不在 vault 根目录时）
pull_tmeet_recordings.exe --vault "D:\知识库"
```

### 操作界面（Web UI）

```powershell
# 直接双击 pull_tmeet_recordings.exe（无参数）即可打开操作界面，自动弹出浏览器
# 或命令行启动：
pull_tmeet_recordings.exe --ui
pull_tmeet_recordings.exe --ui 8000      # 自定义端口
pull_tmeet_recordings.exe --ui --vault "D:\知识库"
```

> exe **无参数运行默认启动界面**；显式带 `--days/--start/--install-schedule` 等参数时按对应命令执行（定时任务即如此）。
> 首次启动需解压约 2~5 秒，请耐心等待；若端口被占用（上次界面未关闭）会给出提示，不会闪退。
> 界面为本地 HTTP 服务（仅 127.0.0.1），退出方式：关闭窗口或 Ctrl+C。
> 前端源码：`scripts/recording_ui.py`（标准库实现，零第三方依赖）。

界面功能：
- **自动拉取**：查看计划任务状态（下次/上次运行、结果），修改定时时间（`--install-schedule` 等效），删除定时；
- **课表管理**：表格化增删改课程（课程/星期/节次/时间段/周次/会议号/教师），编辑学期/开学日期/排除主题，保存即写回 `课表.md`；
- **立即拉取**：后台触发一次拉取，实时查看 `tmp/tmeet_sync.log` 日志。

> 界面为本地 HTTP 服务（仅 127.0.0.1），退出方式：关闭窗口或 Ctrl+C。
> 前端源码：`scripts/recording_ui.py`（标准库实现，零第三方依赖）。

### 定时自动（一键注册 Windows 计划任务）

```powershell
# 注册：每天 19:30 自动拉取最近 2 天（可改时间，如 --install-schedule 21:00）
pull_tmeet_recordings.exe --install-schedule 19:30

# 查询 / 删除
pull_tmeet_recordings.exe --query-schedule
pull_tmeet_recordings.exe --remove-schedule
```

> 每次运行自动追加日志到 `tmp/tmeet_sync.log`；计划任务以当前用户身份运行，需保持 Windows
> 登录状态；tmeet 登录失效后需重新 `tmeet auth login`。

## 四、课表格式（课表.md）

脚本解析 frontmatter + 表格：

```markdown
---
学期: 2026-2027-1
开学日期: 2026-09-01
排除主题: 概率论复习与数理统计导学公开课
调休: 2026-10-10=三, 2026-09-26=四
---

| 课程 | 星期 | 节次 | 时间段 | 周次 | 会议号 | 教师 |
|:--|:--|:--|:--|:--|:--|:--|
| 最优化方法 | 二 | 7-8 | 14:00-15:40 | 1-16 | 123456789 | 张三 |
```

| 字段 | 规则 |
|:--|:--|
| 学期 | 任意文本，用于展示 |
| 开学日期 | `YYYY-MM-DD`，开学所在周计为第 1 周（周次/节次计算基准） |
| 排除主题 | 可选，逗号分隔；会议主题含其中任一关键词则跳过（用于公开课/测试会议等不需要归档的录制） |
| 调休 | 可选，`日期=星期` 逗号分隔；该日期按指定星期的课表匹配（如国庆调休 `2026-10-10=三` 表示周六补周三课），周次仍按自然周计算 |
| 星期 | 一~日 |
| 时间段 | `HH:MM-HH:MM`；会议开始时间落在「开始前 30 分钟 ~ 结束后 45 分钟」内即匹配 |
| 周次 | `1-16`（每周）、`1-8单`、`2-16双`、`1,3,5`（指定周） |
| 会议号 | 可空；填写后优先按会议号强匹配 |
| 教师 | 可空 |

匹配规则：先按「星期 + 周次 + 时间段窗口」筛选；多个候选时选与课程开始时间最接近的；
填了会议号则优先会议号匹配。**学期第几节** = 开学以来（含当周）该课程实际排课次数。

> 同一课程每周多课时（如连上 2 次）请拆成多行（每行一次课）。
> 会议号相同且属同一课程时，多次课共用一行即可（按日期区分节次）。

## 五、归档结构

```
课程/<课程名>/
└── 课堂笔记/
    ├── README.md                        # 自动维护的课程记录索引
    ├── 2026-09-01-第1节-最优化方法.md    # 待润色占位笔记 → Agent 润色后为课堂内容梳理
    └── raw/                             # 原始素材（自动生成，勿手改）
        ├── 2026-09-01-...-逐字稿.md      # 带说话人/时间戳的逐字稿
        └── 2026-09-01-...-纪要.md        # 腾讯会议智能纪要
```

- **命名**：梳理笔记 `YYYY-MM-DD-第N节-主题.md`；raw 文件 `YYYY-MM-DD-主题-<录制ID后6位>-{逐字稿|纪要}.md`
  （后 6 位用于区分同日同名会议）。
- **未匹配课表**的会议（讲座、培训等）默认归档到 `未命名/课堂录音/`（`--no-archive-unmatched` 可跳过）。
- 同一录制重复运行脚本会因文件已存在而跳过（`--force` 强制重下）。

## 六、润色流程（Agent 触发）

1. 定时任务/手动拉取后，脚本在 `课堂笔记/` 生成 **status: 待润色** 的占位笔记。
2. Agent 扫描各课程 `课堂笔记/` 下 `status: 待润色` 的笔记（或 README 中"待润色"行），
   读取 `raw/` 下对应逐字稿与纪要。
3. 按 [[规范/课程笔记生成规范|课程笔记生成规范]] 组织内容：课程信息 → 本次课知识梳理（因果结构、有轻重）→ 例题/板书还原 → 疑问与待查。
4. 完成后：更新占位笔记 frontmatter（`status: 已完成`、补充 `topics`），并更新 README 状态列。

> 逐字稿为语音转写原文，含口语词、错别字（如"仕"="是"），润色时须结合纪要上下文修正。

## 七、常见问题

| 现象 | 处理 |
|:--|:--|
| `user config is empty` | 未登录：`tmeet auth login` |
| `failed to open lock file` | token.lock 被占用：结束残留 tmeet 进程后重试 |
| 无权限（address/smart-minutes/transcript-* 返回无权限） | `tmeet record permission-apply-prepare` 预览 → 用户确认 → `permission-apply-commit` 申请 |
| 500261 内容不足，暂未生成智能纪要 | 会议过短无纪要，raw 纪要文件写入占位说明 |
| 逐字稿/纪要"已存在"但想重下 | 加 `--force` |
| 课表改了没生效 | 脚本每次运行实时解析 课表.md，无需缓存 |
