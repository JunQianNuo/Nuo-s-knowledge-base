# 课程笔记生成规范

## 两类输出的边界

| 输出 | 使用场景 | 结构 | 风格 |
|---|---|---|---|
| 知识点解析梳理（知识梳理） | 初学、补基础、想真正学懂 | 开头和收尾固定，中间按知识逻辑灵活切分 | 详细、直观、有轻重 |
| 知识点汇集（知识汇集） | 复习、查缺补漏、速查 | 固定9板块 | 简洁、清单式、全量覆盖 |

用户说“帮我学”“梳理知识点”“生成笔记”时，默认生成知识梳理。用户说“复习”“查缺补漏”“速查”“清单”时，默认生成知识汇集。

两类输出都必须全量覆盖源 MD 中的概念、定理、公式、例题和作业线索。

## 知识点解析梳理（初学导向）

目的：第一次接触章节时，能全面、难易分明、重轻分明、直观、有逻辑地学懂。

### 文件命名

`XX-章节名-知识梳理.md`

### Frontmatter

```yaml
---
title: 第X章 章节名 — 知识点梳理
subject: 课程名
source: XX-章节名.md
type: 知识梳理
topics:
  - 关键词1
  - 关键词2
---
```

### 内容结构

1. `一、本章核心脉络`：点明核心问题 + Mermaid 概念演进图。
2. 中间内容板块：按知识逻辑自然切分，标题可标注“难点”“核心”“了解即可”。
3. `判定/决策流程`：Mermaid 流程图。
4. `核心公式速查表`。
5. `易错点与注意事项`：使用 `[!warning]` callout。
6. `相关知识点链接`：解释为什么需要前置/后续知识。
7. `作业与练习`：链接习题库 README 或具体习题。

每个核心概念或定理后必须有：

```markdown
> 一句话来说：用人类语言说清本质。
```

核心定理保留直观理解和证明洞察，不机械照抄完整教科书证明；例题要给步骤分解和点评。

## 知识点汇集（复习导向）

目的：已学完后快速翻看，检查是否遗漏。

文件命名：`XX-章节名-知识汇集.md`

固定9板块（标题不随意改名）：

1. `一、本章核心脉络`
2. `二、基础定义`
3. `三、核心方法/定理`
4. `四、计算/应用`
5. `五、判定/决策流程`
6. `六、核心公式速查表`
7. `七、易错点与注意事项`
8. `八、相关知识点链接`
9. `九、作业与练习`

知识汇集不展开长篇证明，不强制直观解释，重点是清单式全量覆盖。

## Frontmatter 模板

```yaml
---
title: 第X章 章节名 — 知识点汇集
subject: 课程名
source: XX-章节名.md
type: 知识点汇集
topics:
  - 关键词1
  - 关键词2
---
```

## 文件命名

- 初学版：`XX-章节名-知识梳理.md`
- 复习版：`XX-章节名-知识汇集.md`

## Mermaid 与格式规则

- Mermaid 节点标签涉及数学符号、括号、方括号、花括号、竖线、冒号时，用 `"..."` 包裹。
- 避免 `<br/>`、`✅❌⬆↔⬇` 等符号；用短节点 + 图外说明。
- Markdown 表格遵守 [[规范/Obsidian写作规范]]，LaTeX 内不要出现裸 `|`。

## 生成流程

```text
读取源 MD → 提取所有概念/定理/公式/例题 → 判断输出模式 →
组织章节主线 → 写正文 → 添加公式速查/易错点/链接/作业 →
按质量审查规范验证
```

## 质量检查清单

- 是否全量覆盖源 MD？
- 知识梳理是否有“> 一句话来说：...”？
- 知识汇集是否保留固定9板块？
- Mermaid 是否可渲染？
- 公式、表格、Wiki-link 是否符合 Obsidian 写作规范？
