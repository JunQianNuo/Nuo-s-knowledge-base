# 课程笔记生成规范

## 学习产物的边界

| 输出 | 使用场景 | 结构与职责 |
|---|---|---|
| 知识点解析梳理（知识梳理） | 初学、补基础、重读与理解 | 按知识依赖组织章节，完整保留确认范围内的定义、条件、推理、例题与作业线索 |
| 按目标组织的复习资料 | 查缺补漏、考试、速查或阶段复习 | 按当前目标选取重点、典型题和易错点，回链知识梳理 |
| 闪卡 | 主动回忆与间隔复习 | 从已核对内容中择优制卡，遵守 [[规范/闪卡规范]] |
| 共享个人原子条目 | 跨章节、跨课程复用 | 概念负责定义与边界，知识点负责条件与结论，方法负责操作流程 |

用户说“帮我学”“梳理知识点”“生成笔记”时，默认生成知识梳理。用户说“复习”“查缺补漏”“速查”“清单”时，按目标使用已有知识梳理、复习资料与闪卡，不再生成一套逐章镜像的汇集文件。

知识梳理必须全量覆盖已确认处理范围内源 MD 的概念、定理、公式、例题和作业线索；短小、折叠和分批不等于删减知识内容。复习资料可以围绕明确目标选取内容，但须说明范围并回链完整讲解。

## CLT 建构主义与本地学习适配（通用要求）

适用于新建或按用户指定范围改写的学习笔记、课堂笔记和知识梳理；复习资料按当前目标采用其中适合速查与练习的部分。与本规范既有结构配合使用，不新增一套强制章节模板。

### 资料层与学习层分开

- **原始资料层**：教材、课件、OCR 源 MD、录音逐字稿与原始纪要保留来源性质，不为了“更好学”直接改写原始材料。
- **课堂笔记层**：忠实保留本次课的重点、例题、论证和疑问；可重组讲解顺序。新增先修解释、例子、自测须标明“补充解释”或“自测（新编）”，不能写成老师原话。
- **知识梳理层**：以理解与独立应用为目标，按知识依赖重组织，不只是压缩、摘录或按课件页码搬运。
- **复习资料层**：围绕明确目标组织考点、必要条件、关键步骤、典型题与易错点，并链接到知识梳理的完整讲解。
- **共享原子条目层**：从已核对内容中沉淀可复用的概念、知识点与方法，先检索已有同义条目，避免按课程重复建卡。

生成前读取指定来源和当前课程必要的相关材料，沿用现有术语、记号和文件位置。不通读全库；需要完整处理某章时必须覆盖该范围的全部来源内容，而非只读开头。发现来源冲突或数学疑点时核对原文，并区分原文、勘误依据与补充解释。

### 分层呈现，而不是把整份笔记写短

聊天可以分轮，静态笔记应完整可读。**短的是单个阅读单元，不是整章的知识覆盖。**

- 开头给出本节要解决的问题、必要先修和阅读路线；先修提供最小提醒与可回看的准确链接，不只写“前面已经学过”。
- 每个小节聚焦一个主要问题，必要时拆成有依赖关系的短段落。采用“先看直觉与核心结论，再看推理，最后自测”的阅读层次。
- 核心定义、符号含义、定理假设、结论和关键逻辑默认可见；较长证明展开、补充例题和自测解析可折叠，不把首次理解必需的信息全部藏起来。
- 复杂章节可以分批生成，但须标明本批范围、未完成内容和衔接位置；未覆盖整章不能标为整章完成。
- 阅读路线可以提示“若此步不熟，回看某小节”；不要因文件存在、章节学过或笔记状态为“已完成”就假设读者已掌握。

### 核心知识单元的组织

根据知识类型选取必要环节，不要求每条定义都机械套完整流程：

1. **问题与最小例子**：先交代为什么需要这个概念或方法，优先使用变量少、计算简单的真实学科对象。
2. **直觉与准确表述**：保留“一句话来说”，随后给出严格定义或定理；区分直觉、类比和数学结论。
3. **符号与条件**：重要公式首次出现时解释符号的数学类型、含义、输入条件、输出结论和适用假设。
4. **关键推理**：说明“已知什么 → 根据什么关系 → 得到什么”；计算、推导与证明的重要变形必须标明依据，不能只列公式跳转。
5. **应用与边界**：对重要或易混知识给出适当例题、受控对照或反例，突出关键条件。只在确有帮助时使用生活类比，并说明局限。
6. **独立验证入口**：重要单元安排少量能检验应用的自测，数学内容必须包含必要的计算、推导或证明任务，不止考复述。

有完整证明要求时，提供完整证明或准确链接到完整证明，不以“控制认知负荷”为由省略必要步骤。

### 可视化选择

- 章节主线与方法选择沿用本规范要求的 Mermaid；概念对比用小表格，关键推导用对齐公式或编号步骤。
- 每张图解释一个核心关系，复杂关系拆成“总览 + 局部”，不堆巨大图谱。
- 单个小节不强制配图；优先用最轻的表达。图、直觉和类比均不能替代严格定义、证明与计算。
- 只引用实际存在的图片和链接，Mermaid 与数学排版遵守 [[规范/Obsidian写作规范]]。

### 静态自测与分层提示

- 不把对话协议中的“【STOP】等待回答”写成静态笔记的停写指令；生成笔记时继续完成所需内容。
- 自测先给题目，再分别使用折叠的 `[!hint]-` 和 `[!solution]-` 提供提示与解析。正文中不紧接着泄露答案；如果要求实时作答，则转入对话模式并真正等待。
- 由完整示范逐步过渡到补全关键步骤、独立新题；相邻任务尽量只增加一个主要难度维度，不为凑流程重复造题。
- 每个重要单元通常选 1–3 道高诊断价值任务，可链接已有习题而非重复录入；根据目标覆盖条件判别、关系理解、真实推理、迁移或边界中的必要维度，不要求每点五维全测。
- 无提示混合题不在标题中写出所需方法；答案解析可在作答后用于核对。
- 尚无用户实际作答时，只能写“自测”“待验证”或学习建议，不能自动标“已掌握”、填写能力等级或虚构错因。

### 来源、改写范围与验收

保留源文件与相关小节的准确回链；链接说明其作用，例如“补先修”“看完整证明”“练习本方法”，不只堆链接列表。
来源关系统一记录在 frontmatter 的 `source` 列表中：库内来源使用带双引号的 Wiki-link，如 `- "[[课程/某课程/课堂笔记/某节课]]"`；原有教材名称、录制说明、时间戳等来源描述继续保留。课堂笔记的逐字稿、纪要与配套课件，以及知识梳理对应的课堂记录，都应标记为来源。
正文的来源区仍可保留可点击链接。依赖、对比、应用、推广等知识联系单独在正文说明，不因链接指向课堂笔记就一律视为来源。Extended Graph 的“知识关联（隐藏来源）”预设隐藏 `source` 关系；“全部关系（含来源）”预设用于核对完整来源。来源节点失去全部有效连线时可以收起，但不要开启会把当前课堂笔记一并移除的“移除目标”选项。
改写已有笔记时，保留原有正确内容、来源、有效块 ID 和个人批注；与适配无关的部分不动，发现冲突单独说明。
本要求适用于后续生成和明确指定的改写，不自动触发全库旧笔记重写。

## 知识点解析梳理（初学导向）

目的：第一次接触章节时，能全面、难易分明、重轻分明、直观、有逻辑地学懂。

### 文件命名

`XX-章节名-知识梳理.md`

### Frontmatter

```yaml
---
title: 第X章 章节名 — 知识点梳理
subject: 课程名
source:
  - "[[课程/课程名/课件/MD/XX-章节名]]"
type: 知识梳理
topics:
  - 关键词1
  - 关键词2
tags:
  - 标准概念名
---
```

### 内容结构

1. `一、本章核心脉络`：点明核心问题 + Mermaid 概念演进图。
2. 中间内容板块：按知识逻辑自然切分，标题可标注“难点”“核心”“了解即可”。
3. `判定/决策流程`：Mermaid 流程图。
4. `核心公式速查表`。
5. `易错点与注意事项`：使用 `[!warning]` callout。
6. `相关知识点链接`：解释为什么需要前置/后续知识。
7. `作业与练习`：链接习题库 README 或具体习题。

每个核心概念或定理后必须有：

```markdown
> 一句话来说：用人类语言说清本质。
```

核心定理保留直观理解和证明洞察，不机械照抄完整教科书证明；例题要给步骤分解和点评。

## 复习资料与共享个人原子条目

- 复习资料放入对应课程实际目录下的 `复习/`，按目标、考试范围或题型组织，详见 [[规范/考试复习规范]]。需要完整讲解时回到知识梳理，不复制整章内容形成第二套笔记。
- 闪卡遵守 [[规范/闪卡规范]]，从明确、可回忆、已核对的内容中择优生成。
- 共享个人原子条目直接放在根目录 `概念/`、`知识点/`、`方法/`，不设课程子目录，不填写课程归属 `subject`。
- 概念条目聚焦定义与边界；知识点条目聚焦条件与结论；方法条目聚焦操作流程。具体模板与链接规则见 [[规范/知识原子卡规范]]。
- 课程、章节和习题只在确有来源或应用关系时关联：`source` 用于溯源，实际应用链接在正文中说明。习题、例子和推导按条目需要添加，不要求每个条目都有习题。
- 课程笔记继续保留课程 `subject`；共享条目不因来源于某门课程而继承该课程归属。

## Mermaid 与格式规则

- Mermaid 节点标签涉及数学符号、括号、方括号、花括号、竖线、冒号时，用 `"..."` 包裹。
- 避免 `<br/>`、`✅❌⬆↔⬇` 等符号；用短节点 + 图外说明。
- Markdown 表格遵守 [[规范/Obsidian写作规范]]，LaTeX 内不要出现裸 `|`。

## 生成流程

```text
确认来源与处理范围 → 读取源 MD 和必要的本地关联资料 →
提取所有概念/定理/公式/例题 → 判断输出类型与先修依赖 →
组织章节主线与分层阅读单元 → 写正文、适量可视化与分层自测 →
添加公式速查/易错点/链接/作业 → 从标签数据库复用标准概念名写入 tags → 对照来源检查覆盖 → 按质量审查规范验证
```

## 质量检查清单

- 是否全量覆盖已确认处理范围内的源 MD，分批未完成项是否明确？
- 知识梳理是否有“> 一句话来说：...”？
- 学习笔记与知识梳理是否有必要先修提醒、适当的直觉和关键推理依据？
- 是否分层呈现而非删减内容，核心条件默认可见，长展开与自测解析适当折叠？
- 自测是否能检查真实应用，且没有把生成笔记、看过例题误写成用户已掌握？
- 课堂原内容、补充解释、新编自测与不确定项是否区分？
- 复习资料是否说明目标与范围，并回链完整知识梳理？
- 共享原子条目是否职责清楚、根目录扁平存放，且未按课程重复建卡或强制补习题？
- Mermaid 是否可渲染？
- 公式、表格、Wiki-link 是否符合 Obsidian 写作规范？
- `tags` 是否复用 [[总览/标签库.base|标签数据库]] 的标准名，核心概念是否能通过内置 `tag:` 搜索找到？`topics` 可保留描述性词，不要求全部转换。
