# 知识原子卡规范

## 四层体系与职责边界

| 层级 | 目录 | 粒度 | 用途 |
|---|---|---|---|
| 概念卡 | `概念/课程名/` | 跨章节复用概念 | 严格定义 + 由来作用 + 关系网 |
| 知识点卡 | `知识点/课程名/` | 章节内方法/定理/关键知识点 | 定义 + 推导 + 例题 + 易错点 |
| 方法卡 | `方法/课程名/` | 解题套路/流程 | 适用场景 + 核心公式 + 流程图 + 例题 |
| 习题 | `课程/课程名/习题库/` | 单题 | 题目 + 提示 + 解析 + 知识/方法双标签 |

## 概念卡

适合：跨章节出现、拥有独立定义、应成为 Graph View 枢纽的概念。概念卡不放例题，不放长推导，不链接章节笔记来污染概念图。

固定结构：

1. `## 一句话`
2. `## 严格定义`
3. `## 由来与作用`
4. `## 相关概念`

相关概念优先链接概念层，如 `[[概念/课程名/相关概念]]`；需要反向导航时可补充知识点层链接并说明关系。

## 知识点卡

适合：章节内重要方法、定理、考试中可单独考查的知识点。

固定顺序：

1. `## 一句话`
2. `## 严格定义`：核心公式用 `\boxed{}`。
3. `## 推导：...`：用 `> [!proof]- 推导` 折叠。
4. `## 算法步骤 / 关键性质`
5. `## 典型例题`：解答用 `> [!example]- 解答` 折叠。
6. `## 易错点`
7. `## 相关概念`
8. `## 习题`

相关概念同时链接概念层和方法层，习题链接到具体习题库 README 或题目。

## 方法卡

适合：有清晰操作步骤的解题套路、跨章节通用计算流程、特定题型固定解法。

固定顺序：

1. `## 适用场景`
2. `## 核心公式/步骤`
3. `## 流程图`
4. `## 典型例题`
5. `## 知识链接`
6. `## 习题链接`

方法卡的流程图使用 Mermaid，节点标签用 `"..."` 包裹。方法卡不放定理长推导，推导属于知识点卡。

## Frontmatter 模板

```yaml
---
title: 名称
type: 概念 # 概念 | 知识点 | 方法
subject: 课程名
source:
  - 课程/课程名/知识点解析梳理/XX-章节名-知识梳理.md
topics:
  - 关键词
---
```

方法卡可补充：

```yaml
method_type: 基础方法
linked_knowledge:
  - 知识点/课程名/依赖知识点
```

## 链接规则

- 概念卡：主要链概念层，避免链章节笔记。
- 知识点卡：链概念层 + 方法层 + 习题。
- 方法卡：链知识点 + 具体习题文件，避免只链 README。
- 习题：可通过 `knowledge_tags` 和 `method_tags` 回链知识点/方法。

## 生成流程

```text
判断卡片层级 → 从章节笔记/习题中抽取定义和例子 →
按模板写入 → 折叠推导/例题 → 补全链接 → 质量检查
```

## 质量检查清单

- 概念卡是否有严格定义且没有例题污染？
- 知识点卡是否含 `\boxed{}`、折叠推导、折叠例题？
- 方法卡是否含流程图、知识链接、习题链接？
- 板块顺序是否正确？
- Wiki-link 是否指向正确层级？
