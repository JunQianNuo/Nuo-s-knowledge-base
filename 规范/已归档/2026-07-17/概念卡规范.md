# 概念卡规范

## 目的

**概念卡片**是跨章节复用的原子知识单元。它不是章节笔记的浓缩，而是把在整个课程中反复出现的基础概念抽出来，形成独立的学习入口。

概念卡 + 知识点卡 + 章节笔记的职责边界：

| 层级 | 目录 | 粒度 | 用途 |
|------|------|------|------|
| **概念卡** | `概念/最优化方法/` | 跨章节复用概念 | 严格定义 + 由来作用 + 关系网 |
| **知识点卡** | `知识点/最优化方法/` | 章节内方法/定理 | 严格定义 + 推导 + 例题 + 易错点 |
| **章节笔记** | `课程/.../知识点解析梳理/` | 全章 | 初学完整内容 |

## 哪些内容适合做概念卡

- 在整个课程中多次出现（≥2 章）
- 有自己的独立定义，不依附于某一种方法
- 在 Graph View 中应该成为**枢纽节点**

例如：凸集、凸函数、下降方向、线搜索、KKT 条件、对偶、Pareto 最优。

**不适合**做概念卡的内容：黄金分割法、单纯形法、回溯线搜索（这些属于知识点卡）。

## 内容结构

| 板块 | 标题 | 内容要求 |
|------|------|----------|
| **一句话** | `## 一句话` | 一句话说清概念本质 |
| **严格定义** | `## 严格定义` | 完整数学公式；`> [!important]` 高亮核心要点或等价刻画 |
| **由来与作用** | `## 由来与作用` | 谁/何时提出？解决什么问题？为什么重要？在优化理论/算法中扮演什么角色？列出关键性质 |
| **相关概念** | `## 相关概念` | Wiki-link **只链概念层**（`[[概念/...]]`），不链章节笔记；不链知识点层 |

**反模式**：
- 概念卡里放例题 → 例题属于知识点卡或章节笔记
- 概念卡里放推导证明 → 推导属于知识点卡
- 概念卡里链章节笔记 → 污染关系图
- 用概述替代严格定义 → 概念卡的核心是数学定义，不能只有直观解释

## Frontmatter

```yaml
---
title: 概念名
type: 概念
subject: 最优化方法
source:
  - 课程/最优化方法/知识点解析梳理/XX-章节名-知识梳理.md
topics:
  - 概念名
  - 相关主题
---
```

`source` 列出该概念在哪些章节中出现过。

## 文件命名

`概念名.md`（中/英文均可，准确表达概念即可）

路径：`概念/最优化方法/概念名.md`

## 模板

```markdown
---
title: 概念名
type: 概念
subject: 最优化方法
source:
  - 课程/最优化方法/知识点解析梳理/XX-章节名-知识梳理.md
topics:
  - 概念名
---

# 概念名

## 一句话

...（一句话说清本质）

## 严格定义

完整数学定义，含公式。

> [!important] 核心要点高亮：等价刻画、关键性质、与其他概念的区别。

## 由来与作用

- 谁提出/何时提出
- 解决什么问题
- 在优化理论/算法中扮演什么角色
- 列出关键性质

## 相关概念

- [[概念/最优化方法/相关概念]]
```

## 生成流程

```
确定概念是否跨章节 → 从章节笔记中提取严格定义 →
写出由来与作用（参考规范/知识点解析梳理规范中的「直观理解」和课程知识图谱） →
补高亮 → 只链概念层 → 写入概念/最优化方法/
```

## 质量检查清单

- 严格定义是否完整（含公式，非概述）？
- `[!important]` 是否高亮了核心要点？
- 由来与作用是否说明了概念的历史/用途/重要性？
- 相关概念是否只链了概念层？
- 有无泄露章节链接或例题？
- file_path 是否正确（`概念/最优化方法/概念名.md`）？

## 反向链接规则

概念卡在「相关概念」板块不仅应链接其他概念文件，还应**反向链接**到使用该概念的知识点文件：

```markdown
## 相关概念
- [[概念/概率论/xxx]]
- [[知识点/概率论/xxx]] — 简述该知识点如何用到本概念
```

此规则确保概念层不是单向孤岛——读者能通过概念找到对应的知识点和方法。
