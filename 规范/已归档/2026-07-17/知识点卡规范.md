# 知识点卡规范

## 目的

**知识点卡片**是面向章节复习和考试的独立学习单元。每张卡片围绕一个具体方法/定理/概念展开，包含严格定义、推导证明、典型例题、易错点和习题链接——让单个知识点能承担独立学习的功能。

概念卡 + 知识点卡 + 章节笔记的职责边界：

| 层级 | 目录 | 粒度 | 用途 |
|------|------|------|------|
| **概念卡** | `概念/最优化方法/` | 跨章节复用概念 | 严格定义 + 由来作用 + 关系网 |
| **知识点卡** | `知识点/最优化方法/` | 章节内方法/定理 | 严格定义 + 推导 + 例题 + 易错点 |
| **章节笔记** | `课程/.../知识点解析梳理/` | 全章 | 初学完整内容 |

## 哪些内容适合做知识点卡

- 有独立定义和迭代步骤的具体方法（黄金分割法、单纯形法、牛顿法）
- 有完整陈述和推论的重要定理（Zoutendijk 定理）
- 在考试中经常单独考查的知识点（KKT 互补松弛、对偶间隙）
- 值得单独展开例题和推导的关键子概念（回溯线搜索、进退法、Pareto 前沿）

**不适合**做知识点卡的内容：跨章节的底层概念（属于概念卡）、完整章节梳理（属于章节笔记）。

## 内容结构

| 板块 | 标题 | 格式要求 |
|------|------|----------|
| **一句话** | `## 一句话` | 一句话说清本质 |
| **严格定义** | `## 严格定义` | 完整数学推导和公式；用 `\boxed{}` 框出核心公式；`> [!important]` 高亮判定条件或关键解读 |
| **推导/证明** | `## 推导：...` | `> [!proof]- 推导` 可折叠 callout；只保留核心洞察步骤，不抄完整教科书证明 |
| **算法/关键性质** | `## 算法步骤` / `## 关键性质` | 表格总结；若为方法则给出算法步骤 |
| **典型例题** | `## 典型例题` | 题目文本可见；解答用 `> [!example]- 解答` 可折叠；含完整手算步骤和点评 |
| **易错点** | `## 易错点` | `> [!warning]` callout；至少一条，最多五条 |
| **相关概念** | `## 相关概念` | Wiki-link 同时链**概念层**（`[[概念/...]]`）和**知识点层**（`[[知识点/...]]`）；不链章节笔记 |
| **习题** | `## 习题` | Wiki-link 到对应习题库 README；如有特定习题号则标注 |

**板块顺序固定**：一句话 → 严格定义 → 推导 → 算法/性质 → 典型例题 → 易错点 → 相关概念 → 习题。

**反模式**：
- 概念用概述替代严格定义
- 例题答案不折叠，影响阅读流
- 推导不折叠，占据过大空间
- 相关概念只链了概念层或只链了知识点层
- 链接了章节笔记 → 污染关系图
- 内容空洞（只有一句话 + 列表，无公式、无例题、无推导）

`知识点名.md`（中/英文均可，准确表达即可）

## 生成流程

```
确定知识点属于哪个章节 → 从章节笔记/知识点解析梳理中提取定义、推导和例题 →
按板块模板填入内容 → 推导和解答折叠 → 高亮核心定义 →
补链概念层 + 知识点层 + 习题库 → 写入知识点/最优化方法/
```

## 质量检查清单

- 严格定义是否完整（含公式和 `\boxed{}`）？
- `[!important]` 是否高亮了核心判定条件？
- 推导/证明是否折叠（`> [!proof]-`）？
- 例题解答是否折叠（`> [!example]-`）？
- 易错点是否用 `> [!warning]`？
- 相关概念是否同时链了概念层和知识点层？
- 有无泄露章节链接（`[[课程/...]]` 只能出现在习题板块）？
- 习题链接是否有效？
- 板块顺序是否正确（定义 → 推导 → 性质 → 例题 → 易错点 → 概念 → 习题）？

## 与方法的链接

知识点卡在「相关概念」板块中应同时链接：
- 概念层文件（`概念/概率论/`）
- 方法层文件（`方法/概率论/`）——链接使用该知识点的解题方法

示例：
```markdown
## 相关概念
- [[概念/概率论/xxx]]
- [[方法/概率论/xxx方法]]
```

方法文件由方法体系归纳生成，知识点不需重复方法中的例题和流程图。
