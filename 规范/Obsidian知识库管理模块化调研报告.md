# Obsidian 知识库管理模块化调研报告

> [!abstract] 结论先行
> 本仓库已有按学科划分的稳定目录、课程规范、闪卡与 Git 基础。**不建议推倒重建或全库改成 PARA / 卡片盒**。推荐采用「**现有目录作物理骨架 + MOC 作导航 + Properties / Bases 作筛选 + 收件箱与复盘作流程 + Git 作备份**」的渐进式组合。

## 选择区

勾选希望实施的模块，或直接回复模块编号（如 `M01 M02 M03 M04`）。未勾选的模块不会改动仓库。

### 推荐组合

| 组合 | 包含模块 | 适合情形 | 预计影响 |
|---|---|---|---|
| A：轻量导航 | M01、M02、M03、M11 | 先解决「找不到、来不及整理」 | 只新增索引、规则与少量模板，不移动旧笔记 |
| B：学习强化 | A + M04、M05、M06、M07、M10 | 以课程、考研、语言复习为主 | 建立课程仪表盘、复习与闪卡闭环 |
| C：完整工作流 | B + M08、M09、M12、M13、M14 | 同时推进数学建模、长期项目与 AI 协作 | 增加项目看板、素材治理与自动化审查 |

- [ ] 采用组合 A：轻量导航
- [ ] 采用组合 B：学习强化
- [ ] 采用组合 C：完整工作流
- [ ] 自定义：勾选下方模块

## 调研摘要：方法如何取舍

| 方法 | 核心做法 | 调研发现 | 对本仓库的取舍 |
|---|---|---|---|
| 文件夹优先 | 用目录承载稳定的物理归属 | 适合大量课件、PDF、题目、代码等有明确来源的文件；仅用双链在大库中容易失去落点 | **保留**现有课程、数学建模、语言等目录骨架 |
| MOC | 用人工维护的主题导航页聚合笔记 | MOC 能在不搬动文件的前提下提供学习路径和跨课程入口 | **优先补充**：每门课程、数学建模、考研建立入口页 |
| PARA | 项目、领域、资源、归档四类管理行动信息 | 对有结束条件的项目有效，但不适合替代学科目录 | **局部采用**：仅用于数学建模比赛、考研阶段计划等活动项目 |
| 卡片盒 / 原子笔记 | 一条可复用的概念、方法或结论一篇笔记，并建立关系 | 利于跨课程迁移和复习，但不应把每页课件强行拆卡 | **选择性采用**：用于 `概念`、`知识点`、`方法`、高价值题型 |
| Properties + Bases | 用结构化属性记录类型、状态、课程、复习时间，再生成视图 | 官方原生支持，可减少依赖；特别适合项目、复习与清单 | **优先采用**：作为仪表盘与筛选层，不取代正文 |
| Dataview | 以查询实时汇总属性与任务 | 已安装，功能成熟；适合复杂查询，但不能替代良好元数据 | **按需采用**：先用 Bases，复杂跨表再使用 Dataview |

> [!tip] 本仓库的最小原则
> 目录回答「文件放哪里」；MOC 回答「从哪里学习 / 导航」；属性回答「它是什么、处于什么状态」；双链回答「与什么有关」。四者不要互相替代。

## 功能模块清单

### M01｜主页与 MOC 导航

- [x] 启用 M01
- **解决问题**：入口分散，课程、数模、语言、考研之间缺少总览与跳转。
- **实施内容**：创建一个仓库主页；为课程、数学建模、语言、考研建立一级 MOC；沿用已有如 [[课程/归档/最优化方法/最优化方法-知识图谱|最优化方法知识图谱]] 的优秀结构。
- **交付物**：主页 1 份、一级 MOC 4 份、MOC 模板 1 份。
- **改动范围**：只新增索引和链接；不移动旧文件。
- **投入 / 收益**：低投入 / 高收益。
- **依赖**：无，使用 Obsidian 原生链接与书签即可。

### M02｜统一收件箱与定期清空

- [x] 启用 M02
- **解决问题**：临时灵感、截图、待处理资料进入正式目录前缺少稳定落点。
- **实施内容**：保留现有 `未命名/` 作为唯一 Markdown 收件箱；课程原始资料仍进入各课程 `未处理项/`；建立「每周清空」清单与状态标记。
- **规则**：收件箱只负责捕获；处理后归档、转任务或删除。`未处理项/` 遵循现有「处理完即删除」规则。
- **交付物**：收件箱说明、处理模板、周复盘清单。
- **投入 / 收益**：低 / 高。
- **依赖**：M03 可增强，但不是前置。

### M03｜最小 Properties 元数据标准

- [x] 启用 M03
- **解决问题**：同类笔记的状态、来源、课程、复习安排无法统一筛选。
- **实施内容**：不批量重写历史文件；仅为新建笔记和被修改笔记逐步使用以下最小字段。

```yaml
---
title: 标题
type: 课程笔记 / 习题 / 概念卡 / 项目 / 资料
status: 待处理 / 学习中 / 已整理 / 待复习 / 已归档
subject: 课程名或领域
topics:
  - 主题
source: 来源文件、链接或题目出处
review_date: 2026-09-01
---
```

- **规则**：`type` 表示笔记类别，`status` 表示生命周期，`topics` 表示主题；标签只用于真正跨域且需检索的概念，不把标签当作第二套文件夹。课程资料保留 `subject`；根目录的共享概念、知识点与方法条目不填写课程归属 `subject`，课程来源只记入 `source` 溯源或正文实际应用链接。
- **交付物**：字段字典、5 类模板、渐进迁移规则。
- **投入 / 收益**：中 / 高。
- **依赖**：无；M04、M10、M11 以此为数据基础。

### M04｜Bases 学习与项目仪表盘

- [x] 启用 M04
- **解决问题**：需要从多个目录查看「待处理资料、待复习笔记、进行中项目」。
- **实施内容**：使用已启用的 Obsidian 原生 Bases，创建「课程进度」「待复习」「项目状态」视图；不强依赖额外插件。
- **交付物**：3 个 `.base` 文件与嵌入式仪表盘说明。
- **投入 / 收益**：中 / 高。
- **依赖**：M03。
- **注意**：Base 是视图，原始数据仍留在 Markdown 属性中，可迁移、可被 Git 记录。

### M05｜课程学习流水线

- [x] 启用 M05
- **解决问题**：不同课程资料路径和处理阶段不一，后续新增课程容易失去一致性。
- **实施内容**：把现有「最优化方法」作为参考模板，形成统一流程：`原始课件 → MD / OCR → 知识点解析梳理 → 习题 / 答疑 → 按目标复习 → 闪卡`；可复用内容按需链接或沉淀到共享概念、知识点与方法条目。
- **交付物**：课程 MOC 模板、课程进度页、章节处理清单。
- **改动范围**：不重构已成熟课程；只补入口页、缺失目录说明及新课程模板。
- **投入 / 收益**：中 / 很高。
- **依赖**：M01；建议配合 M03、M04、M07、M10。

### M06｜概念、知识点、方法、题目的原子化连接

- [x] 启用 M06
- **解决问题**：跨课程的定义、定理、解题方法与题型难以复用。
- **实施内容**：共享个人原子条目直接存放在根目录 `概念/`、`知识点/`、`方法/`，不设课程子目录或课程归属 `subject`。概念负责定义与边界，知识点负责条件与结论，方法负责操作流程；题目保留在实际学习或应用位置，按需要链接相关条目。
- **交付物**：共享条目模板、双向链接规则、跨课程主题索引。
- **投入 / 收益**：中 / 高。
- **依赖**：M01、M03；与现有 [[规范/知识原子卡规范|知识原子卡规范]] 协同。
- **边界**：只从高频、易错、可迁移内容开始；不把所有长笔记机械拆分，不要求每个共享条目都有习题。课程链接只承担溯源或实际应用说明。

### M07｜闪卡与间隔复习闭环

- [x] 启用 M07
- **解决问题**：知识点整理后不能稳定转化为回忆练习，闪卡与笔记容易脱节。
- **实施内容**：以现有 `闪卡/`、Yanki、`scripts/sync_flashcards.py` 为基础，为每门课程维护「应制卡」「已同步」「待复习」入口；从 M06 的概念卡、方法卡与错题中择优制卡。
- **交付物**：课程闪卡索引、制卡判据、同步与抽查清单。
- **投入 / 收益**：中 / 高。
- **依赖**：M05；与 [[规范/闪卡规范|闪卡规范]] 保持一致。

### M08｜考研与数学建模项目管理

- [x] 启用 M08
- **解决问题**：有明确截止日期、阶段目标和产出的事项不适合仅按资料目录管理。
- **实施内容**：在 `数学建模/` 和考研相关内容中局部采用 PARA：项目页记录目标、截止时间、下一步、资料入口、产出与复盘；已完成项目转归档而不删除。
- **交付物**：项目主页、项目模板、阶段复盘模板、项目 Base 视图。
- **投入 / 收益**：中 / 高。
- **依赖**：M03、M04、M10。
- **边界**：不把全部课程改成 PARA；课程仍是长期领域，项目仅承载比赛、训练、阶段计划。

### M09｜素材、附件与来源治理

- [ ] 启用 M09
- **解决问题**：根目录媒体、PDF、PPTX 与 OCR 临时文件混放时，来源和生命周期难以判断。
- **实施内容**：建立附件命名、来源字段、临时文件清理与大文件规则；课程媒体继续靠近对应课程目录，公共图片遵循现有根目录媒体约定。
- **交付物**：附件规则、来源记录模板、季度清理清单。
- **投入 / 收益**：中 / 中高。
- **依赖**：无；建议与 M13 一起实施。

### M10｜任务、复习与周回顾

- [x] 启用 M10
- **解决问题**：知识库记录了内容，但没有固定机制将「待处理、待复习、下一步」重新呈现。
- **实施内容**：每天只记录当日三项重点；每周统一处理收件箱、更新课程进度、安排复习、归档完成项目；用 Bases 或 Dataview 生成待复习清单。
- **交付物**：日计划模板、周回顾模板、复习任务视图。
- **投入 / 收益**：低中 / 高。
- **依赖**：M02；建议 M03、M04。

### M11｜链接、命名与质量审查

- [x] 启用 M11
- **解决问题**：重命名、移动、OCR 转换后可能出现失效链接、空笔记、重复文件或未处理材料。
- **实施内容**：建立月度只读审查：未解析链接、孤立笔记、空文件、未处理项、异常大文件、重复附件；先出报告，再人工确认后改动。
- **交付物**：审查脚本或检查清单、问题报告、修复记录。
- **投入 / 收益**：中 / 高。
- **依赖**：无；遵循 [[规范/质量审查规范|质量审查规范]]。
- **安全原则**：审查与自动修复分两步，绝不因扫描结果直接删除资料。

### M12｜AI 协作与自动化处理

- [x] 启用 M12
- **解决问题**：课件转写、章节梳理、题目入库、链接审查等重复工作耗时。
- **实施内容**：把现有 `AI/`、`scripts/`、规范文件整合为「输入 → AI 草稿 → 人工核验 → 写入正式目录 → 质量审查」的可追踪流程；为常见任务沉淀 Prompt 模板。
- **交付物**：任务入口页、处理日志模板、人工核验点、常用 Prompt 索引。
- **投入 / 收益**：中高 / 高。
- **依赖**：M05、M11；已有 AI 工具规范可直接复用。
- **边界**：AI 不自动修改核心知识笔记、不替代来源核查、不直接清理文件。

### M13｜Git、Git LFS 与版本里程碑

- [x] 已部署（v0.1）
- **已完成**：根仓库已连接 GitHub、启用 Git LFS，并创建与推送 `v0.1` 标签。
- **可选增强**：配置 Obsidian Git 的自动提交与提交前检查；关键阶段创建版本标签；保持课程大文件由 LFS 管理。
- **交付物**：自动备份策略、版本命名规则、恢复演练清单。
- **投入 / 收益**：低 / 高。
- **注意**：自动提交只备份，不等于自动合并冲突；跨设备修改前仍应先拉取。

### M14｜归档与渐进式整理

- [x] 启用 M14
- **解决问题**：历史资料并非无价值，但长期混在活跃区域会增加浏览噪声。
- **实施内容**：按「活跃、暂缓、已完成、归档」管理；每次只处理一个小范围，移动前先确认链接与 Git 状态；建立归档索引而非删除历史。
- **交付物**：归档规则、迁移批次清单、归档 MOC。
- **投入 / 收益**：中高 / 中高。
- **依赖**：M01、M11、M13。

## 推荐实施顺序

| 阶段 | 模块 | 目标 | 原则 |
|---|---|---|---|
| 第 1 阶段 | M01、M02、M03、M11 | 建立入口、收口与数据标准 | 不搬文件，不批量改历史笔记 |
| 第 2 阶段 | M04、M05、M10 | 让课程与复习任务可见 | 先选一门课程试点 |
| 第 3 阶段 | M06、M07、M08 | 把学习成果转为可复用知识与行动 | 从高频考点、错题、比赛项目开始 |
| 第 4 阶段 | M09、M12、M13、M14 | 治理素材、自动化与长期维护 | 所有批量操作先报告、后执行 |

> [!warning] 不建议一次实施的内容
> - 全库重命名、移动或改写 frontmatter；
> - 用标签取代现有课程目录；
> - 为了图谱而大量补双链；
> - 未经抽检就让 AI 自动归档或删除文件；
> - 为了仪表盘而先安装大量插件。

## 调研依据与来源评估

### 官方能力（高可信）

- [Obsidian Bases 官方文档](https://obsidian.md/help/bases)：Bases 是原生数据库式视图，基于本地 Markdown 与属性进行筛选、排序和多视图展示。
- [Obsidian Properties 官方文档](https://obsidian.md/help/properties)：属性支持文本、列表、日期、链接等类型，适合将笔记的类别和状态结构化。
- [Obsidian Tags 官方文档](https://obsidian.md/help/tags)：标签可用于跨域主题检索与层级标签；不应与目录承担同一种职责。
- [Obsidian Templates 官方文档](https://obsidian.md/help/plugins/templates)：原生模板可插入固定属性与日期，适合降低新笔记的格式成本。

### GitHub 实践（中高可信）

- [MOC 最小示例库](https://github.com/prisant-labs/obsidian-vault-collection/tree/main/methodology-vaults/maps-of-content)：展示主页 → MOC → 原子笔记的渐进式导航结构。
- [研究型 Obsidian 模板](https://github.com/hoonsubin/obsidian-research-vault-template)：采用 MOC、属性、收件箱、项目与归档的组合，验证了分层结构可共存。
- [PARA 中文模板](https://github.com/Yang642514/obsidian-para-pkm-template)：将项目、领域、资源、归档与收件箱结合，适合作为项目层参考而非全库替换方案。
- [Dataview 官方仓库](https://github.com/blacksmithgu/obsidian-dataview)：说明其可从 Markdown 元数据生成实时查询；复杂仪表盘可在 Bases 后按需引入。
- [Obsidian Git 文档](https://github.com/Vinzent03/obsidian-git/blob/master/docs/Features.md)：支持源代码管理视图、提交、拉取、推送与定时同步；Windows 下 Git LFS 可被插件使用。

### Bilibili、YouTube、知乎的社区案例（启发性参考）

- Bilibili：[PARA 与 MOC 介绍](https://www.bilibili.com/video/BV1tR4y1p733/)，直接比较了 PARA 与 MOC 两种组织方法。
- Bilibili：[文件夹管理实践](https://www.bilibili.com/video/BV1bb421B7Ah/)，提供了基于文件夹的长期工作流案例。
- Bilibili：[双链、图谱与标签公开课](https://www.bilibili.com/video/BV1H84y1R7Xg/)，适合学习基础链接、标签、YAML 与插件概念。
- YouTube：[Folders, Tags and Links](https://www.youtube.com/watch?v=AiRuPNSFUOA)，展示文件夹负责主结构、标签负责横向筛选、链接负责关系表达的组合思路。
- YouTube：[MOC 与链接的无文件夹组织](https://www.youtube.com/watch?v=vFs2oWDUJPA)，提供 MOC 导航优先的对照案例。
- 知乎：[Obsidian 工作系统案例](https://zhuanlan.zhihu.com/p/765819583)，提供从记录到组织再到个人项目支持的使用经验。

> [!note] 证据边界
> 社区视频、模板和文章反映的是个人实践，不存在适用于所有人的「唯一最佳结构」。本报告的推荐是结合本仓库已有的课程层级、题目与闪卡体系后的工程判断，而非照搬任何单一模板。
