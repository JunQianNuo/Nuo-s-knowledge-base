# 知识库元数据规范

## 目标

使用最少、稳定、可查询的 Properties 支持导航、Bases、复习与项目管理。新建笔记和实质修改时按需维护；批量迁移按用户明确授权的范围执行，不因规范更新自动重写全部历史笔记。

概念、知识点、方法是跨领域内容类型。卡片分别放在 `概念/名称.md`、`知识点/名称.md`、`方法/名称.md`，不按课程分层，也不设置 `subject` 归属。课程信息可以作为来源或应用场景在正文出现。

## 通用字段

```yaml
---
title: 标题
type: 知识点
status: 学习中
topics: []
source: []
related: []
---
```

| 字段 | 类型 | 用途 | 规则 |
|---|---|---|---|
| `title` | 文本 | 展示标题 | 与文件名可不同，但应语义一致 |
| `type` | 文本 | 内容类型 | 必填；不使用标签表达类型 |
| `status` | 文本 | 生命周期状态 | 从下方词表按实际情况填写；不以创建文件或读过内容代替已掌握 |
| `topics` | 列表 | 主题检索 | 按需填写少量关键词，跨领域复用优先；不用于指定卡片归属 |
| `source` | 链接列表 | 出处与追溯 | 库内来源每项使用带双引号的 Wiki-link，不写裸路径 |
| `related` | 链接列表 | 补充知识关联 | 可选；每项使用带双引号的 Wiki-link，正文仍说明关联含义 |
| `subject` | 文本 | 课程资料的课程信息 | 课程笔记或原始课程资料可按需保留；概念、知识点、方法卡不设置 |
| `review_date` | 日期 | 下次复习 | 仅对确需复习的笔记填写 |
| `due_date` | 日期 | 截止日期 | 仅对项目和任务填写 |
| `method_type` | 文本 | 方法分类 | 方法卡按检索需要选用，不要求每张填写 |

字段应服务于实际检索，不要求每类笔记填齐表内所有字段。空列表可暂留；没有用途的可选字段可以删除。

## 来源链接与图谱

`source` 统一使用列表，库内来源的写法如下（示例链接实际存在，使用时替换为本笔记的真实来源）：

```yaml
source:
  - "[[规范/课程笔记生成规范]]"
  - "[[规范/知识原子卡规范]]"
```

正文的来源区可以继续保留来源链接、书目、页码、题目编号、录制说明、时间戳和外部 URL。历史来源描述在迁移时保留到正文或对应资料笔记，不因统一字段丢失出处；没有真实库内来源时保留空列表，不虚构来源链接。

依赖、对比、应用、推广等知识关系在正文解释，必要时用 `related` 补充。某链接是否为来源，按本笔记实际取材关系判断；链接指向课程或课堂笔记，不代表它必然是来源。

Extended Graph 的“知识关联（隐藏来源）”预设隐藏 `source` 关系；“全部关系（含来源）”预设用于核对完整来源。来源节点失去全部有效连线时可以收起，但不要开启会把当前笔记一并移除的“移除目标”选项。

## 受控词表

### `type`

`MOC`、`课程笔记`、`知识梳理`、`习题`、`概念`、`知识点`、`方法`、`项目`、`资料`、`日计划`、`周回顾`、`审查报告`、`索引`、`规范`。

### `status`

`待处理`、`学习中`、`已整理`、`待复习`、`进行中`、`暂缓`、`已完成`、`已归档`、`使用中`、`规划中`。

> [!warning]
> 不以标签代替内容类型、文件位置或生命周期状态。标签只承担跨域概念检索；没有用户实际验证时，不用元数据宣称已掌握。

## 维护与迁移

1. 新笔记从 `模板/` 创建，按内容职责取舍正文和可选字段。
2. 维护旧笔记时优先核对类型、状态、真实来源和有效关系；三类卡片移除课程归属，保留原有课程出处。
3. 不为同一主题强制建立三类卡，不为补齐元数据而生成虚构链接。
4. 批量迁移按授权范围先审查再执行，并验证路径、链接、字段和原内容是否保留。
5. 课程资料字段可用 [[总览/课程笔记.base|课程笔记视图]] 检查；三类卡片的职责与链接规则见 [[规范/知识原子卡规范]]。
