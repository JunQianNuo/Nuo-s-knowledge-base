# 知识库元数据规范

## 目标

使用最少、稳定、可查询的 Properties 支持导航、Bases、复习与项目管理。**不要求批量回填历史笔记**：新建笔记和每次实质修改时再补全。

## 通用字段

```yaml
---
title: 标题
type: 课程笔记
status: 待处理
subject: 课程名或领域
topics:
  - 主题
source: 来源文件、网页或题目出处
review_date: 2026-09-01
---
```

| 字段 | 类型 | 用途 | 规则 |
|---|---|---|---|
| `title` | 文本 | 展示标题 | 与文件名可不同，但应语义一致 |
| `type` | 文本 | 笔记类型 | 必填；不使用标签表达类型 |
| `status` | 文本 | 生命周期状态 | 必填；从下方受控词表选取 |
| `subject` | 文本 | 所属课程或领域 | 课程、语言、数模、考研项目建议填写 |
| `topics` | 列表 | 内容主题 | 2–5 个为宜，跨课程复用优先 |
| `source` | 文本或列表 | 来源与追溯 | 保留文件名、URL、题目编号或链接 |
| `review_date` | 日期 | 下次复习 | 仅对需要复习的笔记填写 |
| `due_date` | 日期 | 截止日期 | 仅对项目和任务填写 |

## 受控词表

### `type`

`MOC`、`课程笔记`、`习题`、`概念`、`知识点`、`方法`、`项目`、`资料`、`日计划`、`周回顾`、`审查报告`、`索引`。

### `status`

`待处理`、`学习中`、`已整理`、`待复习`、`进行中`、`暂缓`、`已完成`、`已归档`、`使用中`、`规划中`。

> [!warning]
> 不以 `#待办`、`#已完成` 等标签代替 `status`。标签只承担跨域概念检索，不承担文件位置、笔记类型或工作状态。

## 迁移方式

1. 不批量修改历史文件；
2. 新笔记从 `模板/` 创建；
3. 正在复习或维护的旧笔记优先补 `type`、`status`、`subject`；
4. 批量迁移前先用 [[总览/课程笔记.base|课程笔记视图]] 检查字段表现；
5. 需要改动大量文件时，先生成审查报告并分批验证。
