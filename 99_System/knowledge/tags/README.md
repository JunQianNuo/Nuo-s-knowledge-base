# 标签库

![[99_System/knowledge/tags/标签库.base]]

## 查询与维护

在数据库中查标准名或同义名称，再把“内置搜索检索式”列中的 `tag:标准名` 输入 Obsidian 搜索。这个检索式由标准名动态生成。

每条记录保存为 `总览/标签库/条目/标签-名称.md`；数据库直接读取这些记录，没有另一份独立词表。记录不填写 `tags`，不会作为学习资料混入标签搜索。

| 字段 | 用法 |
|:--|:--|
| `canonical_tag` | 唯一标准名，符合官方字符规则，大小写不重复建记录 |
| `tag_aliases` | 同一概念的历史写法、缩写；允许保留不能直接用作标签的数学写法 |
| `promote` | 为 true 时，脚本可依据显式主题和卡片标题补充此标签 |
| `source_kind` | 登记依据，如共享条目名称、重复概念主题、人工核对映射、历史标签 |
| `source` | 真实来源示例，不是完整使用文件清单 |
| `status` | 使用中表示参与当前词表；待处理表示仅登记保留的历史标签，需要核对用途 |

初始概念检索词来自共享原子条目的明确名称、显式知识/方法标签、已核对的同义关系，以及至少在两篇笔记元数据中重复使用的合法概念词。内容类型、课程归属、状态和“待补”等结构词不据此补标。重复使用只证明该词已有复用依据，不代表所有同义词已穷尽。

“历史标签待核对”保留现有标签；没有证据时不合并或删除。将其中一条用于补标前，先确认它是概念，再启用 `promote`。

新增笔记时先查此库、复用标准名；确有新概念时新增一条记录。至少填写 `type: 标签条目`、`canonical_tag`、`tag_aliases: []`、`promote` 和真实来源。文件名使用“标签-”前缀，避免与概念卡或方法卡重名。重命名标准名时，把旧标准名加入 `tag_aliases`，再执行审计与同步。

## 与笔记字段的分工

- `tags`：内置 `tag:` 搜索真正使用的标签，填写标准名，不带 `#`。
- `topics`：保留描述性主题，允许数学写法和细粒度词，不要求全部成为标签。
- `knowledge_tags`、`method_tags`：需要区分知识和方法角色时保留；相关标准名也应出现在 `tags` 中。

数据库记录同义关系不会让内置搜索自动展开同义词；它负责约束命名，脚本负责将标准名补进实际笔记。默认使用扁平概念名；`/` 只表示真实的上下位层级。

## 执行同步

在知识库根目录运行，只读审计：

```powershell
python scripts/tag_maintenance.py --report tmp/tag-audit.json
```

检查报告后执行：

```powershell
python scripts/tag_maintenance.py --apply --report tmp/tag-applied.json
```

脚本只精确匹配 `topics`、知识/方法标签和共享卡片标题，不按正文子串猜主题。它保留正文及其他字段，写入前备份原始字节并核对文件是否被其他操作修改。默认备份位于用户目录 `.codex/backups/knowledge-tags/`，本次运行输出会给出准确路径。原始录制 `raw/`、隐藏目录和数模外部项目不在自动补标范围内。

同步后再次审计应为零待修改，并在 Obsidian 内置搜索中核对实际结果。

本轮验证发现，运行中的 Obsidian 偶尔没有收齐外部文件更新。遇到磁盘已有 `tags` 而搜索仍漏项时，先保存当前编辑、重载知识库，再核对实际搜索结果；不要继续改名或重复补标。
