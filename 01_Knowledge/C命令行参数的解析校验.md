# C命令行参数的解析校验

> 一句话：命令行给 C 程序的是一组字符串；先确认数量和格式，再转换、检查业务条件，最后计算。

## 输入与边界

入口 `int main(int argc, char *argv[])` 中，`argc` 是参数字符串的数量；`argv[0]` 通常是调用名称，用户数据从 `argv[1]` 开始，`argv[argc]` 为 null 指针。访问某项前必须确认它存在。

例如 `./compute 12 + 3` 通常使 `argc == 4`，后三项分别是 `"12"`、`"+"`、`"3"`。数字字符串不能直接相加得到数值结果。

## 操作顺序

1. 对四则运算先检查 `argc == 4`，否则输出用法并以非零状态退出。
2. 用 `strtod` 转成浮点数，或用 `strtol` 转成整数。检查是否消费了至少一个字符、是否完整消费、是否越界；整数还要检查目标类型范围。
3. 只接受完整的 `+`、`-`、`*`、`/` 运算符，拒绝未知或多字符输入。
4. 做除法前检查除数是否为零；计算后按程序需求处理溢出或非有限结果。
5. 成功才打印结果。错误消息应说明哪个参数不合法，而不是把转换失败悄悄当成零。

下面是“完整有限浮点数”校验辅助函数，调用者仍需先检查参数数量：

```c
#include <stdlib.h>
#include <errno.h>
#include <math.h>

static int parse_number(const char *s, double *out)
{
    char *end;
    errno = 0;
    double x = strtod(s, &end);
    if (end == s || *end != '\0' || errno == ERANGE || !isfinite(x))
        return 0;
    *out = x;
    return 1;
}
```

它允许 `strtod` 识别的数值形式和前导空白；若业务只准十进制或禁止空白，还应另加格式限制。不能只检查返回值是否为零，因为 `"0"` 是合法输入，`"abc"` 也是可能返回零的非法输入。

## 小例与检查

```bash
./compute 8.5 "*" 2   # 预期 17
./compute 8 / 0        # 应报告除零
./compute 8x + 2       # 应报告数字格式错误
./compute 8 +          # 应报告参数不足
```

Shell 中未引用的 `*` 可能展开为文件名，所以乘号须写成 `"*"` 或 `'*'`。还要测试未知运算符、极大数与负数。用 Shell 脚本自动编译运行可复用 [[01_Knowledge/Linux终端文件文本与脚本工作流]]；能处理一个正常输入不能证明校验完整。
