# OpenMP循环分工与归约

> 一句话：先证明循环各项能独立计算，再分配迭代；每线程先算局部结果，最后按明确规则合并。

## 何时可用

输入是循环、数组范围和期望输出。需满足编译器支持的规范循环形式，并排除会改变结果的跨迭代依赖。例如 `c[i]=a[i]+b[i]` 可独立执行；`a[i]=a[i-1]+1` 依赖上一项，不能直接套用本方法。判断读写关系见 [[01_Knowledge/并行算法的数据依赖判定]]。

## 分工和归并

1. 核对索引范围、共享输入和输出写入位置，将临时量放入循环体。
2. 规则循环用 `parallel for` 分配。已有 `parallel` 域时可用 `omp for` 让现有团队分工，避免无意创建嵌套团队。
3. 对可归约的求和、乘积、最大值等使用相应 `reduction`，不要无保护地修改共享累加变量。

以中点积分估计圆周率为例，设正整数 $n$ 为子区间数，$h=1/n$，$x_i=(i-\tfrac12)h$：

$$
\pi=\int_0^1\frac{4}{1+x^2}\,dx
\approx h\sum_{i=1}^{n}\frac{4}{1+x_i^2}.
$$

```c
double sum = 0.0;
#pragma omp parallel for reduction(+:sum)
for (long i = 1; i <= n; ++i) {
    double x = (i - 0.5) / n;
    sum += 4.0 / (1.0 + x * x);
}
double pi = sum / n;
```

`sum` 的归约副本先保存部分和，结构结束时合并；原始 `sum` 先设零，归一化只做一次。公式及独立小规模数值检查复用 [[01_Knowledge/复合中点积分的分层数值验证]]。

手动循环可令线程号 $t\in\{0,\ldots,p-1\}$ 处理 $i=t+1,t+1+p,\ldots\le n$；$p$ 应取域内实际团队大小。每个 $1\le i\le n$ 唯一对应 $t=(i-1)\bmod p$，所以不会遗漏或重复。线程先求 `local_sum`，最后用 `critical` 合并一次，通常比每项加锁竞争少；归约通常更简洁。

## 嵌套迭代怎样分配

```c
#pragma omp parallel for collapse(2)
for (int i = 0; i < rows; ++i) {
    for (int j = 0; j < cols; ++j) {
        c[i][j] = a[i][j] + b[i][j];
    }
}
```

`collapse(2)` 合并两层迭代空间分配，适合外层项数少而总项数多。层数不能超过可关联循环层数，循环形式、界限和中间语句必须满足所用 OpenMP 版本及编译器约束；课堂这种无中间语句的矩形完美嵌套是直接适用形式。不能把所有版本都概括成“只允许完美嵌套”。合并并不消除数据依赖，也不保证更快。

嵌套并行是在外层线程中再形成团队，可用 `omp_set_max_active_levels(2)` 调整活动层级；它与 `collapse` 不是同一操作，可能造成线程过量和更多同步。通常先比较单层分工与 `collapse`，再由测量决定是否嵌套。

## 怎样检查成功

先对小规模逐项核对覆盖、边界、步长和串行结果，再测试不同线程数。浮点归约顺序可改变末位，按 [[01_Knowledge/并行浮点归约的误差核验]] 设置容差，不能借此解释巨大漂移。性能测量固定算法、输入、优化选项并重复计时，见 [[01_Knowledge/并行程序性能测量与可扩展性]]。代码通过编译不能替代这些语义检查；9月28日重建来源没有提供当日运行数据。
