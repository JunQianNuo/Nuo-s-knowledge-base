# RDMA与高性能互联的作用

> 一句话：RDMA把已授权内存之间的数据搬运更多交给网卡，减少CPU、软件协议栈和重复复制开销，但不消除传播、同步和拥塞。

## 什么被“直接”访问

远程直接内存访问允许一个节点通过网络接口访问远端授权、已注册的内存区域。应用仍需建立连接或通信对象、注册缓冲区并管理访问权限及完成事件；“远端CPU少参与数据路径”不等于无需远端程序事先协作。

例如接收方准备一块允许写入的缓冲区并向发送方提供受控访问信息，发送方发起RDMA写，网卡把数据送入该区。双方仍需协议保证缓冲区有效、完成后再读取或复用；RDMA也不会自动解决应用层数据竞争。

## 技术范围与比较方式

| 技术 | 课堂涉及的定位 |
|:--|:--|
| HIPPI | 早期大型机/超算短距高性能接口，主要理解历史脉络 |
| Fibre Channel | 面向可靠数据传输的互联体系，常见于存储网络 |
| Ethernet | 通用网络生态，不能只凭名称推断具体代际性能 |
| InfiniBand | 面向低延迟、高带宽互联，支持RDMA |
| RoCE | 在以太网上提供RDMA的技术体系 |
| Slingshot | 面向大规模系统互联，关注路由、吞吐和拥塞 |
| NVLink | GPU及相关设备间的高速互联，层级与普通节点网络不同 |

例如InfiniBand与RoCE应比较实际网络部署和通信路径，NVLink应先看所连接的设备与拓扑，不能把所有标称带宽列成一个“越大越好”的速度排名。参数取决于版本、端口聚合、单双向计数与测量条件；课堂模糊的数百Gb/s或微秒量级描述不作为某型号现行规格。

高带宽也不能消除小消息启动成本；RDMA降低的软件开销只是总延迟的一部分。优化仍需减少消息次数、改善数据局部性和控制同步，见[[01_Knowledge/延迟带宽通信成本模型]]。
